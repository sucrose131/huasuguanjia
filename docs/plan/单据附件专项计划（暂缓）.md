# 单据附件专项计划（暂缓）

> 状态：暂缓，不进入当前开发范围  
> 编制日期：2026-08-04  
> 恢复条件：文件存储、权限和OA附件关系确认后单独批准实施

## 1. 暂缓说明

当前库存及业务规则改造不实现单据附件功能。

暂缓范围包括：

- 关键单据附件上传；
- 多附件上传；
- 附件自定义名称；
- 附件预览和下载；
- 附件删除；
- 附件必填校验；
- 附件权限；
- 本系统与 OA 之间的附件同步。

本期业务单据、通用出入库和 OA 审批对接不得依赖附件功能才能完成。

## 2. 后续目标

后续通过统一附件能力支持不同业务单据，不在每张业务表中重复增加附件字段。

预期能力：

- 一个业务单据关联多个附件；
- 保留原始文件名；
- 支持自定义显示名称；
- 记录文件类型、大小、哈希、上传人和上传时间；
- 支持逻辑删除和权限校验；
- 支持草稿附件暂存；
- 支持按业务单据查询附件。

## 3. 建议通用模型

```text
attachment_id
document_type
document_id
original_name
display_name
storage_key
mime_type
file_size
file_hash
uploaded_by
created_at
deleted_at
```

如草稿阶段尚未生成业务单据ID，可增加临时上传令牌，在单据保存后完成正式绑定。

## 4. 恢复开发前待确认事项

1. 文件保存到本地磁盘、NAS、MinIO还是云对象存储；
2. 单文件大小、单据总容量和附件数量上限；
3. 允许和禁止的文件类型；
4. 是否进行病毒扫描；
5. 哪些单据支持附件；
6. 哪些单据或业务阶段必须上传附件；
7. 创建人、经办人、审批人和管理员的查看、上传、删除权限；
8. 单据作废或删除后附件保留期限；
9. 是否需要文件版本管理；
10. OA审批是否引用本系统附件，还是将附件文件同步到OA；
11. OA回调是否会携带审批附件；
12. 敏感文件的访问审计和下载日志要求。

## 5. 后续技术原则

- 生产环境不得只依赖API容器本地临时目录存储文件；
- 文件内容和业务数据库元数据分离；
- 下载使用鉴权接口或短时签名地址；
- 服务端校验文件类型和大小，不能只依赖前端；
- 文件名不得直接作为物理存储路径；
- 文件哈希可用于完整性校验和重复文件识别；
- 删除优先采用逻辑删除，并按保留策略异步清理物理文件；
- 所有上传、下载、改名和删除操作应保留审计记录。

## 6. 后续验收方向

- 同一单据可以上传多个附件；
- 自定义显示名称不改变原始文件信息；
- 无权限用户不能访问附件；
- 草稿附件可以在单据创建后正确绑定；
- 单据作废后附件按规则保留或禁止访问；
- OA附件传递符合最终确定的集成方式；
- API或容器重新部署不会造成附件丢失。
