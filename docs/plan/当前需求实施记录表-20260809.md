## 1. 记录表用途

本表用于持续记录十五项需求及后续新增集成范围实际完成了什么、还剩什么、如何验证以及何时完成。

维护规则：

1. 开发前先更新实施构想；
2. 开发完成后必须在本表追加一条实施记录；
3. 每条记录至少包含日期、需求编号、改动内容、涉及范围、验证结果和结论；
4. 没有验证依据的项目不能标记为“已完成”；
5. 状态发生变化时同步更新“需求状态总表”，历史实施记录只追加、不覆盖；
6. Git 提交后在记录中补充提交号；尚未提交时填写“待提交”。
7. 每个功能必须先完成界面设计、字段—API—数据库映射和业务确认，再进入正式实现。

## 2. 状态定义

| 状态           | 含义                                   |
| -------------- | -------------------------------------- |
| 已完成         | 代码、数据库和约定范围内验证均已完成   |
| 代码完成待验收 | 代码已存在，但仍需目标环境或浏览器验收 |
| 部分完成       | 已完成部分功能，仍有明确代码缺口       |
| 待实施         | 已确认需要开发，尚未完成               |
| 暂缓           | 当前版本明确不开发，不计为缺陷         |

## 5. 下一次开发完成后的记录模板

在上方“实施记录”表格末尾追加一行：

```text
| YYYY-MM-DD | 需求编号 | 实际完成的功能 | 修改的模块/数据库 | 测试、类型检查、页面验收结果 | 已完成/部分完成/失败回退 | 提交号或待提交 |
```

如本次开发改变了需求状态，还必须同步修改“需求状态总表”和配套实施构想，不能只追加流水记录。
