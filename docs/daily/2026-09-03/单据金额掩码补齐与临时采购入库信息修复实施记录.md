## 一级需求 1：金额脱敏单据的金额展示统一为掩码（不再显示 ¥0.00 假零）

### 现象
- 「仅自己经办(own)」或无查看权限的用户打开他人单据详情/列表时，金额应显示掩码，实际部分位置显示 `¥0.00`。

### 根因
- 后端把脱敏金额返回为 `null`，但前端多处把 null 兜成 0：`?? 0`/`|| 0` 包裹、`数量×单价` 计算、金额合计 reduce、自定义金额函数，导致显示 `¥0.00`；
- 详情组件此前只按「能力级 canViewAmount」判断，未按「单据归属」判断 own 范围。

## 一级需求 2：临时采购入库 供应商/收货经办人/创建人 显示与反向生成问题

### 现象
- 临时采购入库填了供应商，保存后供应商不显示、反向生成的申请/订单供应商缺失；
- 入库单创建人显示异常（手机号/空）；单据详情「收货经办人」显示手机号而非具体人名。

### 根因（本地库抽查证实）
1. `PurchaseReceiptForm.doSave` 的载荷**漏发 `vendorId`**（前端校验必填但没提交）→ 后端 `saveReceipt` 直入创建时回退「首行商品默认供应商」→ 大量临时入库链 `vendor_id=0`（本地 `GA202609030002/GA202609010001`）；
2. 后端 `receipts()` 不返回 `createdByName/receiverName`，`receipt(id)` 不返回 `vendorId/vendorName/receiverName/createdByName` → 详情无供应商、人名前端拿不到；
3. 表单「收货经办人」硬编码 `auth.user.username`（登录账号=手机号）；`receiverOptions`/订单列表人名 SQL 兜底到 `username`（OA 账号 nickname 为空即手机号），未优先员工姓名；
4. 引擎 `creator` 忽略后端已给的 `createdByName`。

### 交付
| 文件 | 改动 |
| --- | --- |
| `purchase.service.ts` | `receipts()` 补 `receiverName/createdBy/createdByName`（员工姓名>昵称>登录账号）；`receipt(id)` 补 `vendorId/vendorName/receiverName/createdByName`；`saveReceipt` 临时入库**编辑**时把供应商与收货经办人同步到反向生成的订单/申请（保持链路一致）；`receiverOptions` 标签与订单列表人名 SQL 员工姓名优先 |
| `PurchaseReceiptForm.vue` | 直入保存载荷补 `vendorId`；「收货经办人」按单据收货人显示具体人名（本人取登录 displayName，他人取后端 receiverName） |
| `BusinessDocumentPage.vue` | `creator` 优先 `createdByName` |

### 验证

- 历史坏数据（已确认入库单 vendor=0）无法在单据上直接改供应商（已确认单据不可编辑），如需补录需业务侧提供处理方式（本地库中为测试数据）。
