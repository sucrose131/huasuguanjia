# 采购申请生成状态误判修复实施记录（2026-09-03）

日期：2026-09-03
分支：fix/0903-purchase-application-status（基于 master）
关联：`docs/daily/2026-09-02/采购申请反向生成链路收货人回填修复实施记录.md`

## 一、问题

- 现象：已有采购订单的申请单（包括直接订单/临时入库**反向生成**的）列表"生成状态"仍显示"未生成"。
- 根因：正向"申请→生成采购订单"会给订单明细写 `source_application_detail_id`（指向申请明细）；
  但两个反向生成点（`startOrder` 直接采购订单、`saveReceipt` 临时直接入库）创建申请后**没有回填订单明细的该关联**，
  而"生成状态"按该明细级引用计算 → 有订单也判为未生成。

## 二、改动

| 对象 | 内容 |
| --- | --- |
| `purchase.service.ts startOrder` | 反向生成申请明细后，`$executeRaw` JOIN 更新订单明细 `source_application_detail_id`（按 goods+sku 与同 `po_id` 匹配，订单明细 goods+sku 唯一） |
| `purchase.service.ts saveReceipt`（直接入库） | 生成订单明细后同样回填关联 |
| `purchase.service.spec.ts` | 两个反向生成用例 tx 补 `$executeRaw` mock |
| 存量数据 | 本地库 12 条订单明细已回填关联（PA202609010002-006、…010、PA202609020007、PA202609030001 等），全库复查 0 条有订单却未关联 |

## 三、顺带修复（master 既有）

- `purchase.service.spec.ts` quick-sku 回归用例（f426410 遗留）：saveApplication 调用补 oaOrgId/receiverId、user 改对象、去掉多余参数 → 运行失败 + 类型错误均修复；
- `requisition.service.spec.ts`：stock 断言补非空 `!`（类型检查错误）。

## 四、验证

- API 类型检查：非 integrations 0 错误（此前 4 处均在本次修复范围）；
