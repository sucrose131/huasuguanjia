# 采购/领用审批状态显示口径补充（待提交/已取消）实施记录

> 日期：2026-09-03（分支 `feature/0902-oa-cancel-master`）
> 类型：展示文案口径修正（业务负责人确认，随采购撤回/终止功能一并落地）

## 一、需求确认

1. 列表「审批状态」列不再出现「待审批」误导文案：单据**未进入审批流程**（草稿、撤回待重提、未推送 OA）显示「待提交」，与 OA 各过程态（OA审批中/待提交OA/OA退回发起人/OA提交失败）区分。
2. 补 `approve_status=3`（取消/终止）显示分支：本系统终止（创建人操作）→「已取消」；OA 侧撤销（回调 0 号操作人）→「OA已取消」。此前 3 会错误落到「待提交/待审批」兜底。

## 二、实施内容

| 文件 | 修改 |
| --- | --- |
| `apps/web/src/utils/approval-status.ts` | `approvalStatusText`：新增 `approveStatus===3` 分支（按 `approve_by===0` + `oaStatus==='CANCELED'` 区分 OA 侧撤销/本系统终止）；兜底文案「待审批」→「待提交」。`approvalStatusType`：取消类 → `info` 灰。 |
| `apps/web/src/utils/approval-status.spec.ts` | 兜底改「待提交」断言；新增 3/已取消/OA已取消 渠道与颜色用例。 |
| `apps/web/src/views/business/configs/requisition-application.spec.ts` | 兜底断言同步；补 3 渠道用例（共用同一工具）。 |
| `apps/web/src/views/business/configs/purchase-application.ts` | 头注释 0 的说明改「待提交」。 |

数据库字典未改动：`approval_status` / `requisition_approval_status` 被库存类单据等多处共用，字典名仍为「待审批/已审批/已取消」，采购页筛选下拉与表单详情回退仍显示字典名（如需列/筛选项完全一致，需单独处理采购页筛选选项，另行确认）。
