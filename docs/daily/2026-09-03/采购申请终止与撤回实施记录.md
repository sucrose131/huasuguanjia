# 采购申请终止与撤回实施记录

日期：2026-09-03
关联：采购申请创建人结束审批。原「取消」未上线，已直接做成终止 + 撤回，不保留取消接口和权限。

## 一、已确认口径

创建人在审批中（`status=1` 且 `approve_status=0`）同时可见两个按钮：

| 操作 | 成功后本地状态 | 之后能否编辑提交 | 缺料申请 |
| --- | --- | --- | --- |
| 终止 | `status=1`，`approve_status=3`（字典仍为已取消） | 不能 | 允许，并回退缺料 |
| 撤回 | `status=0` 且 `approve_status=0`（草稿），单号不变 | 可以 | 不允许，只能终止 |

已推送 OA 时，两个操作都先 `dealProcess(cancel)`；OA 失败则本地仍保持审批中。OA 侧取消回调仍写 `3`（相当于终止）；若本地已撤回成草稿，回调不再改单据。

不新增表或字典项。不保留 `POST .../cancel` 和 `purchase:applications:cancel`。

## 二、字段 / API / 数据库映射

| 页面操作 | API | 权限 | 数据库 |
| --- | --- | --- | --- |
| 终止 | `POST /purchase/applications/:id/terminate` | `purchase:applications:terminate` | `approve_status=3`，意见「创建人终止审批」 |
| 撤回 | `POST /purchase/applications/:id/withdraw` | `purchase:applications:withdraw` | `status=0`，`approve_status=0`，意见「创建人撤回审批」 |
