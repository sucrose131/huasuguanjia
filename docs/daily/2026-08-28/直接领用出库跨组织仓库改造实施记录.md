# 直接领用出库跨组织仓库改造实施记录

> 日期：2026-08-28
> 分支：`dev`
> 类型：影响用户操作的业务改造（业务负责人已确认交互与映射）
> 当前状态：代码完成，自动化与浏览器验收通过

## 一、需求确认

业务负责人确认（原“直接新增领用申请单”场景澄清后）：

1. 领用出库单「直接领用出库」的仓库下拉应展示当前账号**授权组织**下的全部领用类仓库（原来只显示 OA 固定所属组织下的仓库）。
2. 选仓库后**反推组织**，并据此筛部门、筛人员；人员手动选择。
3. 范围仅限「直接领用出库」，其余入口不变；仓库 `dept_id` 仅作自动带出提示，`dept_id=0` 回退为该组织部门下拉。

## 二、实施内容

### 后端（`apps/api/src/requisition/`）

| 文件 | 修改 |
| --- | --- |
| `requisition.service.ts` | 新增 `directOutputOptions(user)`：按 `orgId + authorizedOrganizations` 返回授权组织领用类仓库（含 `raw.orgId/deptId`，标签带组织名）；`applicationFormOptions` 增加可选 `deptId` 参数（按部门筛人 + 组织直属兜底）；`saveOutput` 改收 `AuthUser`，`saveDirectOutput` 新增 `assertAuthorizedOrganization` 后端组织授权校验 |
| `requisition.controller.ts` | 新增 `GET /requisitions/direct-output-options`；`application-form-options` 透传 `deptId`；`outputs` POST/PATCH 传完整 `AuthUser` |

### 前端（`apps/web/src/views/business/forms/RequisitionOutputForm.vue`）

- 新增 `loadDirectOutputWarehouses()`（跨组织仓库）、`directWarehouseChanged()`（反推组织/带出部门/筛人员）、`deptChanged()`（按部门刷新人员）。
- `loadRequisitionOptions` 支持 `deptId` 与 `preserveWarehouses`（直接领用模式刷新部门/人员时保留跨组织仓库列表）。
- 直接领用出库创建：仓库下拉改跨组织来源；未选仓库前部门/接收人禁用；部门自动带出（仓库挂部门 → 直接选中；组织唯一部门 → 自动选中）。

### 数据库

无新增表、字段、索引或字典；无数据清洗。

## 三、验证结果

- `requisition.service.spec.ts`：22/22 通过（新增 3 个用例：跨组织仓库选项、按部门筛人、越权组织拒绝）。
- API 类型检查：`src/requisition/` 无错误（全量仍有既有外部同步测试类型错误，与本次无关）。
- Web `vue-tsc`：通过。
- API 实测：
  - `GET /requisitions/direct-output-options`（admin）：42 个仓库，跨多组织，标签如「行政-办公耗材仓（华溯控股（深圳）有限公司）」「华爱办公耗材库（深圳华爱健康管理有限公司）」。
  - `application-form-options?orgId=2&deptId=20`：健康服务部成员 + 组织直属人员。
- 浏览器验收（admin，`/requisitions/outputs` → 直接领用出库）：
  - 仓库下拉 42 项跨组织 ✓
  - 选 org 9「行政-办公耗材仓」→ 部门自动带出，接收人=行政部人员（8 人）✓
  - 选 org 2「华爱办公耗材库」（dept_id=0）→ 部门留空，部门选项=该组织 4 个部门；选「健康服务部」→ 接收人刷新为部门成员+组织直属（14 人）✓
  - 请求序列核实：`direct-output-options` → `application-form-options?orgId=` → `?orgId=&deptId=` ✓
  - 未点击保存，验收过程未修改业务数据。

## 四、影响范围与遗留项

- 影响：领用出库单「直接领用出库」新增流程；新增 1 个只读 options 接口；`application-form-options` 增加可选参数（向后兼容）。
- 其余页面（领用申请单、非直接出库、退回单）行为不变。
- 遗留：直接领用出库仍要求部门必填（既有约束），未放开“组织级无部门领用”；该语义如需放开需另行业务确认。
