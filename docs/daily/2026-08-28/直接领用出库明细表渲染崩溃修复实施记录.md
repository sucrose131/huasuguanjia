# 直接领用出库明细表渲染崩溃修复实施记录

> 日期：2026-08-28
> 分支：`dev`
> 类型：影响用户操作的缺陷修复（回归修复）
> 当前状态：代码完成，浏览器验收通过

## 一、问题与根因

「直接领用出库」新增弹框的明细表**看不到任何明细行**，点击「+ 添加明细」也无效（行数不变）。

根因（浏览器控制台 + element-plus 源码定位）：

- 直接领用出库的空白明细行 `remainingQty = null`，而 8-27 提交 `9b55287`（领用出库数量口径与编辑锁死修复）把出库数量列改为 `:max="maxOutputQty(s.row)"`，`maxOutputQty` 对空白行返回 `0`；
- 该列 `el-input-number :min="1" :max="0"`，element-plus 2.9.x 的 `verifyValue` 在 `max < min` 时**直接 throwError**（`[InputNumber] min should not be greater than max`）；
- 抛错发生在 `ElInputNumber → TableTdWrapper → ElTableBody` 的组件更新阶段，导致整张明细表 body 渲染崩溃，一行都不显示；每次新增行重复触发同样抛错。

即：明细表其实一直有数据（Vue 状态 `details` 有 1 行），但渲染层被 InputNumber 抛错打崩。该缺陷在本次跨组织改造**之前**已存在（由 8-27 数量口径修复引入），本次发现并修复。

## 二、修复内容

`apps/web/src/views/business/forms/RequisitionOutputForm.vue`：

1. `maxOutputQty` 全面保证 `max >= 1`（各分支 `Math.max(1, ...)`），从根上杜绝 `min > max` 抛错；
2. 直接领用出库的语义修正：没有申请剩余量，未选库存批次时**不设上限**（返回 `undefined`），选中批次后按批次库存量封顶；
3. 出库数量输入框禁用条件：直接领用出库模式改为「未选库存批次时禁用」（原条件按 `remainingQty > 0`，对直接出库恒为禁用），选中批次后启用。
