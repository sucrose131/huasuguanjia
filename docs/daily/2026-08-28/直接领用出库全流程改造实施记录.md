## 一、需求确认（业务负责人逐项确认）

1. 领用类型可选（直接领用=1 / 借用=2）；审批分流：直接领用→反向申请单「已通过」不走 OA；借用→「待审批」走 OA 审核。
2. 领用人签字必签才能保存出库；签署人默认=领用接收人（领用人）；签名附件写入申请单 attachments(category=signature) + signature_attachment。
3. 申请数量(draw_qty) 与 出库数量(fact_draw_qty) 均编辑；出库数量 ≤ 申请数量；剩余可出 = min(申请数量−历史已出, 批次库存) 联动。
4. 是否可归还跟随领用类型（借用=可归还，直接领用=无需归还）。
5. 布局：直接出库单不显示「领用申请号」（创建/查看一致）；备注/确认人/确认时间/附件与查看一致。
6. 出库时序：出库单保存即确认扣库存；借用 OA 驳回时自动生成待确认退回单追回物资。

## 二、实施内容

### 后端（`apps/api/src/requisition/`）

| 文件 | 修改 |
| --- | --- |
| `requisition.service.ts` | `saveDirectOutput`：领用类型校验（1/2）；签字必填 + 上传签名；逐行 申请数量/出库数量 分列（`quantity ≤ drawQty`）；`is_returnable` 跟随领用类型；反向申请单按类型写 `approve_status`（直接领用=1，借用=0）、签字四要素、`draw_qty/fact_draw_qty` 分列；借用事务后 `oaApproval.submit` 走 OA；`ensureAutomaticOutput`（问题A）复用直接出库单不重复生成；`handleOaApprovalResult` 驳回分支（问题B）自动生成待确认退回单；`output(id)` 返回 `directOutput`/`drawType` |
| `requisition-oa-approval.service.ts` | `submit()`：直接领用出库反向生成的借用申请以**领用人（接收人）身份**发起 OA（代提交），操作人仅作系统提交人；正常借用仍要求申请人=提交人（防跨账套错配） |
