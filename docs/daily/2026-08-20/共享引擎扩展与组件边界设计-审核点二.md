# 共享引擎扩展与组件边界设计（审核点二）

> 日期：2026-08-20  
> 当前分支：`review/0820-remote-dev`  
> 设计依据：审核点一确认结果、现有模块化架构、`Element Plus Table表格样式归档.md`  
> 本阶段范围：只确定架构边界、界面契约和字段映射，不修改业务逻辑、不修改数据库。

## 1. 目标

在保留“共享引擎 + 独立配置 + 独立表单 + 薄页面”的前提下，恢复重构前已完成的业务能力。共享引擎只提供通用机制，不写采购拆单、盘点、付款等业务判断；特殊业务由对应页面和独立组件负责。

## 2. 文件职责边界

| 层级 | 负责内容 | 明确禁止 |
| --- | --- | --- |
| `BusinessDocumentPage.vue` | 列表、查询、分页、通用弹框、权限过滤、通用插槽、刷新 | 禁止导入采购、盘点、生产等专用组件；禁止按业务 key 堆积 `if/else` |
| `business-document-config.ts` | 通用类型契约：权限码、弹框尺寸、详情加载、通用能力开关 | 禁止承载具体业务流程 |
| `configs/*.ts` | 页面字段、查询项、普通行操作、权限码映射、API 调用 | 禁止放大型弹框模板和复杂交互状态 |
| `*Page.vue` 薄页面 | 组合共享引擎和本业务扩展插槽，管理专用弹框状态 | 禁止重新形成旧版通用大文件 |
| `forms/*.vue` | 本单据新增、编辑、查看字段与校验 | 禁止复制共享列表、分页和权限逻辑 |
| `components/{domain}/*.vue` | 拆单、盘点连续操作、付款等专用交互 | 禁止成为跨业务万能组件 |
| API 服务 | 权限最终校验、并发锁、幂等、金额计算、库存事务 | 禁止只依赖前端隐藏按钮保证安全 |

## 3. 共享引擎契约改造

### 3.1 权限契约

拟扩展配置：

```ts
type RowAction = {
  key: string
  permission?: string
  // 保留现有 label/show/confirm/primary/handler
}

type BusinessDocumentConfig = {
  pagePermission?: string
  createPermission?: string
  dialog?: { width?: string; top?: string; className?: string }
  loadDetail?: (id: string | number) => Promise<Record<string, any>>
  // 保留现有配置
}
```

显示规则：

1. 页面路由权限决定能否进入页面；
2. `createPermission` 决定新增按钮是否显示；
3. `RowAction.permission` 与现有 `show(row)` 同时满足才显示行操作；
4. 金额查看、金额编辑仍是独立白名单，与菜单/操作权限叠加；
5. 后端权限和金额白名单是最终校验，前端隐藏只负责正确交互，不能代替安全拦截。

### 3.2 通用扩展插槽

共享页面提供以下作用域插槽：

| 插槽 | 用途 | 暴露内容 |
| --- | --- | --- |
| `page-actions` | 页面右上角补充通用以外的入口 | `refresh/openCreate` |
| `row-actions` | 追加本业务专用行操作 | `row/refresh/openView/openEdit` |
| `business-dialogs` | 挂载采购拆单、盘点等专用弹框 | `refresh` |
| `form-extra` | 挂载通用表单之外的附件等区域 | `form/mode` |

共享引擎不识别“采购拆单”“盘点”“付款”等业务名称，只提供挂载点。

### 3.3 详情加载与弹框

1. 查看、编辑前统一通过可选的 `loadDetail(id)` 获取完整数据，避免仅把列表摘要行传入表单；
2. 表单组件不重复请求已经加载的详情；确需延迟加载的明细由组件声明；
3. 简单表单默认 720px；复杂明细弹框由配置或专用组件指定 920/1180px；
4. 弹框统一 `close-on-click-modal=false`，避免误操作丢失录入内容。

## 4. P0 独立业务组件设计

### 4.1 采购申请拆单生成

`PurchaseApplicationPage.vue` 负责挂载现有 `PurchaseApplicationOrderPreviewDialog.vue`，操作放在“更多”内：

1. **整单生成**：选择一个供应商，载入全部尚未生成的申请明细；输入每行总金额后生成一张采购订单；
2. **选品生成**：勾选多条尚未生成的明细，选择一个供应商，输入每行总金额后生成一张采购订单；
3. **关联订单**：查看该采购申请已生成的全部采购订单并可跳转查看。

选择表格设置稳定 `row-key`；已生成明细不可再次选择。接口继续使用：

`POST /purchase/applications/:id/generate-order`

请求字段：`generationMode`、`vendorId`、`details[].applicationDetailId`、`details[].totalAmount`。

### 4.2 采购金额规则

采购订单明细改为：

- 用户输入：`totalAmount`（本行总金额）；
- 系统计算并只读显示：`unitPrice = totalAmount / quantity`；
- 数量必须大于 0，总金额必须大于 0；
- 前端按两位小数展示，后端用 Decimal 重新计算并作为权威值；
- 无金额查看权限显示 `****`，无金额编辑权限不能生成或修改金额。

### 4.3 采购付款入口

`PurchaseOrderPage.vue` 在订单行恢复“付款”操作，满足状态、剩余应付金额、菜单操作权限和金额编辑白名单时显示。点击跳转 `/purchase/payments` 并携带 `orderId`，付款表单只允许选择/回显该订单。

采购付款页面继续保留列表、查看和撤销记录能力；不再以页面“直接新增付款”作为主要入口，是否隐藏该页新增按钮在实施时按上述规则处理。

### 4.4 库存盘点连续操作

`InventoryCheckPage.vue` 挂载独立的盘点流程弹框，恢复同弹框连续操作：

1. 选择当前授权组织、该组织仓库、盘点类型、盘点日期；
2. 点击“载入盘点明细/下一步”创建盘点单并在当前弹框载入仓库库存批次；
3. 用户在同一弹框填写实盘数量、损坏数量和备注；
4. 提交后保存明细并进入既有审批/后续盘盈盘亏流程；
5. 创建成功但用户关闭弹框时，保留草稿并可从列表继续编辑，不能重复创建。

明细使用带边框表格、稳定 `row-key`、固定表头/最大高度，数量右对齐；不恢复成大页面内嵌逻辑。

### 4.5 库存过账安全

所有入库、出库、调拨、盘点、退回、撤销操作统一验证：

1. 后端事务内锁定源单与库存行；
2. 校验当前状态和可操作数量；
3. 同一业务动作具备幂等保护，重复点击不得重复增减库存；
4. 单据状态、库存流水、批次库存和来源映射在同一事务提交；
5. 撤销必须验证后续单据和已使用数量，不允许破坏链路；
6. 自动化测试直接核对操作前后数据库数量及流水唯一性。

## 5. P1 通用能力恢复

### 5.1 附件

复用 `DocumentAttachments.vue`。仅在单据已持久化并取得 `documentType/documentId` 后挂载；新增草稿尚无 ID 时先保存再上传。附件入口通过表单扩展区或专用表单组件接入，不在共享引擎写死业务类型。

### 5.2 单据追溯

复用 `DocumentTraceDialog.vue`。列表行通过配置声明支持追溯，薄页面挂载统一追溯弹框；上下游关系由后端按真实来源字段查询，不由前端拼接。

### 5.3 操作记录

采购业务复用 `PurchaseOperationHistoryDialog.vue`；其他业务若已有统一日志接口则使用通用记录弹框。操作记录只读，展示操作人、动作、时间、结果和意见。

## 6. UI 规范落地

1. 业务列表使用 `stripe`，明细表使用 `border`；
2. 操作列固定右侧，主操作平铺，次要操作进入“更多”；
3. 长文本使用 `show-overflow-tooltip`；
4. 状态统一使用 `StatusTag/el-tag`；
5. 金额和数量右对齐，金额显示两位小数；
6. 采购拆单多选表格设置稳定 `row-key`，明确已生成行不可选；
7. 复杂明细弹框使用 920/1180px 和 `max-height`，不强制套用 720px；
8. 分页、筛选由后端完成，避免再次引入全量加载。

## 7. 字段、API、数据库映射

本阶段设计**不新增表、不增删字段、不修改数据字典**。需要恢复的关键字段在当前结构中已有映射：

| 前端业务字段 | API 字段 | 数据库字段/约束 | 用途 |
| --- | --- | --- | --- |
| 采购申请明细 ID | `applicationDetailId` | `hspsi_purchase_order_detail.source_application_detail_id` | 标记申请明细已生成；现有唯一索引阻止一个明细重复生成有效映射 |
| 生成状态 | `generationStatus` | 由有效采购订单明细映射计算 | 未生成、部分生成、全部生成展示 |
| 行总金额 | `totalAmount` | 由数量和 `hspsi_purchase_order_detail.unit_price` 计算/返回 | 用户输入的业务金额 |
| 采购单价 | `unitPrice` | `hspsi_purchase_order_detail.unit_price` | 后端按总金额÷数量计算并保存 |
| 供应商 | `vendorId` | `hspsi_purchase_order.vendor_id` | 每张拆分订单选择一个供应商 |
| 来源采购申请 | `applicationId` | `hspsi_purchase_order.pur_id` | 订单追溯申请主单 |
| 采购付款关联订单 | `orderId` | `hspsi_purchase_order_payment.po_id` | 从采购订单行发起付款 |
| 盘点主单 | `id/checkNo/orgId/warehouseId/checkType` | `hspsi_inventory_check` 对应字段 | 创建盘点任务 |
| 盘点明细 | `id/checkQty/damagedQty/remark` | `hspsi_inventory_check_detail` 对应字段 | 同弹框连续录入与提交 |

说明：`totalAmount` 是交互和 API 层业务字段，不要求在订单明细表重复新增“总金额”列；保存的权威字段仍为 Decimal 单价，订单行总额按数量乘单价计算。若后续业务要求保留“用户原始输入总金额”且必须与舍入后的单价乘数量完全区分，才需要另行提出数据库变更并单独审核。

数据字典继续复用 `approval_status`、`purchase_order_status`、`purchase_payment_progress_status`、`inventory_check_type` 等现有字典，不写死新的枚举值。

## 8. 实施与验收顺序

1. 实施共享引擎权限、详情加载、弹框尺寸和扩展插槽；
2. 对 31 个页面补齐新增和行操作权限码，完成静态权限矩阵检查；
3. 恢复采购申请三项操作及拆单弹框；
4. 恢复采购总金额输入、单价计算；
5. 恢复采购订单行付款；
6. 修复采购退款金额编辑白名单；
7. 浏览器审核采购界面；
8. 自动化测试采购申请→拆分订单→付款→入库及删除/作废释放明细；
9. 恢复盘点同弹框连续操作并验证库存过账安全；
10. 按“库存 → 领用 → 生产 → 销售/售后”继续逐链验收；
11. P0 稳定后恢复附件、追溯和操作记录；
12. 输出最终功能等价性差异归零报告。

## 9. 审核点与暂停规则

### 审核点二（当前必须暂停）

请确认：

1. 是否同意上述共享引擎与独立业务组件边界；
2. 是否同意采购申请“整单生成 / 选品生成 / 关联订单”三个短按钮文案；
3. 是否同意采购付款页面保留查询和记录管理，但付款新增必须从采购订单行发起；
4. 是否同意订单明细表继续只保存 Decimal 单价，由总金额÷数量计算，不新增重复总金额字段。

### 后续暂停点

- **审核点三**：共享骨架和采购前端界面完成后暂停，业务负责人审核按钮、弹框、字段和交互；
- **审核点四**：采购完整逻辑及自动化测试完成后暂停，审核数据库结果和链路；
- **审核点五**：库存盘点与库存安全完成后暂停；
- 领用、生产、销售/售后每条链路完成后分别输出结果，不跨链路一次性修改。

审核点二通过前，不开始业务代码实现。
