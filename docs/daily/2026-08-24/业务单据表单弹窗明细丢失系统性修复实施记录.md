# 业务单据表单弹窗「关闭后再打开明细丢失」系统性修复实施记录（2026-08-24）

> 分支：`fix/0824-dialog-detail-reload`（基于 `dev`）
>
> 类型：前端缺陷系统性修复（影响所有 `views/business/` 单据表单）

## 一、问题

生产 BOM 编排「查看/编辑」时，**只有第一次打开会显示原料明细，关闭后再打开明细为空**。

排查结论：商品、BOM 数据本身有效；问题出在前端弹窗生命周期。

## 二、根因（三个条件叠加）

1. **共享弹窗未销毁内容**：`apps/web/src/views/business/BusinessDocumentPage.vue` 的 `<el-dialog v-model="formDialog">` 没有 `destroy-on-close`，弹窗关闭只是隐藏，表单组件保持挂载，`onMounted` 只执行一次。
2. **明细只靠 `onMounted` 加载**：`forms/ProductionBomForm.vue` 在 `onMounted` 的 `else if (form.value.id)` 分支里 `api.get('/production/boms/' + id)` 拉详情并写入 `form.value.details`；没有对 `modelValue.id` 的 `watch`。
3. **每次打开整体替换表单数据**：`openView/openEdit → resolveDetail(row)`，而 BOM 的 config **未配置 `loadDetail`**，`resolveDetail` 直接 `return { ...row }`（列表行不含 `details`）。

时序：第一次打开 → 组件挂载 → `onMounted` 拉详情 → 明细显示；关闭 → 组件保留；第二次打开 → `form.value` 被替换成无 `details` 的新对象 → `onMounted` 不再执行 → 明细为空。

**系统性范围**：`forms/` 下 31 个表单中 27 个都是「在 `onMounted` 里用 `form.value.id` 拉详情」的写法，而 31 个 config 只有 `purchase-application`、`purchase-order` 配置了 `loadDetail`。BOM 因列表行不含 `details` 最先暴露，其余单据同源。

## 三、修复方案（系统性加固）

在共享弹窗上启用 `destroy-on-close`：

```diff
     <el-dialog
       v-model="formDialog"
       :title="config.title"
       :width="config.dialog?.width || '720px'"
       :top="config.dialog?.top || '3vh'"
       :class="config.dialog?.className"
       :close-on-click-modal="false"
+      destroy-on-close
     >
```

效果：弹窗每次关闭销毁内容，再次打开时表单组件重新挂载、重新执行 `onMounted`（重新拉详情与选项），所有「依赖 `onMounted` 加载详情/明细」的单据表单一并修复，无需逐个改 27 个表单或补 `loadDetail`。

未选「给 BOM 单独补 `loadDetail`」方案的原因：`loadDetail` 与 `onMounted` 并存会造成每次打开两次拉取详情；系统性方案一处改动覆盖全部单据。

## 四、影响范围

- `apps/web/src/views/business/BusinessDocumentPage.vue`（唯一改动文件，+1 行）。
- 所有 `views/business/` 单据表单（生产、采购、销售、领用、库存）每次打开弹窗都会重新挂载并重新拉取基础选项与详情。
- 无数据库、无接口、无字典变更。

## 六、遗留与注意事项

- `purchase-application`、`purchase-order` 两个 config 已配置 `loadDetail`，其表单 `onMounted` 内同时有拉详情逻辑：启用 `destroy-on-close` 后每次打开会拉取两次详情（父级 `resolveDetail` + 表单 `onMounted`）。属轻微冗余请求，功能正确，后续可在表单内去掉重复拉取。
- 弹窗每次打开重新挂载后，表单组件内部临时状态（如未保存的输入）随关闭丢失——与「关闭即放弃」的既有交互一致。
