## 2. 旧版基准和实施结果

### P1-01 采购订单新增/编辑

- 恢复“运输方式”和“物流单号”，继续使用旧版 `el-select`、`el-input`；
- 恢复“金额与付款”区域：订单总金额、退货后应付、累计付款、累计退款、净已付款、本次付款、付款后待付、付款进度、付款日期、付款渠道和付款备注；
- 本次付款仍只在新建订单时允许填写，金额可为 0，且不能超过订单总额；
- 直接采购订单恢复“快捷新增商品”和“补充 SKU”；来源采购申请的订单继续保持明细锁定；

### P1-03 采购退货

### P1-04 采购付款

### P1-05 库存调整

### P1-06 库存报损出库

- 首轮只恢复了“保存草稿/保存并提交审核”，业务审核指出报损出库表单字段和布局仍未完整对齐旧分支；该问题已重新打开并专项修正；
- 页面标题恢复为“报损出库单”，新增按钮恢复为“新增报损出库单”；关联盘亏后继页面的错误标题由“报损出库单”纠正为旧版“报亏出库单”；
- 主信息恢复旧版四列布局和顺序：来源盘点单、业务类别、组织、仓库、部门、报损类型、原因、报损去向、日期、经办人、备注；
- 组织恢复旧版 `el-tree-select`，原因和备注恢复旧版普通 `el-input`，报损/报亏类型继续按既有字典分支显示；
- 明细恢复旧版单一“商品 / SKU / 批次”库存选择器，不再拆成重构后的商品搜索、SKU和批号三段；

- 单价继续受金额编辑权限控制；恢复“报损数量不能超过当前库存”校验；
- 盘点损坏生成的报损单恢复旧版锁定条件，组织、仓库、类型、原因、日期和明细不得被重新编辑；
- 报亏出库只读页同时恢复旧版报亏类型下拉、日期选择器、报亏数量和单价数字输入框的只读组件形态；

## 4. 字段、API与数据库映射

| 功能 | 复用接口/字段 | 数据落点 |
| --- | --- | --- |
| 采购快捷商品/SKU | `GET /goods/name-availability`；明细 `newGoods/newSku` | 单据保存成功后由现有采购服务创建正式商品/SKU |
| 采购订单首次付款 | 订单保存载荷 `currentPaymentAmount/currentPaymentDate/currentPaymentChannel/currentPaymentRemark` | 现有采购订单与付款流水事务 |
| 采购申请提交 | `POST /purchase/applications/:id/submit` | 现有采购审批状态和 OA 流程 |
| 采购退货提交 | `POST /purchase/returns/:id/submit` | 现有采购退货审批流程 |
| 库存调整/报损提交 | 保存载荷 `submit` | 现有库存单据状态和 OA 流程 |
| 库存流水字段 | `GET /inventory/ledger` 返回字段 | 只读展示，不写数据 |
| 领用审批/确认字段 | 详情接口现有状态、人员、时间、意见字段 | 只读展示，不写数据 |
| 售后外部数据 | `receivedAt/externalPayload` | 只读展示，不写数据 |
| 生产入库删除 | 行数据 `confirmStatus/status` | 只控制前端入口显示，不改变删除接口 |

数据库核对结论：本批全部字段和接口均已存在；未新增表、字段、索引、字典或迁移，也未使用前端过滤替代后端权限控制。
