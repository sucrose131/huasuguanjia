# 库存调拨单「发出人/接收人不是有效系统用户」修复实施记录（2026-08-26）

> 分支：`fix/0826-transfer-send-receive-user`
>
> 类型：前端缺陷修复（下拉数据源用错 ID 体系，纯前端，无接口/数据库变更）

## 一、问题

库存调拨单新增时填写完参数保存，报 `HTTP 400 发出人或接收人不是有效系统用户`。

## 二、根因

- 后端 `saveTransfer`（inventory.service.ts:775-783）校验 `sendBy`/`receiveBy` 必须是
  **在册且启用（status=1）的系统用户**（`hspsi_sys_user.id`）；调拨单列表/详情解析发出人/接收人姓名
  同样查 `hspsi_sys_user`（`users()`）。
- 前端 `InventoryTransferForm.vue` 的发出人/接收人下拉却加载了 **`/base-data/employees/options`**，
  其 value 为**员工主键 `hspsi_basic_staff.id`**。员工 id 与系统用户 id 是两套体系，多数不相等
  （既有数据 `IT202607310003 send_by=1` 等仅是 id 撞号巧合），导致所选人员 id 在 `hspsi_sys_user`
  中查不到或非启用 → 400。
- 同类问题：库存查询页「领用记录」视图的**领用人筛选**（`query.receiverId` 对应领用出库
  `receiver_id`，即系统用户 id）同样误用员工选项，筛选永远无法命中。

## 三、修复

| 文件 | 改动 |
| --- | --- |
| `apps/web/src/views/business/forms/InventoryTransferForm.vue` | 发出人/接收人下拉数据源改为 `/inventory/users/options`（系统用户，value=sys_user.id，含 `raw.orgId`） |
| `apps/web/src/views/business/InventoryStockPage.vue` | 领用人筛选数据源改为 `/inventory/users/options`（初始加载 + 组织切换后重载） |

两个接口返回结构兼容（`value`/`label`/`raw.orgId`），组织过滤逻辑不受影响。

## 四、验证

| 项 | 结果 |
| --- | --- |
| Web 类型检查（vue-tsc） | 通过 |

| 回归 | 组织/仓库联动、商品联动等逻辑未触碰；后端校验不变 |

## 五、遗留

- 员工（`hspsi_basic_staff`）与系统用户（`hspsi_sys_user`）的关联（`staff_id`）已有，若后续业务要求
  「按员工选人自动映射到对应系统用户」，可作为增强另行设计；本次按系统既有口径（校验/姓名解析均为系统用户）修复。
