# 待办系统持久化与接收人配置化实施记录（2026-08-26）

> 分支：`feature/0826-todo-persistence`
>
> 类型：待办（hspsi_sys_todo）写入/闭环重构，接收人由「权限码 + 组织授权」配置化解析（无数据库/接口契约变更，无新增表）

## 一、背景

原待办系统为「双轨制」：

- **持久化**：仅 3 个场景写 `hspsi_sys_todo`（领用提交→审批人、采购已付款→收货人、采购订单生命周期→收货人）；
- **实时生成**：`dashboard.todos()` 直接按各业务表 `approve_status=0` 现查 10 类单据，拼接到待办列表。

问题：领用申请既写持久化又被实时生成（重复）；持久化待办无完成闭环（审批通过后仍挂着）；采购"待收货"与"已付款"给同一收货人写两条。

## 二、业务语义（经业务确认）

1. **采购申请**审批通过（系统/OA 汇聚 `applyApplicationApproval`）→ 给该组织下"采购经理"下发待办（提示生成采购订单）；
2. **采购订单**发起采购 → 给订单收货人下发"待收货"待办；付款完成后**同一条件办**更新为"已完成付款，请关注到货/收货"；
3. **领用申请**：非借阅提交后保留系统内待审批，给审批人下发待办（原逻辑保留）；审批通过（系统审批或借阅 OA 回调）后 → 给**领用人 + 出库执行人**下发待办，并关闭原"待审批"待办。

## 三、接收人配置化（不写死角色）

- 新增 `TodoService.resolveRecipients(permissionCode, orgId)`：复用领用审批人判定范式（`hspsi_sys_user_authorized_org` + `user_role` + `role`(admin) + `role_menu` + `menu.code`），按权限码反查用户；
- 代码仅引用权限码，不出现角色名：
  - 采购经理 → `purchase:applications:generate-order`
  - 领用出库执行人 → `requisitions:outputs:confirm`
- 权限码对应菜单为配置数据（`hspsi_sys_menu.code`），角色调整只改菜单/角色配置，不改代码；无匹配配置时返回空，调用方按无人接收处理。

## 四、改动清单

| 文件 | 改动 |
| --- | --- |
| `apps/api/src/database/todo.service.ts` | 新增 `resolveRecipients(permissionCode, orgId)`、`completeByBusiness(businessType, businessId)`（按单据批量关闭 status=0 → 1 + completed_time） |
| `apps/api/src/purchase/purchase.service.ts` | ① `applyApplicationApproval` 审批通过分支：按 `purchase:applications:generate-order` 给采购经理写待办（businessType=`purchase_application`）；② `generateApplicationOrder` 生成订单后 `completeByBusiness('purchase_application')`；③ `syncPurchaseOrderTodo` 增加 `paid` 参数，文案随付款状态更新；④ `ensurePurchasePaidTodo` 改为复用 `syncPurchaseOrderTodo`（合并为一条 `purchase_receipt` 待办，删除独立 `purchase_order` 写入） |
| `apps/api/src/requisition/requisition.service.ts` | 新增 `syncApprovedRequisitionTodos`：审批通过后关闭 `draw_approve` 待办，给领用人（`applicant_id`）+ 出库执行人（`requisitions:outputs:confirm`）写 `draw_approve_output` 待办；接入系统 `approve`（通过/驳回）与 OA 回调 `handleOaApprovalResult` |
| `apps/api/src/dashboard/dashboard.service.ts` | `todos()`：移除领用申请实时生成（与持久化待办去重）；`storedRows` 路由按 `source_type/business_type` 映射（采购订单/采购申请/领用申请/领用出库） |
| `apps/api/src/purchase/purchase.service.spec.ts` | 重写"已付款待办"3 个用例：验证合并为单条 `purchase_receipt`、文案随状态更新、不再写 `purchase_order` 类型待办 |
| `apps/api/src/requisition/requisition.service.spec.ts` | `todoService` mock 补齐 `completeByBusiness`/`resolveRecipients` |

## 五、验证

- `tsc -p tsconfig.json --noEmit`：合并区域 0 错误（仅 `src/integrations/*/sync/*.spec.ts` 既有报错，与本改动无关）；
- `vitest run`：采购 34、领用 15、领用 OA 13、dashboard 6、todo.service 3 等全部通过；
- 采购"已付款"用例验证：`updates` 中同时出现"待收货/到货及入库"与"已完成付款"文案，均指向同一条 `purchase_receipt`（user_id=收货人、business_id=订单），且不再产生 `purchase_order` 类型待办。

## 六、上线前需要的数据配置（非代码）

1. 菜单表新增权限码（如无）：`purchase:applications:generate-order`、`requisitions:outputs:confirm`；
2. 将上述菜单挂到对应角色（如"采购经理"角色、仓库/出库执行人角色），并确保相关用户已授权目标组织（`hspsi_sys_user_authorized_org`）；
3. 未配置前 `resolveRecipients` 返回空，对应待办不会下发（不影响其他功能）。
