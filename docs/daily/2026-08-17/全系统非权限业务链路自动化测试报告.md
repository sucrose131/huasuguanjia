## 四、已打通的核心业务链路

### 1. 主数据与商品

- 启用仓库、供应商、客户、原料、成品和默认 SKU 可正常建立并被业务单据使用；
- 商品分类仓库类型校验、仓库所属组织校验、SKU 归属校验和混合仓库类型拆单提示的单元测试通过；
- 启用仓库缺少类型、启用分类缺少仓库类型的审计结果均为 0。

### 2. 采购链路

以下真实数据库链路全部成功：

`生产缺料 → 自动生成采购申请 → 人工审批采购申请 → 生成采购订单 → 开始采购 → 采购入库 → 库存增加 → 采购付款 → 采购退货`

采购申请拆单专项验证通过：

- 同一申请的两条明细分两次生成两张采购订单；
- 每次可选择供应商并录入明细总金额；
- 系统按“总金额 ÷ 申请数量”反算单价；
- 已生成明细再次生成时被拦截；
- 未发生入库或付款的采购订单删除后释放明细；
- 释放后的明细可以重新生成采购订单；
- 测试临时单据已清理。

### 3. 生产链路

以下真实数据库链路全部成功：

`销售缺口 → 生产计划 → 缺料采购 → 补料重校 → 生产计划审批 → BOM 正式领料出库 → 成品入库`

BOM 多次退库、累计可退量、并发超退、完成后唯一入库、冲正和库存不足保护已由 4 组专项单元测试覆盖；本轮未另建一组真实多次退库测试单据。

### 4. 销售与售后链路

以下真实数据库链路全部成功：

`销售订单 → 成品出库 → 销售收款 → 销售退款 → 销售退货 → 自动生成折价销售单 → 售后记录`

售后深度接口验证结果：

- 售后列表、详情、处理进展接口均返回 200；
- 当前抽检售后记录存在 1 条独立处理进展；
- 外部申请幂等、原始快照不覆盖、处理人防伪和售后可退换数量规则的专项测试通过。

### 5. 库存链路

以下真实数据库链路全部成功：

- 采购入库和生产成品入库增加库存；
- 生产领料、销售出库和报亏减少库存；

### 6. 领用链路

`领用申请 → 审批生成出库草稿 → 领用出库 → 领用退回 → 库存恢复`

直接领用反向生成申请、审批驳回不回滚已生效库存、自动生成退回草稿和幂等规则的专项测试通过。

## 五、当前未打通或存在风险的名单

### P1：定时任务功能未落地到本地数据库

**现象：**

- `GET /system/scheduled-tasks` 返回 500；
- `GET /system/scheduled-task-types` 返回 500；
- `/system/tasks` 没有可用菜单入口，直接访问会被导航守卫重定向。

**根因：**

- 本地 `hspsi-dev` 缺少 `hspsi_sys_scheduled_task`；
- 本地 `hspsi-dev` 缺少 `hspsi_sys_scheduled_task_run`；
- 代码仓库已有 `20260814_scheduled_task.sql` 和 `20260814_scheduled_task_run.sql`，但本地未执行；

### P1：真实 OSS 未配置，带签字的领用专项链路被阻断

独立执行“领用申请校验 → 自动出库 → 单据追溯”的数据库脚本时，保存签字附件返回：`阿里云 OSS 尚未配置完整`。

因此当前结论是：

- 附件权限、元数据、操作日志等 8 项单元测试通过；
- 真实上传、预览、下载和签字附件保存未打通；
- OSS 不可用时，要求上传签字的领用申请会返回 503。

### P2：全量测试命令和类型检查存在既有技术债

1. 3 个华数之家真实请求测试文件没有使用统一的 `RUN_EXTERNAL_INTEGRATION_TESTS` 跳过开关，导致本地缺少外部地址时直接让 `pnpm test` 失败；
2. API 外部集成测试文件存在 15 处 TypeScript 错误，集中在华数之家会议/分期订单、十方清源订单/用户同步测试；
3. `verify-quantity-guards.ts` 仍把生产计划测试夹具写成旧状态值 2，而当前正式出库要求状态值 3。临时按当前字典修正后，销售、采购、生产并发保护全部通过。

以上问题不阻塞 API 和 Web 的正式生产构建，但会导致仓库级“全量测试、全量类型检查”不能一条命令全绿。

### 外部环境待联调，不在本轮判失败

这些模块的本地模拟和单元测试已覆盖主要转换、幂等、失败重试和库存处理逻辑，但没有外部测试环境，不能标记为真实端到端已通过。
