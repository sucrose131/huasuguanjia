# 组织仓库库存商品联动全局收口实施记录

日期：2026-08-27

## 一、修复目标

解决部分业务界面在组织或仓库确定后仍加载全系统库存商品、SKU 和批次的问题，统一执行以下边界：

- 组织决定可选仓库；
- 实际库存操作由“组织 + 仓库”共同限定商品、SKU 和批次；
- 出库类场景只允许选择所选仓库中库存数量大于零的批次；
- 销售订单允许选择仓库类型匹配但当前零库存的商品，以保留缺货触发生产计划的业务链路。

## 二、实现内容

1. 新增前端统一的库存选项加载方法，缺少组织或仓库时直接返回空选项。
2. 后端库存选项接口强制要求组织和仓库，并验证仓库属于该组织。
3. 销售订单补齐所选仓库实际库存加载和“可用库存”展示数据来源。
4. 销售出库继承并锁定订单仓库，批次仅来自该订单组织和仓库。
5. 领用出库、库存调拨、库存调整、折价销售改为按组织和仓库按需加载库存。
6. 生产临时出库、编辑出库、执行出库、查看出库均增加组织范围及正库存条件。
7. 修复库存调整行内已加载库存与选中库存查找来源不一致的问题。

## 三、数据库影响

- 数据库表结构：无改动。
- 数据字典：无改动。
- 历史数据：未删除、未修改。

## 四、测试结果

- Web 类型检查：通过。
- API 自动化测试：库存 47 项、生产 14 项、销售 23 项、采购 34 项，共 118 项全部通过。
- 新增接口边界测试：缺少组织或仓库时返回空数据；组织和仓库齐全时校验归属关系并只查询正库存。
- API 全量类型检查：仍有华溯之家、十方清源集成测试文件的既有类型错误；本次修改文件未产生新增类型错误。

## 五、验收口径

- 组织未确定时不得出现可选仓库或库存商品。
- 仓库未确定时不得出现库存商品、SKU 或批次。
- 切换组织或仓库后必须清理旧的失效选择。
- 出库、调拨、调整、生产领料只能看到所选组织、所选仓库的正库存。
- 销售订单仍可选择当前零库存但仓库类型适配的商品，并正确展示其可用库存为零。
