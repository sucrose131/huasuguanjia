# PM-19 采购订单操作记录不完整 修复实施记录（2026-08-25）

> 分支：`fix/0825-confirm-403`（基于 `dev`）
>
> 类型：缺陷修复（审计能力补全，使用现有通用操作日志表，无表结构变更）
>
> 依据：《采购流程第二轮测试报告（PM-04～PM-20）》2026-08-24 版 P1「采购订单操作记录不完整」

## 一、问题

`PO202608240001` 已执行「开始采购」，但操作记录只显示「创建采购订单」「生成采购入库单」，未记录已执行的「开始采购」。不满足关键状态变更可审计要求。

## 二、根因

- `startOrder`（开始采购）与 `cancelOrderPending`（退回未到货）只更新订单 `status` 与 `updated_at`，**没有**任何面向审计的状态迁移记录；
- `operationHistory('orders')` 仅从业务表派生：创建、入库单、退货单、付款（这些本就有据可查），订单级状态迁移（开始采购/退回未到货）无处可读。
- 订单表 `status` 会随后续操作（到货、退货等）被 `recalcOrderStatus` 改写，无法从当前字段反推历史迁移时点，故不能靠派生，必须显式记录。

## 三、修复方案与映射

审计载体采用项目已有的通用操作日志表 `hspsi_sys_oper_log`（sales / amount-access / inventory-general / attachments 已在用），**无数据库结构变更**：

| 位置 | 改动 |
| --- | --- |
| `purchase.service.ts` 新增 `logOrderTransition(tx, poId, action, label, userId, detail)` | 写 `hspsi_sys_oper_log`：`service_name='purchase-order-transition'`、`router='purchase/orders/:poId/:action'`、`response_data=label`、`request_data=detail`、`created_by/updated_by=userId` |
| `startOrder` | 订单状态置 2 后记录「开始采购」（detail：订单进入采购中） |
| `cancelOrderPending` | 生成未到货退货单后记录「退回未到货」（detail：生成退货单 xxx） |
| `operationHistory('orders')` | 按 `service_name + router 前缀` 读取上述日志并合并进操作记录（key=`transition-:id`） |

映射：操作记录展示字段 ← `hspsi_sys_oper_log`（action=`response_data`、result=「已执行」、operator=`created_by`、time=`created_at`、detail=`request_data`）。

范围说明：付款、入库确认已由 `hspsi_purchase_order_payment` / `hspsi_purchase_order_input` 派生展示，不重复写日志。
