# 采购/领用申请与采购订单「仓库⇄商品」双向联动 改进实施记录（2026-08-25）

> 分支：`fix/0825-goods-warehouse-bidirectional`（基于 `feat/0824-detail-goods-enrich`）
>
> 类型：前端交互改进（纯前端，无数据库、无接口契约变更；后端校验保持不变）

## 一、需求与边界（已与业务确认）

- 问题：采购申请、采购订单、领用申请三个表单**先选仓库再选商品**时，商品下拉显示该组织全部商品，
  未按仓库类型收窄；而销售订单、采购入库、出库、通用入出库等已是「选仓库→商品过滤」，交互不一致。
- 方案：**双向联动**
  1. 选了仓库 → 商品下拉按仓库类型过滤（本需求新增）；
  2. 选了商品 → 仓库下拉按商品类型收窄（原有能力，保留）；
  3. 两者都未选 → 显示组织全部商品；
  4. 混合类型明细（`documentWarehouseType=0`）仍只受已选仓库约束，多类型单据可通过先不选仓库录入。
- 边界（业务已确认）：分类未配置仓库类型的商品（`categoryWarehouseType=0`）在选仓库后**保留显示**。

## 二、实现

| 文件 | 改动 |
| --- | --- |
| `apps/web/src/utils/goods-warehouse.ts`（新增） | `filterGoodsByWarehouseType(goods, warehouseType)`：未选仓库返回全量；选仓库后保留 `categoryWarehouseType===0` 与匹配类型商品。`warehouseTypeOf(warehouses, warehouseId)`：从 `raw.warehouseType` / `warehouseType` 解析所选仓库类型 |
| `apps/web/src/utils/goods-warehouse.spec.ts`（新增） | 4 项单测（全量/过滤/空列表/类型解析） |
| `forms/RequisitionApplicationForm.vue` | 新增 `selectedWarehouseType` computed；`searchGoodsOptions` 先按仓库类型过滤再按关键字匹配 |
| `forms/PurchaseApplicationForm.vue` | 同上（仓库选项源 `options.warehouses`） |
| `forms/PurchaseOrderForm.vue` | 同上 |

数据流：仓库下拉（已含 `warehouseType`）→ `selectedWarehouseType` → 过滤 `contextGoods`
（`all-goods-options` 已携带 `categoryWarehouseType`）→ 商品下拉展示。未增加任何请求。

## 四、影响范围

- 仅三个表单的商品搜索下拉展示收窄；仓库下拉、保存校验、后端过账逻辑均不变。
- 行为变化：编辑已选仓库的单据时，新增明细只能选择与仓库类型匹配（或未配置类型）的商品；
  需要混合类型明细时先不选仓库再录入（与既有「仓库按商品收窄」逻辑对称）。
