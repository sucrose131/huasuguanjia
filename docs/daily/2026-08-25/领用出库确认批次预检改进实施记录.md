# 领用出库确认前批次预检与引导 改进实施记录（2026-08-25）

> 分支：`fix/0825-requisition-output-batch-check`（基于 `feat/0824-detail-goods-enrich`）
>
> 类型：前端交互改进 + 后端文案引导（无数据库、无接口契约变更）
>
> 背景：用户在领用出库列表对自动生成的出库单 `DRO20260825000002`（1900860006）直接点「确认」，收到
> `HTTP 400 确认出库前必须填写全部物品批号`。排查结论：后端校验正确（批次出库必须有批次），问题在
> 前端交互——列表「确认」不预检批次、编辑保存不校验批次，用户无从获知需先选批次。

## 一、改动清单

| 文件 | 改动 | 说明 |
| --- | --- | --- |
| `apps/web/src/views/business/business-document-config.ts` | `RowAction` 新增 `verify?: (row) => string \| null \| Promise<...>` | 共享引擎行操作预检钩子（向后兼容，其余页面不受影响） |
| `apps/web/src/views/business/BusinessDocumentPage.vue` | `runAction` 在确认弹窗前执行 `verify`，返回非空文案则 `ElMessage.warning` 并中止（不发请求、不弹框） | 通用能力：先引导补数据再操作 |
| `apps/web/src/views/business/configs/requisition-output.ts` | 「确认」行操作新增 `verify`：拉取出库单详情，任一明细 `batchNo` 为空则提示「部分出库明细未选择库存批次，请先编辑并选择全部批次后再确认」 | 领用出库确认前批次预检 |
| `apps/web/src/views/business/forms/RequisitionOutputForm.vue` | `validate()`：非直接出库（申请型）模式新增「全部明细必须选择库存批次且数量>0」校验 | 保存即拦截，避免保存不可确认的出库单（与直接出库口径一致） |
| `apps/api/src/requisition/requisition.service.ts` | 确认出库批次校验文案增加引导：「确认出库前必须填写全部物品批号，请先编辑出库单并选择库存批次」 | 兜底提示（接口直调场景） |

字段映射：前端「库存批次」下拉 → 行 `stockKey` → `stockChanged` 写入 `batchNo` → 保存 `details[].batchNo` → 后端
`hspsi_draw_approve_output_detail.batch_no`；确认预检读取 `GET /requisitions/outputs/:id` 返回的 `details[].batchNo`。

## 三、影响范围与说明

- 共享引擎 `RowAction.verify` 为新增可选钩子，未使用的页面行为完全不变。
- 领用出库「确认」点击时会多发一次详情请求（仅当批次缺失时才中止），开销可忽略。
- 同一交互缺口也存在于采购入库确认（同样要求批号），本分支未扩展；如需可复用 `verify` 钩子跟进。
