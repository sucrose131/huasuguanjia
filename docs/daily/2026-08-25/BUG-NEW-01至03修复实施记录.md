## 一、BUG-NEW-01：库存查询按 SKU 编号搜不到（P0）

### 1.1 问题

采购入库确认后，库存查询中按 **SKU 编号**（如 `1900701110`）搜索返回 0 条。

### 1.2 数据库核对结论

- 原测试数据（`GA202608210002` / `PO202608210003` / 批次 `AUTOGA-20260821-02`）在当前本地库 `hspsi-dev` 中已不存在，无法直接回查原始单据。
- 用今日单据 `GA202608240001`（org 9 / 仓库 1 / sku `1900701110` / 批次 `PH20260824`）按报告步骤真实复现：确认入库 → 数据库回查 **单据（`comfirm_status=1`、`posting_version=1`）、库存余额（+1）、批次库存（+1）、库存流水（`source_no=GA202608240001`，posting_key 唯一）四者一致**。
- 库存查询验证：按商品名称、编码搜索均能查到；按 **SKU 编号搜索返回 0**。

**结论**：库存过账链路正确；缺陷在库存查询 keyword 搜索——只匹配商品名称/编码与 SKU 规格文本（`spec_models`），而“SKU 编号”就是 `sku_id` 主键，纯数字搜索永远为空。

### 1.3 修复

仅调整后端查询条件（`apps/api/src/inventory/inventory.service.ts`），无数据库、无接口契约变更：

| 位置 | 改动 |
| --- | --- |
| `stocks()` keyword 分支 | 关键字为纯数字时，`where.OR` 追加 `{ sku_id: 精确值 }` |
| `inventoryKeywordIds()` 共享助手 | 返回值 `skuIds` 追加纯数字关键字的 `sku_id` 精确匹配（库存查询“领用记录”视图及库存预警、调拨、调整/报损列表等 5 处共用，一并消除同源缺陷） |

### 1.4 验证

- 修复前：SKU `1900701110` 搜索 total=0；修复后：total=4（含批次 `PH20260824` qty=1），名称搜索不受影响。
- 新增 3 项单测（stocks 纯数字 SKU 匹配 / 非数字行为不变 / 无关键字不匹配）。

## 二、BUG-NEW-02：超额付款被静默截断（P1）

### 2.1 问题

剩余应付 ¥1.34 时输入 ¥2.00，系统不报错，而是静默改成 ¥1.34 并提示成功。

### 2.2 根因与修复

- 根因：前端 `el-input-number` 绑定了 `:max="剩余应付"`，Element Plus 在输入超限时**自动改写输入值**，用户输入被无声替换；后端 `savePayment` 的上限校验（`付款金额超过剩余应付`，HTTP 400）一直存在且有效。
- 修复（`apps/web/src/views/business/forms/PurchasePaymentForm.vue`）：移除 `:max` 与 `maxAmount` 计算属性，允许用户输入原值；保存时由既有前端 `validate()`（“付款金额不能超过剩余应付”）明确提示并拦截，后端继续兜底校验。

### 2.3 验证

- 后端实调：对未付订单 `PO202608240001`（剩余 ¥20）提交 ¥9999 → HTTP 400 “付款金额超过剩余应付”。
- 前端行为：输入超限值不再被改写，保存时弹出明确提示（需浏览器页面复核）。

## 三、BUG-NEW-03：采购退货列表来源入库单号不一致（P1）

### 3.1 问题

退货表单及全链路追溯显示来源 `GA202608210002`，退货列表却显示 `GA1900920036`，编号不一致。

### 3.2 根因与修复

- 根因：退货列表/详情接口未返回来源入库单号（`po_input_no`），前端列表展示的来源编号与详情/追溯口径不一致。
- 修复（`apps/api/src/purchase/purchase.service.ts`）：`returns()` 列表按 `po_input_id` 关联 `hspsi_purchase_order_input` 补 `receiptNo`；`returnDetail()` 同步补 `receiptNo`。列表、详情、追溯统一读取同一张表的真实单号。

### 3.3 验证（真实 API 调用）

- `CGTH1900930006` → `receiptNo=GA1900920018`；`CGTH1900930005` → `receiptNo=GA1900920007`；详情接口同步返回。
- `PRT202608120001` 来源 `po_input_id=1900920028` 在入库单表中已硬删除（不存在该行），返回 `receiptNo=null`——不伪造编号，属数据层情况而非代码缺陷。
