# 消息中心改造与审批/入库消息通知实施记录（2026-08-25）

## 需求背景

原始一级需求（工作台消息中心）：

1. 消息中心内容直接读取 `hspsi_sys_message` 与 `hspsi_sys_notice` 两张表，不再展示临时拼装消息；
2. OA 回调审批**通过/驳回**时向业务单据创建人发送审批结果消息；
3. 采购入库单**确认入库**时向**采购订单创建人**发送入库通知（经业务确认：通知采购订单创建人而非采购申请创建人；同一订单多次分批入库时**每次入库各发一条**，同一张入库单重复确认不重复发）；
4. 消息列表明确标识已读/未读，未读可一键标记为已读。

## 实现内容

### 1. 消息中心只读两表（`apps/api/src/dashboard/dashboard.service.ts`）

- `messages()` 删除 `generated-*` 临时拼装逻辑（待办审批、库存预警、最新销售/采购/生产动态），仅按 `user_id` 读取 `hspsi_sys_message` 并 join `hspsi_sys_notice`；
- 保留分类推导口径：`notice.source_type===2 → 审批消息`、`notice.level>=2 → 预警消息`、其余 → `业务消息`；
- 保留 `category` 过滤、分页与 `unreadCount`（全量未读计数，不受分页影响）；
- `items[].createdAt` 保持后端原样返回（UTC Date，与其他业务接口一致），**不在后端新增格式化**；消息中心前端 `DashboardPage.vue` 的 `dateText` 改为复用项目标准 `@/utils/format` 的 `dateText(value, true)`（本地时区转换后截取到分钟），与 GoodsPage/InventoryStockPage 等其他页面同一时间处理模式；
- 响应其余字段不变（id/title/content/category/isRead/readTime），`GET /dashboard` 总览与前端不受影响。

### 2. 新增统一消息写入服务（`apps/api/src/message/message.service.ts` + `message.module.ts`）

- `sendApprovalNotification({ businessType, businessId, procStatus })`：仅处理 `PASSED/REJECTED`；按 `business_type` 映射单据表（采购申请/采购退货/生产计划/销售订单/领用申请/库存调拨/调整/盘点/报损/报亏/报盈）查询单据号、`created_by`、组织；创建 `hspsi_sys_notice`（`source_type=2`，`level=1`，`status=1`，`publish_time=now`）+ `hspsi_sys_message`（`is_read=0`）；
- `sendPurchaseReceiptNotification({ poId, receiptNo, orderNo, quantity })`：按 `po_id` 读取 `hspsi_purchase_order.created_by/org_id` 发送入库通知（`source_type=1`，标题「采购入库通知」，正文含订单号、入库单号、本次入库数量）；
- 单据缺失、创建人为 0、businessId 缺失、非通过/驳回状态 → 静默跳过，不写库。

### 3. OA 回调审批结果消息（`apps/api/src/requisition/requisition-oa-callback.controller.ts`、`requisition.module.ts`）

- 构造器注入 `MessageService`；`hspsi_oa_approval_instance` 查询 select 增加 `business_id`；
- 各业务 handler 分发后调用 `notifyApprovalResult`：`duplicate`（重复回调）不发、非 `PASSED/REJECTED` 不发、无 `business_id` 不发；
- 通知写库失败仅通过 NestJS `Logger.error` 记录应用日志，**不修改 callback_log**（`hspsi_oa_approval_callback_log` 只反映审批结果处理本身），不影响回调 ack（业务确认口径）。

### 4. 采购入库通知（`apps/api/src/purchase/purchase.service.ts`、`purchase.module.ts`）

- 构造器注入 `MessageService`；
- `confirmReceipt` 事务内记录 `{ poId, receiptNo, orderNo, quantity }`（`alreadyConfirmed` 提前返回不发），**事务提交后**调用 `sendPurchaseReceiptNotification`，通知失败仅 `Logger.error` 记录应用日志、不影响入库结果；
- 行为：每次不同入库单确认成功各发一条；同一张单重复确认不发；生成/编辑待确认入库单（`saveReceipt`/`generateReceipt`）不发；订单 `pur_id=0`（无关联申请）也正常通知订单创建人。

### 5. 前端已读/未读标识（`apps/web/src/views/DashboardPage.vue`）

- 消息行改为 `<div role="button">`（避免按钮嵌套），每行显示 `未读`（danger）或 `已读`（info）标签，保留未读行浅色背景与红点；
- 未读行增加「标记已读」按钮（`@click.stop`），点击行或按钮均调用既有 `POST /dashboard/messages/:id/read` 后刷新列表与未读数。

## 字段映射

| 页面/通知内容 | API | 表.字段 | 写入时机 |
| --- | --- | --- | --- |
| 列表标题/正文/分类 | GET /dashboard/messages → items[].title/content/category | hspsi_sys_notice.title/content/source_type/level | 只读 |
| 已读状态 | items[].isRead | hspsi_sys_message.is_read | 只读 |
| 标记已读 | POST /dashboard/messages/:id/read | hspsi_sys_message.is_read=1, read_time | 用户操作 |
| 审批消息 | 无新 API（服务内部） | notice(source_type=2)+message | OA 回调非重复 PASSED/REJECTED |
| 入库通知 | 无新 API（服务内部） | notice(source_type=1)+message | 每次确认入库成功后 |
| 铃铛未读数 | GET /dashboard/messages → unreadCount | hspsi_sys_message.is_read=0 计数 | 只读 |

### 6. 消息中心分页（`dashboard.service.ts`、`DashboardPage.vue`）

- 后端 `GET /dashboard/messages` 支持 `page/pageSize/category`（原有），响应新增 `categoryCounts`（审批/预警/业务三类总数，基于全量未过滤数据，不受当前分类与分页影响，供侧栏徽标使用）；
- 前端消息中心改为服务端分页：`pageSize=20`，列表底部新增 `el-pagination`（上一页/页码/下一页），与待办面板同款 `table-footer`；分类切换调用后端 `category` 参数过滤并重置到第 1 页；侧栏徽标改用 `categoryCounts`；
- 标记已读后按当前页/分类刷新，未读数（全局）与列表状态同步。

## 影响范围

- 接口：`GET /dashboard/messages`（移除临时拼装消息）、`POST /dashboard/messages/:id/read`（不变）；无新增对外 API；
- 页面：工作台「消息中心」列表、总览消息摘要、顶部铃铛未读数；
- 数据：仅写入既有 `hspsi_sys_notice`/`hspsi_sys_message`，无表/字段/字典变更；
- 模块：新增 `MessageModule`，`PurchaseModule`、`RequisitionModule` 引入；`PurchaseService`、OA 回调控制器构造器增加 `MessageService` 依赖。
