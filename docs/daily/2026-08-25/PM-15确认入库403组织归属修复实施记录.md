# PM-15 采购经理确认入库 403（组织归属）修复实施记录（2026-08-25）

> 分支：`dev`（工作区改动，尚未提交）
>
> 类型：数据权限中间件缺陷修复（影响所有库存过账类操作，无数据库/接口变更）
>
> 依据：《采购流程第二轮测试报告（PM-04～PM-20）》2026-08-24 版 P0「采购经理无法确认采购入库」

## 一、问题

采购经理账号（用户 219，非超管）在采购入库 → 确认入库时提示「无法确认目标数据的组织归属」，接口返回 HTTP 403，单据停留在待入库；库存、退货、退款、财务联动全部中断。

## 二、根因（数据库核对 + 代码定位）

- 报告原始单据 `GA202608240001`（org 9 / 仓库 1 / 批次 `PH20260824`）仍在库中，可复现。
- `apps/api/src/database/prisma.service.ts` 的数据权限中间件 `assertTargetWhere` 对非超管用户的所有 `findUnique/update/upsert/delete` 操作，需要先确认目标行属于用户授权组织：
  1. 若 where 含组织字段值 → 直接比对（通过）；
  2. 否则查找**标量唯一键**（`typeof where[field] !== 'object'`）回查行组织；
  3. **复合唯一键（如 `hspsi_inventory_batch_total` 的 `goods_id_sku_id_warehouse_id_batch_no`）的 where 值是对象，且键内不含 org_id** → 既无标量唯一键可查，也没有组织字段 → 直接抛 403「无法确认目标数据的组织归属」。
- 该 Prisma 版本（5.22）的 dmmf 中复合 `@@id`/`@@unique` **不作为 `isId/isUnique` 字段暴露**，原 `uniqueColumns` 对批次表为空，进一步确认无法解析。
- 影响面：`InventoryPostingService.post`（采购入库确认/撤销、销售/领用/生产出库、通用出入库、调拨、报损等所有走批次库存的过账）对**非超管用户**一律 403。admin 因 `isSuperAdmin` 跳过中间件，故此前 admin 验证全部通过、掩盖了该问题。

## 三、修复方案与映射

仅修改数据权限中间件（`apps/api/src/database/prisma.service.ts`），不涉及数据库结构、接口契约与字典：

| 位置 | 改动 |
| --- | --- |
| `ScopedModel` 类型 | 新增 `compoundKeys: string[][]`（复合唯一键列集） |
| `scopedModels()` | 从 dmmf `model.primaryKey.fields` / `model.uniqueFields` 提取复合键列集（转为可变数组） |
| `assertTargetWhere` | 无标量唯一键时，遍历 `compoundKeys`：按键名（列名 `join('_')`）取 where 对象值，按列 `WHERE col1=? AND col2=?` 回查目标行 `org_id`；命中且组织不符才 403；未命中行放行（交由底层返回 not found / upsert-create 走 create 组织校验） |

安全语义保持不变：跨组织访问仍被拒绝（验证见下）。
