# 库存查询按权限导出 Excel 实施构想与记录

## 一、需求确认与范围

- 在“库存管理—库存查询”的仓库库存视图增加“导出 Excel”按钮；领用记录视图不增加导出。
- 导出当前最近一次成功查询的全部匹配结果，不受当前分页和每页条数影响。
- 组织为必选项；选择具体仓库时只导出该仓库，选择“全部仓库”时只包含当前账号在该组织内获授权的数据。
- 导出固定为真实 `.xlsx` 文件，不用 CSV 文件改扩展名。
- 导出只读，不修改库存、批次或业务单据数据。
- 本次按业务确认增加独立操作权限 `inventory:stocks:export`；默认仅超级管理员拥有，其他角色由管理员按需授权。

## 二、数据和权限核对

库存查询来源仍为 `hspsi_inventory_batch_total`，商品、SKU、组织、仓库、单位和分类名称继续复用现有库存查询映射。服务端查询运行在现有 Prisma 数据范围上下文中，前端传入的组织、仓库 ID 不能扩大账号授权范围。

金额权限每次导出时通过 `AmountAccessService` 重新读取，不使用页面上一次返回结果判断。库存快照遵循现有“仅全部范围可见金额”的口径：

| 用户金额权限      | 单位成本、库存金额 |
| ----------------- | ------------------ |
| 无金额权限        | `¥****`            |
| 仅查看—权限内自己 | `¥****`            |
| 可编辑—权限内自己 | `¥****`            |
| 仅查看—权限内全部 | 输出真实数值       |
| 可编辑—权限内全部 | 输出真实数值       |

独立导出权限只决定能否执行导出，不改变金额权限和组织数据范围。即使拥有导出权限，没有“权限内全部”的金额权限时，文件中的单位成本和库存金额仍只能是 `¥****`。

## 三、界面和交互

1. “导出 Excel”显示在库存查询页右上角、刷新按钮之前。
2. 仅拥有 `inventory:stocks:export` 的账号显示按钮；后端同时要求库存查询页面权限和导出权限。
3. 未选择组织、尚未成功查询或当前结果为空时不执行导出，并给出明确提示。
4. 导出使用最近一次成功查询条件，不把 `page/pageSize` 传给导出接口，避免只导出当前页。
5. 下载期间按钮显示加载状态，接口错误沿用全局错误提示；二进制错误响应会解析服务端 JSON 消息。

## 四、字段—API—数据映射

接口：`GET /api/inventory/stocks/export`。

| Excel 顺序/字段 | 数据来源                           | 类型与格式                               |
| --------------- | ---------------------------------- | ---------------------------------------- |
| 1 序号          | 导出结果行号                       | 数字                                     |
| 2 ID            | 商品、SKU、仓库、批号组合 ID       | 文本                                     |
| 3 商品编码      | `hspsi_goods_info.query_code`      | 文本，保留前导零                         |
| 4 商品名称      | `hspsi_goods_info.goods_name`      | 文本                                     |
| 5 规格          | `hspsi_goods_info_sku.spec_models` | 文本                                     |
| 6 组织          | 组织名称映射                       | 文本                                     |
| 7 所在仓库      | 仓库名称映射                       | 文本                                     |
| 8 即时结存      | `inventory_qty`                    | 数字，最多 4 位小数                      |
| 9 累计入库      | `input_qty`                        | 数字，最多 4 位小数                      |
| 10 累计出库     | `output_qty`                       | 数字，最多 4 位小数                      |
| 11 单位成本     | `inventory_amount / inventory_qty` | 有权时数值、4 位小数；无权时文本 `¥****` |
| 12 库存金额     | `inventory_amount`                 | 有权时数值、2 位小数；无权时文本 `¥****` |
| 13 库存状态     | 即时结存是否大于 0                 | “有库存”或“无库存”                       |

文件只有一个可见工作表，无隐藏工作表、隐藏列、公式或操作列。文件头记录组织、仓库、商品条件、批号、仅显示有库存条件、Asia/Shanghai 导出时间和数据条数。

## 五、后端保护和性能边界

- 服务端强制校验组织为有效正整数，并查询有效组织；无权或不存在时拒绝。
- 指定仓库时校验仓库有效、属于所选组织且处于账号授权范围内。
- 复用页面库存筛选构造，保证商品关键字、批号和仅有库存条件一致。
- 空结果返回业务错误，不生成空文件。
- 单次导出上限 100,000 条，超过后要求缩小查询范围，避免单请求占用过多内存和数据库资源。
- 工作簿使用流式写出；响应设置 `no-store`，防止包含金额的数据被浏览器或中间缓存长期保存。
- 导出成功后写入操作日志，记录用户、筛选条件、文件名、条数及是否包含真实金额；审计日志失败不会把已经成功的文件下载改成业务失败。
