# 库存盘点新增单号冲突修复记录

## 一、问题与原因

- 新增库存盘点时，数据库返回 `uk_check_no` 唯一约束冲突，接口表现为服务器内部错误。
- 盘点单号使用非采购业务共享的 Redis 当日流水；本地 Redis 数据重建或丢失后，计数可能落后于 `hspsi_inventory_check.check_no` 已有最大流水，第一次新增会生成重复单号。
- 该问题与 OA 是否连通无关；OA 不参与新增盘点单号生成。

## 二、数据库核对

- 本地连接已确认是 `127.0.0.1:3306/hspsi-dev`。
- 现有盘点单号字段为 `hspsi_inventory_check.check_no`，唯一约束为 `uk_check_no`。
- 本次不新增表、字段、索引或数据字典，也不清理历史盘点数据。

## 三、修复方案

1. 生成 `IC` 盘点单号前，读取数据库当日最大六位流水。
2. 将数据库最大流水作为 Redis 原子脚本的最低水位；Redis 不存在或落后时先抬升，再执行递增。
3. 保留非采购业务原有共享 Redis 键和六位流水格式，不改变历史单号及其他业务前缀。
4. Redis 无法连接时仍按既有规则返回业务单号服务不可用，不回退为进程内计数。

## 四、验证记录

- 自动化覆盖 Redis 计数重置、数据库已有 `IC20260909000013` 的场景，下一单应生成 `IC20260909000014`。
- 业务单号服务目标测试通过；API 生产构建通过。
- 本修复不依赖 OA，不修改库存数量、库存金额或盘点明细。

## 五、test 环境注意事项

- test 环境 Redis 若与本地或其他环境共用，仍存在跨环境计数污染风险，必须保证 `NODE_ENV` 和 Redis 实例/键空间隔离。
- 数据库水位查询可消除 Redis 落后导致的重复单号，但不能替代 Redis 可用性；Redis 故障仍会阻止新增盘点。
