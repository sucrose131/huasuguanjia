# 采购入库来源订单金额权限收口实施构想与记录

## 一、需求确认

- 采购订单“生成入库”操作权限保持不变，允许有业务权限的用户代他人订单生成入库单。
- 普通采购入库、换货采购入库中的单价和金额，归属来源统一按采购订单创建人判断。
- 金额权限无查看能力：金额始终脱敏。
- 金额范围为 `own`：仅来源采购订单 `created_by` 等于当前用户时显示金额。
- 金额范围为 `all`：在既有菜单、组织和数据权限范围内显示金额。
- 临时采购入库仍沿用自身生成链路；其反向生成的采购订单创建人与入库操作人一致。

## 二、数据库核对

| 对象 | 关键字段 | 用途 |
| --- | --- | --- |
| `hspsi_purchase_order` | `po_id`、`created_by` | 来源采购订单及金额归属人 |
| `hspsi_purchase_order_input` | `po_input_id`、`po_id`、`created_by` | 入库单、来源订单及实际生成操作人 |
| `hspsi_purchase_order_detail` | `unit_price`、`total_amout` | 订单单价、金额真实数据 |

- 已通过 `127.0.0.1:3306/hspsi-dev` 只读连接确认上述订单和入库字段可用。
- 来源订单创建人与入库单创建人是两个不同业务口径，不修改或复用现有字段含义。
- 本次不新增表、字段、索引或数据字典，不执行数据迁移。

## 三、界面与接口设计

1. `GET /api/purchase/orders/:id`
   - 按采购订单 `created_by` 计算记录级金额权限。
   - 返回准确的 `amountMasked`，他人订单不再出现“金额已置空但页面按可见处理”的情况。
2. `GET /api/purchase/receipts/:id`
   - 查询入库单关联采购订单的 `created_by`，以该字段作为金额归属。
   - 不再使用入库单 `created_by`（执行生成入库的人）决定金额可见性。
   - 无权限时在响应层将注册的金额字段置空，并返回 `amountMasked: true`。
3. 采购入库表单
   - 优先使用接口 `amountMasked` 控制单价、行金额和合计金额统一显示 `¥ ****`。
   - 切换来源订单时先清除旧明细和旧脱敏状态，防止异步请求期间短暂显示上一张订单金额。
   - 普通采购入库保存仍不提交来源订单单价，真实价格继续由服务端订单数据提供。

## 四、业务与安全边界

- 只调整金额响应和展示，不限制代办生成、办理入库及库存过账权限。
- 不将脱敏后的空值写回数据库，不影响库存计价、采购应付或财务计算。
- 入库单创建人仍表示实际操作人，用于操作记录、列表显示和既有业务权限。
- 换货入库使用相同的来源订单金额归属规则。
- 采购入库详情使用专用来源归属判断，并跳过全局按入库单创建人的二次范围判断，避免订单本人因入库单由他人生成而被误脱敏。

## 六、验收用例

1. `view/edit + own` 用户为订单创建人，即使入库单由他人生成，也能查看来源订单金额。
2. `view/edit + own` 用户不是订单创建人，即使自己执行生成入库，也只能看到 `¥ ****`。
3. `view/edit + all` 用户可查看权限范围内采购订单及对应入库单金额。
4. 无金额查看权限的用户始终只能看到 `¥ ****`。
5. 普通入库和换货入库执行结果一致，入库数量、批次和库存过账不受影响。
6. 切换来源订单时不显示上一订单的价格或合计金额。
7. 浏览器网络响应中，无权限场景的 `unitPrice`、`amount`、`totalAmount` 等金额字段为 `null`。

## 七、验证结果

- API 采购服务及金额归属测试：64 项通过。
- Web 金额权限及生成入库流程测试：18 项通过。
- API 生产构建通过，Web 类型检查通过。
- 浏览器以临时 `view + own` 测试账号对他人采购订单执行“生成入库”：生成成功后单价、行金额、合计金额均为 `¥ ****`。
- 同一入库详情接口返回 `amountMasked=true`，明细 `unitPrice`、`amount` 均为 `null`。
- 将测试账号金额范围切换为 `all` 后刷新：单价、行金额及合计金额均正常显示 `¥ 60.00`。
- 验收完成后已删除临时测试账号、金额授权、角色关系、测试入库单、入库明细及单据链路关系。
