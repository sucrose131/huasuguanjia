# 下拉选项远程搜索修复实施记录（2026-08-14）

## 一、问题

BOM 编排「成品」下拉框无法选择商品 `1900700117`（编码 `test`，名称「测试商品」）。根因不是商品数据异常（该商品 `status=1`、未删除、分类启用、存在有效 SKU），而是前端多处参考数据下拉框只加载了固定 `pageSize: 100` 的首屏数据（后端列表统一按 `goods_id DESC` / 主键倒序，且多数接口把 `pageSize` 上限限制在 100）。当前库共 526 个启用商品，该商品在倒序中排第 516 位，超出首屏 100 条，且下拉框仅 `filterable`（本地过滤）无远程搜索，导致永远选不到。

同类问题同样存在于生产计划、BOM、销售/采购订单、供应商、采购入库/申请等「主数据/单据」下拉框：业务单据随时间增长必然超过 100 条上限。

## 二、方案

新增通用组件 `RemoteSelect.vue`：`el-select` + `filterable remote reserve-keyword`，输入关键字时防抖（250ms）调用传入的 `fetch(keyword)`，打开下拉时用空关键字回显已有列表；选中值不在当前搜索结果时以 `selectedLabel`（选中时缓存）或 `currentLabel` 回显，避免编辑态显示裸 ID。

各页面提供 `fetch` 函数：空关键字返回本地已加载列表（保留「点开即见列表」体验），非空关键字调用后端 `keyword` 接口并把命中项合并回本地 options（保证 `goodsOf`/`byId`/`lookup` 等展示辅助仍能取到名称）。

## 五、遗留与边界

- 基础资料 `options` 接口（组织/部门/仓库/供应商/客户/用户/单位）后端 `pageSize` 仍统一上限 100；本次已为「供应商、采购订单」等高频增长项加远程搜索，其余基础资料若业务量增长超过 100 需按同样模式补远程搜索或放开上限。
- 库存批次下拉（`/inventory/stocks?pageSize=200`，TempSupplementDialog / ExecuteOutDialog / ViewOutboundDialog / EditOutboundDialog 等）为另一数据域，批次超过 200 时存在同类隐患，本次未处理。
- 浏览器端到端验收（真实账号操作 BOM 成品检索并保存）待业务负责人确认。
