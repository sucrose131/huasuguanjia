# 定时任务定义与调度管理实施记录（2026-08-14）

## 一、今日工作范围

落地系统管理「任务管理」：用数据库保存预置同步任务的名称、开关和 Linux Cron，API 进程按 `Asia/Shanghai` 调度。后台可新增/删除任务（类型从已实现处理器下拉选择）、修改执行时间，保存后无需重启。

库表已在 `hspsi-dev` 与当前 `.env` 指向的 `hspsi-test` 执行。菜单 `system:4:view` → `/system/tasks` 已种子。

## 三、接口与调度

- `GET /system/scheduled-task-types`
- `GET /system/scheduled-task-cron-preview`
- `GET/POST /system/scheduled-tasks`
- `PUT/DELETE /system/scheduled-tasks/:id`
- `POST /system/scheduled-tasks/:id/run`
- `GET /system/scheduled-tasks/:id/runs`
- `GET /system/scheduled-tasks/:id/runs/:runId`

调度器每约 10 秒检查当前分钟，读取启用任务并按 Cron 投递。同一 `task_code` 进程内互斥。命中的任务进入进程内单通道队列，串行执行，避免与网站共用 Prisma 连接池时并行打满。OA 组织同步按启用账套顺序执行组织 → 职位 → 人员。

列表/预览的下次执行、最近执行按 `Asia/Shanghai` 墙钟返回（`YYYY-MM-DD HH:mm`），不再直接展示 UTC。

扫描数据库失败时不记下当前分钟，约 10 秒后重试，避免漏掉当天定点任务。执行器写入开始时间失败时回写失败状态，不再变成未捕获拒绝。

## 四、界面

系统管理新增「任务管理」页：列表展示 Cron、启用开关、下次执行、最近结果；「执行记录」查看历史；编辑可改执行时间并预览下次执行；支持立即执行和软删除。

## 七、缺陷修复（同日）

| 问题 | 处理 |
| --- | --- |
| 下次/最近执行把 UTC ISO 切片成北京时间前一天 17:00 | API 按 `Asia/Shanghai` 返回 `YYYY-MM-DD HH:mm`，页面同样按北京时间解析 |
| `listEnabled` 失败仍记下分钟，当天定点任务漏跑 | 仅在扫描成功后记下分钟；失败约 10 秒重试 |
| `void execute` 在 `markRunStart` 失败时未捕获拒绝 | 回写失败状态后返回，队列排空也包住异常 |
| 默认同 Cron 并行四类同步打满连接池、网站卡死 | 进程内单通道串行队列；立即执行若有在跑任务则排队。商品同步补进程内防重入 |

## 八、稳定性与安全补强（同日）

| 项 | 处理 |
| --- | --- |
| 原始 error.message 泄露到列表 | 任务表 `last_message` 仍脱敏；执行历史 `message` 写入原始错误（截断 500） |
| `BigInt(userId)` 非法输入 500 | `parseUserId` 校验数字，返回 400 |
| 下游 hang 拖死串行队列 | 30 分钟超时后释放 `running`，同 code 仍等底层结束再重入 |
| 无执行历史 / 手动执行无法追踪 | 表 `hspsi_sys_scheduled_task_run`；`POST /run` 返回 `runId` |
| 失败要等到次日 Cron | 自动重试 3 次（1/5/15 分钟），等待期间不占用队列 |
