# 组织—仓库—商品联动约束补齐实施记录

> 日期：2026-08-14
>
> 需求：实现「组织—仓库—仓库类型—商品分类—商品」业务约束联动（补齐缺口）
>
> 分支：`dev`

## 原始需求

实现「组织—仓库—仓库类型—商品分类—商品」的业务约束联动：

- 选择组织后只显示该组织的启用仓库；
- 选择商品后，根据商品分类配置的仓库类型进一步筛选仓库；
- 同一单据存在不同仓库类型的商品时，提示拆单；
- 约束深度：前端联动过滤 + 后端保存/过账强校验。

参考采购订单（`PurchasePage` + `purchase.service.ts` 的 `requiredWarehouseType`）现有实现。

## 现状盘点结论

- 后端强校验（`BusinessMasterDataService`）已覆盖采购、库存、销售、领用、生产、库存过账；通用出入库通过 `posting.post → validateMaster → assertGoodsLines` 已覆盖。
- 前端「组织→仓库」「仓库→商品」各单据基本已实现。
- 真正缺口：① 销售/领用缺「商品→仓库」反向筛选；② 除采购外缺「不同类型→提示拆单」。

## 本次完成

### 1. 后端：商品选项返回分类仓库类型

`apps/api/src/database/business-master-data.service.ts` 的 `goodsOptions` 返回值新增 `categoryWarehouseType` 字段（商品分类的仓库类型），供前端「选商品→筛仓库」使用。向后兼容，不影响既有调用方。

### 2. 后端：统一拆单提示

`assertGoodsLines` 增加「商品类型一致性」检查：同一单据明细包含多种分类仓库类型时，直接抛出「同一单据只能包含相同仓库类型的商品，请拆分单据」（与采购订单文案一致）。该改动自动覆盖所有调用 `assertGoodsLines` 的单据（库存、销售、领用、生产、库存过账）。

### 3. 前端：销售/领用「商品 → 仓库」联动

`apps/web/src/views/WorkflowPage.vue`：

- 新增 `optionWarehouseType` / `lineWarehouseType` / `documentWarehouseTypes` / `documentWarehouseType`；
- `requisitionWarehouseOptions` 增加按 `documentWarehouseType` 收窄仓库（选商品后只显示同类型仓库）；
- `lineGoodsOptions`：销售订单、领用申请、领用直接出库的商品列表由「按所选仓库加载（`contextGoods`）」改为「按账号可见范围加载（`options.goods`）」，实现「先选商品、再选仓库」；生产 BOM 保持按仓库加载不变；
- `businessWarehouseChanged` 与打开对话框的 `loadContextGoods` 调用，仅保留 BOM 场景。

### 4. 通用出入库

确认 `create → posting.post → validateMaster → assertGoodsLines` 链路已含仓库—商品类型强校验，无需改动。

### 5. 切换组织/仓库时清理失效明细

按「切换组织、仓库、商品时重新校验」补充前端联动：

- 采购 `PurchasePage`：`organizationChanged` 切换组织时清空明细（`form.details`）；新增 `warehouseChanged`，切换仓库时清理「类型不匹配」的明细行（保留匹配行与空行），并为 3 处仓库下拉绑定 `@change="warehouseChanged"`。
- 通用出入库 `InventoryGeneralPage`：新增 `organizationChanged`，切换组织时清空 `warehouseId` 并重置明细（`loadSelectableRows` 已含清明细逻辑）；组织下拉改绑 `organizationChanged`。
