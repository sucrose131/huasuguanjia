# 新增领用申请按仓库库存收窄候选实施构想与记录

日期：2026-09-10

## 一、确认需求

仅调整“领用管理 > 领用申请单 > 新增领用申请单”：

- 未选择仓库时，沿用组织与仓库类型映射后的商品候选和库存展示。
- 选择仓库后，商品下拉只显示当前仓库至少有一个正库存 SKU 的商品。
- 选择商品后，规格下拉只显示该商品在当前仓库库存大于 0 的 SKU。
- 编辑、查看历史领用申请不收窄候选，确保零库存或已停用历史明细仍可正常回显。
- 本次仅优化选择入口，不恢复“零库存禁止提交”的前后端拦截；最终可出库数量仍由领用出库确认校验。

## 二、数据与接口核对

| 页面判断 | 接口字段 | 数据来源 | 判断口径 |
| --- | --- | --- | --- |
| 商品是否可选 | `GET /requisitions/all-goods-options` 的 `skuStockByWarehouse` | `hspsi_inventory_total.inventory_qty`，按组织、仓库、商品、SKU 汇总 | 当前仓库至少一个 SKU 数量大于 0 |
| 商品库存展示 | 同上 | 同上 | 当前仓库所有正库存 SKU 合计；负库存 SKU 不抵扣其它可选 SKU |
| 规格是否可选 | 同上 | 同上 | 当前仓库对应 SKU 数量大于 0 |

现有接口已经返回所需仓库与 SKU 库存映射，无新增表、字段、字典或数据库脚本。

## 三、界面与业务行为

- 选择仓库时重新读取库存快照，再刷新商品和规格候选。
- 快速连续切换仓库时，只采用最后一次选择对应的请求结果，避免旧请求覆盖新仓库库存。
- 切换仓库后，若某行商品已无任何正库存规格，则清空该行商品信息；若商品仍可选但原规格无库存，则只清空规格、单位和意向批号。
- 库存刷新失败时保留当前明细并提示，不使用失败结果误清空用户已录入内容。
- 商品选中后优先选择有库存的默认规格；默认规格无库存时选择第一个有库存规格。

## 四、影响范围与风险

- 影响新增领用申请的商品、规格下拉和切换仓库行为；不影响编辑、查看、审批、领用出库、领用退回和其它业务表单。
- 库存属于实时变化数据：候选加载后到实际出库前仍可能被其它单据占用，因此不能把下拉过滤当作库存锁定。
- 本次按 SKU 汇总库存过滤，不按批次过滤；意向批号不代表预占，实际批次可用量仍以出库确认为准。
- 当前库存小于或等于 0 的 SKU 不显示；如果账面负库存与正库存 SKU 同属一个商品，负库存不会抵扣其它正库存 SKU 的可选择数量。
- 每次切换仓库会增加一次商品库存接口请求；接口失败时采用保守的“保留明细并提示”策略。
