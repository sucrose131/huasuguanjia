# 停业组织业务隔离实施记录（2026-08-12）

## 一、需求

组织设置为停业后，不得继续出现在新增仓库的所属组织选项中，也不得通过接口绕过页面继续创建或修改仓库。

## 二、实施内容

- 修正组织选项接口：组织使用 `operation_status=1` 过滤，不再错误传递无效的 `status=1`；
- 新增仓库时校验所属组织必须正常营业且未删除；
- 修改仓库时对当前或新传入的所属组织执行相同校验；
- 发现停业组织 ID `5` 与正常组织 ID `13` 同名；按业务确认仍只显示组织名称，另一条同名组织由业务人员另行停用；
- 保留历史列表、详情、仓库和业务单据的展示能力；
- 按业务确认将基础资料页面中的所属组织查询和表单选项改为可搜索树形选择器，树节点仅显示组织名称；
- 公司资料的上级公司沿用组织树，并保留顶级公司选项；
- 采购申请列表筛选及新增、编辑表单的所属组织改为可搜索组织树，保留原有部门和目标仓库联动；
- 库存调拨单的调出组织、调入组织改为可搜索组织树，保留双方仓库和仓库类型联动；
- 将剩余14处可操作组织控件统一改为可搜索组织树，覆盖采购订单、临时采购入库、采购付款、库存查询及单据、通用入出库、生产临时出库、实验室临时出库、BOM、销售订单和系统用户；
- 抽取通用组织树构建工具，兼容基础资料 options 和系统用户 options 两种返回结构；
- 保留来源单据锁定、查看态禁用、组织切换后仓库/部门/商品联动；两处纯只读组织控件未改；
- 未新增数据库表、字段或字典。
