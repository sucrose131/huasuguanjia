# 领用申请商品库存按组织筛选修复实施记录

> 日期：2026-09-04
> 对应需求：领用管理（领用申请单商品下拉库存）
> 前置：`docs/daily/2026-09-01/领用申请单商品库存可见性实施记录.md`（方案 A：候选不变 + 库存展示）

## 一、需求与边界

- 用户：新建/编辑领用申请单时，在明细里搜索并选择商品。
- 现象：商品下拉展示的库存未按库存表组织字段收口，可能把其他组织写在同一仓库下的库存汇总进来。
- 本次要做：`GET /requisitions/all-goods-options` 查询 `hspsi_inventory_total` 时必须同时限制 `org_id = 单据组织` 与本组织启用仓库。
- 本次不做：不按库存收窄商品候选；不改商品主档 `org_id` 映射（仍按组织 → 仓库类型 → 分类 → 商品）；不改表结构、字典、前端交互。

## 二、当前有效口径（实施构想）

领用申请商品下拉仍分两层：

1. 候选：组织仓库类型映射全量启用商品（0828），零库存仍可选。
2. 库存展示：只读 `stockByWarehouse`，未选仓库=领用可用仓库合计，选仓库=该仓库数量。

库存数量来源：

| 页面元素 | 业务含义 | API 字段 | 数据库 | 说明 |
| --- | --- | --- | --- | --- |
| 商品下拉库存 / 暂无库存 | 当前单据组织可用库存 | `stockByWarehouse` | `hspsi_inventory_total.inventory_qty` | `org_id = 单据组织` 且 `warehouse_id` 属于该组织启用仓库；不依赖 Prisma 组织拦截器 |
