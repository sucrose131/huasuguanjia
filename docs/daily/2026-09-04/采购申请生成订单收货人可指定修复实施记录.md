# 采购申请生成订单收货人可指定修复实施记录

> 日期：2026-09-04
> 现象：对已通过的采购申请做「生成订单」时收货人只读不可指定；部分历史申请收货人为空，导致无法创建订单（后端报"采购申请未指定有效收货人"）。
> Git 提交：feature=`0fc9801`，test=`5199cc2`

## 根因
- 后端 `generateApplicationOrder` 强制用申请单的 `receiver_id` 覆盖请求值（`if (application.receiver_id > 0n) receiverId = application.receiver_id`），且为空即报错；
- 前端生成订单弹框的「收货人」是只读 `el-input`，提交 payload 未携带 `receiverId`，候选也仅申请原收货人一个值。

## 交付
| 文件 | 改动 |
| --- | --- |
| `purchase.service.ts` | 收货人取值改为：优先用生成订单时指定的 `receiverId`，缺省再回退申请收货人，两者皆空才报错；仍复用 `assertApplicationReceiverScope` 校验组织归属 |
| `PurchaseApplicationOrderPreviewDialog.vue` | 「收货人」由只读改为可选 `el-select`：按申请所属组织拉取 `/purchase/application-receiver-options`（员工姓名优先），并保留申请原收货人；提交 payload 携带 `receiverId`；校验文案改为"请选择收货人" |

## 验证
- API 非集成 typecheck 0 错误；web vue-tsc 0 错误；purchase 组件 + business configs vitest 38 项通过。
- 兼容点：申请已填收货人的正常单据默认带出原收货人，行为不变；历史收货人为空时可在生成订单界面补选组织内收货人。

## 状态与遗留
- 状态：代码完成，待浏览器验收（用收货人为空的历史申请验证能补选收货人并生成订单；用有收货人的申请验证默认回显原收货人）。
