## 四、验证检查点（每张表单提交后）

1. `hspsi_oa_approval_instance` 新增/更新记录：`business_type`、`business_id`、`form_key`、`bus_key`、`account_set_id`、`proc_status=RUNNING`、`proc_inst_id` 非空
2. 发起请求参数（可从日志或拦截器核对）：
   - `formKey` = 该账套表单的 form_key
   - `starterId` = 提交人 `outer_ref_id`（member）
   - `starterOrgId` = 提交人主部门 `outer_ref_id`
   - `formData` = JSON，字段键为 DB 中 `unique_name`，人员控件为 `[{USRNAM, STFSEQ, USRNBR, ORGSEQ}]`
3. OA 侧表单渲染：无缺字段、人员控件正常显示中文名、金额/数量格式正确
4. 审批通过/驳回回调后：单据 `approve_status` 正确变更、OA 实例 `proc_status=PASSED/REJECTED`、下游流程可继续

## 五、建议执行顺序

1. **A 组（领用）**：已走通，回归确认无回退
2. **B 组（采购申请）**：今日修复「身份改按(用户,账套)解析」后重点验证 B-1/B-2/B-3
3. **C 组（库存调拨）**：与领用同为人员控件场景，优先验证 C-1
4. **D/E/F/G 组**：其余 8 张表单逐张冒烟
5. **H 组**：权限边界 + 多账套身份切换
