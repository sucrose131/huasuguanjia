# 采购申请成本承担组织去掉祖先展开实施记录（2026-09-02）

日期：2026-09-02
关联：`docs/daily/2026-09-01/采购业务产品优化实施记录-20260901.md`（成本承担组织与推送OA组织拆分口径）
分支：dev-0901-latest

## 一、问题与确认

- 现象：成本承担组织下拉在"授权组织"基础上沿 `parent_id` 向上展开，出现上级法人组织选项（如十方清源用户的选项含集团）。
- 核对结论（业务确认：去掉祖先展开）：
  1. 祖先展开是 4ee5422"采购申请按多组织发起OA"引入的历史逻辑，其设计理由"人员挂子公司、以上级法人组织身份**发起**"在拆分出 `oa_org_id`（推送OA组织，自带账套内祖先展开）后已由推送OA组织承担；
  2. 成本承担组织现在只承担成本归属并约束仓库/收货人，成本必须落在账号**直接授权（数据权限）范围内**；
  3. 实测：选上级组织当成本承担组织后仓库接口返回空（数据权限不放行），属死胡同选项。

## 二、改动

| 位置 | 改动 |
| --- | --- |
| `purchase.service.ts applicationOrganizations` | 去掉祖先展开查询与 `parent_id` 递归，只返回 `user.orgId + authorizedOrganizations`；注释更新 |
| `purchase.service.ts assertApplicationOrganization` | 校验口径同步收紧为"直接授权组织范围"（防止仅前端过滤/API 绕过） |
| `purchase.service.spec.ts` | "组织选项包含有效上级组织"用例改为"只含直接授权组织，不向上展开" |

- `applicationOaOrganizationOptions`（推送OA组织）**保持不变**（OA 按账套走上级法人发起场景继续可用）。

## 四、遗留说明

- 集团集中采购且成本记集团的场景：子公司用户需由集团**直接授权**后才能把成本承担组织选为集团；或用推送OA组织选集团发起、成本记子公司。
- 历史草稿若曾把成本承担组织存为上级组织，编辑时会按新口径校验拦截（仅草稿、本地测试数据，影响小）。
