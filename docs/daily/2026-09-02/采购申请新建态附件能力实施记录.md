# 采购申请新建态附件能力实施记录（方案 B：临时附件机制）

日期：2026-09-02
对应需求：采购申请单附件上传能力打通（新建态即可上传，保存后绑定）
关联：`docs/daily/2026-09-01/OA测试环境表单切换实施记录.md`（OA 附件控件 `pc744eoan0wp` 已在映射中）

## 一、需求与业务确认

- 背景：采购申请单界面此前无附件上传入口（后端 `ATTACHMENT_DOCUMENTS.purchase_application` 与通用页附件区已就绪，但新建弹框无上传途径；附件元数据依赖业务表 `attachments` JSON 列与 `documentId`，未保存前无法关联）。
- 业务确认（2026-09-02）：
  1. **方案 B**：新建态即可上传（临时附件机制）——上传到 OSS 临时目录，单据保存成功后绑定；取消/失败清理。
  2. 审批中（已提交）不允许上传附件（保持既有通用规则不变）。

## 二、设计（字段—API—数据库映射）

| 页面/接口 | 说明 | 落库/存储 |
| --- | --- | --- |
| `POST /attachments/:documentType/stage-url` | 新建态预签名上传地址（不要求单据存在），文件上传至 `documents/tmp/{userId}/{uuid}{suffix}` | 仅 OSS 临时对象，不写库 |
| 前端 PUT 至 OSS 预签名地址 | 文件直传 OSS | OSS 临时对象 |
| `POST /purchase/applications`（新增 `stagedAttachments`） | 保存采购申请（草稿），单据落库后逐一校验临时对象并复制到 `documents/purchase_application/{purId}/{uuid}{suffix}`，追加写 `hspsi_purchase_approve.attachments` JSON | 业务表 `attachments` 列 + OSS 正式对象 |
| `POST /attachments/:documentType/discard-staged` | 取消/放弃时清理当前用户自己的临时对象 | 删除 OSS 临时对象 |

- 无数据库表/字段/字典变更。
- 安全：`commitStaged` 校验 attachmentId 为 UUIDv4、objectKey 必须为 `documents/tmp/{当前用户}/{uuid}{suffix}`、HEAD 比对实际大小/类型一致后才复制；`discardStaged` 仅删除当前用户前缀的临时对象。

## 五、遗留与说明

1. 新建态绑定失败（如 OSS 对象缺失/大小不符）不阻断单据保存，返回"草稿已保存，附件绑定失败：xxx"；用户可在编辑态重新上传。
2. 取消新建弹框会清理已上传的临时对象；若浏览器关闭等异常路径，临时对象由既有 `cleanup-oss-orphans` 脚本兜底清理。
3. 审批中（review）上传仍被拦截（通用规则，业务确认保持）；编辑态附件能力沿用通用页 `DocumentAttachments`（保存草稿后可用）。
4. 方案 B 的 staging 接口为通用能力（任意 `ATTACHMENT_DOCUMENTS` 业务类型），目前仅采购申请接入；其它单据如需同样能力可复用。

## 六、补丁：上传按钮无响应修复（2026-09-02 追加）

- 现象：新建态"上传附件"按钮点击无反应（文件选择框不弹出）。
- 根因：`<label>` 包裹原生 `<button>`（el-button 渲染为 button）时，按钮作为可交互元素会吞掉点击，不触发 label 关联的 `<input type=file>`（Chrome 行为）。
- 修复：`PurchaseApplicationForm.vue` 与共享组件 `DocumentAttachments.vue` 均改为 **input ref + 按钮 `@click="inputRef?.click()"` 程序化触发**，输入框隐藏样式加 `pointer-events: none`。
- 验证：web 全量测试 69 项通过；`vue-tsc` 通过；vite 编译 200。浏览器实际点击请业务复测。

## 七、补丁：浏览器上传 Failed to fetch（OSS CORS + https 签名）（2026-09-02 追加）

- 现象：选定附件后浏览器报 `Failed to fetch`，文件上传失败。
- 根因：OSS 桶 `hspsi` 未配置 CORS（预检返回 `CORSResponse: CORS is not enabled for this bucket`），浏览器跨域 PUT 被拦；该问题同样影响编辑态 `DocumentAttachments` 上传（此前浏览器内从未成功过）。
- 修复：
  1. 用 ali-oss 为桶配置 CORS 规则（AllowedOrigin `*`，GET/PUT/POST/DELETE/HEAD，AllowedHeader `*`，暴露 ETag/x-oss-request-id/Content-Length，MaxAge 3600），预检复测 200 并返回允许头；
  2. OSS 客户端加 `secure: true`，签名 URL 统一 https，避免 https 页面混合内容拦截。
- 验证：浏览器等价 PUT（带 Origin 头）返回 200 + `Access-Control-Allow-Origin: *`；stage-url 返回 https 地址；attachments 13 项测试全过。
- 说明：CORS 规则为桶级配置（生产/测试共用同一桶），`*` 允许任意来源——如生产环境有更严格安全要求，可在 OSS 控制台收紧为具体域名。
