# 采购申请反向生成链路收货人回填修复实施记录（2026-09-02）

日期：2026-09-02
分支：dev-0901-latest
关联：`docs/daily/2026-09-02/采购申请成本承担组织去掉祖先展开实施记录.md`（同日采购字段口径核对）

## 一、问题与确认

- 核查对象：由采购订单 / 临时采购入库**反向生成采购申请**时的数据填充链路，特别是"收货人、收货经办人→收货人"回填。
- 核查结论（业务确认：只修 ①②，生产缺料与 oa_org_id 不在本次范围）：
  1. **直接采购订单开始采购**（`startOrder`，source_type=direct_order）反向生成的采购申请：org/dept/warehouse 已回填，但**收货人 receiver_id 未回填（0）**——订单有收货人，申请为空；
  2. **临时采购入库（直接入库）**（`saveReceipt`，source_type=temporary_receipt）反向生成 申请+订单+入库：订单、入库单都带收货人（收货经办人=当前用户），**唯独申请的收货人为空**——"收货经办人→收货人"链路断在申请；
  3. 附带发现：生产缺料自动生成申请（production.service.ts）同样 receiver_id=0（本次不动，业务口径待定）。

## 二、改动

| 位置 | 改动 |
| --- | --- |
| `purchase.service.ts startOrder` | 反向生成申请 data 增加 `receiver_id: order.receiver_id`（订单收货人回填） |
| `purchase.service.ts saveReceipt` | 事务前统一取值 `chainReceiverId = body.receiverId ? BigInt(body.receiverId) : userId`；反向生成的**申请**补 `receiver_id: chainReceiverId`；同链路生成的**订单**与**入库单**的 receiver 改同一取值，保证 申请/订单/入库 三条收货人一致 |
| `purchase.service.spec.ts` | startOrder 用例补 receiver_id=8n 断言；直接入库全链路用例补 申请/订单/入库 三条 receiver_id=9n 断言 |

- oa_org_id：本次不改（自动审批单不再 OA 提交，历史兼容回退 org_id 已覆盖展示）。

## 三、验证

- API 类型检查：非 integrations 0 错误；
- purchase 3 文件 49 项测试全过（含新增收货人回填断言）。

## 四、遗留

1. 生产缺料自动生成采购申请（source_type=production_plan）的收货人语义未定，未在本次范围；
2. 直接入库时若表单"收货经办人"未来放开为可选他人（当前只读=当前用户），`chainReceiverId` 已预留按 body.receiverId 取值；
3. 本次改动未推送。

## 五、追加：反向生成单 OA 栏回显修复（2026-09-02）

- 现象：反向生成的采购申请 OA 一栏显示占位符"选择本次审批发起组织"（`oa_org_id=0`）。
- 修复：三个自动生成点（直接采购订单 `startOrder`、临时直接入库 `saveReceipt`、生产缺料 `production.service.ts`）生成申请时补 `oa_org_id = org_id`（所属组织），与系统"未单独指定推送组织时回退 org_id"语义一致；详情接口据此回显组织名，前端查看态不再显示占位符。
- 存量数据：本地库 7 条反向生成单（direct_order 6 + temporary_receipt 1）已执行 `oa_org_id = org_id` 回填。
- 验证：purchase/production 相关 53 项测试全过；类型检查 0 错误。
