# 当前版本测试用例清单

> 编制日期：2026-08-09
>
> 测试分支：`codex/0807-new-require`
>
> 测试数据库：`hspsi-dev`
>
> 使用说明：本清单只覆盖今天完成或优化的功能，测试人员每验证一项即可勾选一项。

## 一、商品资料与组织可见范围

- [ ] 使用管理员账号进入商品分类和商品资料，页面应能查看全部有效分类和全局商品。
- [ ] 使用普通组织账号进入商品分类，页面应只显示该组织已启用仓库类型所关联的分类。
- [ ] 使用普通组织账号进入商品资料，页面应只显示当前组织可用分类下的商品和 SKU。
- [ ] 使用没有启用仓库的普通组织账号查看商品资料，页面应不显示受仓库类型限制的商品。
- [ ] 普通组织账号直接访问可见范围外的商品详情时，系统应拒绝访问而不能返回商品信息。
- [ ] 停用组织最后一个同类型仓库后重新查询商品，相关分类和商品应立即不可见。
- [ ] 重新启用对应类型仓库后再次查询商品，相关分类和商品应恢复可见。

## 二、采购申请快捷建档

- [ ] 在采购申请中搜索一个全局不存在的商品名称，系统应显示新增商品入口。
- [ ] 打开采购申请的新增商品窗口，页面应只要求填写商品名称、商品分类和基础单位。
- [ ] 填写三项信息并加入采购申请明细，明细行应显示为待创建且此时商品资料尚未落库。
- [ ] 关闭或取消尚未保存的采购申请后重新搜索该商品，系统应仍显示新增入口且数据库中不应产生商品。
- [ ] 保存包含待创建商品的采购申请，系统应同时生成正式商品、默认 SKU、采购申请和正确的明细关联。
- [ ] 保存成功后到商品资料查询新商品，系统应只生成一条商品主档和一个默认 SKU。
- [ ] 在采购申请中搜索全局已存在且当前组织可用的商品名称，系统应选择现有商品而不允许重复新增。
- [ ] 在采购申请中搜索全局已存在但当前组织不可用的商品名称，系统应提示仓库类型不可用并禁止选择和重复新增。
- [ ] 采购申请保存失败时检查商品资料，系统应回滚商品、SKU和申请单据而不遗留半成品数据。

## 三、无来源采购订单快捷建档

- [ ] 新建无来源采购订单并搜索全局不存在的商品，系统应提供与采购申请一致的三字段新增商品入口。
- [ ] 保存包含待创建商品的无来源采购订单，系统应同时生成正式商品、默认 SKU 和采购订单明细关联。
- [ ] 启动无来源采购订单的采购流程，系统应反向生成一张已通过的采购申请并保持商品和数量一致。
- [ ] 取消尚未保存的无来源采购订单后查询商品资料，系统应不产生商品和默认 SKU。

## 四、直接采购入库快捷建档与库存过账

- [ ] 新建直接采购入库并搜索全局不存在的商品，系统应提供名称、分类和基础单位三字段新增入口。
- [ ] 保存包含待创建商品的直接采购入库单，系统应同时生成正式商品、默认 SKU 和入库明细关联。
- [ ] 确认包含全局商品的直接采购入库单，系统应成功确认并将入库数量增加到目标仓库库存。
- [ ] 确认入库后查看库存记录，商品、SKU、仓库、单位、数量和自动批号应与入库单保持一致。
- [ ] 使用其他组织的非全局历史商品尝试入库过账，系统应拒绝处理并保持组织数据隔离。

## 五、采购单位显示

- [ ] 查看采购申请列表和详情中的商品明细，单位应显示基础资料中的计量单位文字而不是数字或编码。
- [ ] 查看采购订单列表和详情中的商品明细，单位应显示基础资料中的计量单位文字而不是数字或编码。
- [ ] 查看采购入库列表和详情中的商品明细，单位应显示基础资料中的计量单位文字而不是数字或编码。
- [ ] 查看采购退货列表和详情中的商品明细，单位应显示基础资料中的计量单位文字而不是数字或编码。
- [ ] 查看单位字段为空的历史采购明细，页面应回退显示对应商品的基础单位文字。

## 六、采购业务单号

- [ ] 新建采购申请，生成的单号应保留原英文前缀并使用当天日期加四位日流水号作为数字后缀。
- [ ] 新建采购订单，生成的单号应保留原英文前缀并使用当天日期加四位日流水号作为数字后缀。
- [ ] 新建采购入库、采购退货、采购付款和采购退款，生成的单号均应保留各自前缀并符合日期加四位日流水格式。
- [ ] 同一天连续创建两张同类型采购单据，后一张单号的四位流水应递增且不得重复。
- [ ] 分别查看采购列表、详情和操作记录，同一张单据的正式业务单号应完全一致。

## 七、采购操作记录与审批规则

- [ ] 在任意状态的采购申请上点击“更多”，菜单应始终显示“操作记录”且不能出现空菜单。
- [ ] 在已完成采购订单上打开操作记录，时间线应按实际数据展示创建、审批、付款和入库等历史动作。
- [ ] 在发生退货或退款的采购单据上打开操作记录，时间线应展示对应的退货或退款动作。
- [ ] 打开采购单据的“更多”菜单，页面不应向用户显示“业务链路”入口。
- [ ] 提交采购退货后检查库存，审批通过前系统不应扣减退货库存。
- [ ] 将采购退货审批通过后检查库存，系统应按退货数量执行一次库存扣减且重复操作不得再次扣减。

## 八、生产缺料与采购申请

- [ ] 产生生产缺料记录后，系统应直接生成对应采购申请而不要求先审批生产缺料清单。
- [ ] 查看缺料生成的采购申请，来源缺料、商品、SKU和数量应与生产缺料记录一致。
- [ ] 缺料生成采购申请失败时检查数据，系统应整体回滚而不能遗留不完整的采购申请。

## 九、销售与售后

- [ ] 新建普通销售订单后，单据应直接进入有效状态而不出现本系统审批流程。
- [ ] 尝试通过旧审批入口处理普通销售订单，系统应拒绝该操作并保持销售订单有效状态不变。
- [ ] 打开售后记录编辑页面，系统应显示独立的客服处理进展编辑区域和历史时间线。
- [ ] 在同一售后记录中连续新增多条处理进展，时间线应分别保留每次内容、状态、处理时间和操作人员。

## 十、临时出库

- [ ] 打开临时出库窗口的去向下拉框，选项应同时包含“实验出库”和“其他”。
- [ ] 选择“其他”并保存临时出库单后重新打开详情，系统应正确保存并回显“其他”。

## 十一、库存领用历史查询

- [ ] 进入库存领用历史页面，筛选区域应提供组织、部门、领用人、商品、批号、日期和持有状态条件。
- [ ] 单独使用任一筛选条件查询领用历史，返回记录应符合所选条件。
- [ ] 组合使用组织、部门和领用人查询领用历史，返回记录应同时满足全部筛选条件。
- [ ] 切换持有或归还状态查询领用历史，返回记录的状态应与所选条件一致。

## 十二、主列表序号与数据库 ID

- [ ] 查看公司、商品、采购、库存、生产、销售、领用和系统管理的主要列表，表格应同时显示序号和数据库真实 ID。
- [ ] 对任一主列表执行翻页或筛选，序号应按页面规则展示且数据库 ID 应始终对应真实业务记录。

## 十三、本轮不纳入验收的事项

- 采购申请删除价格字段以及采购订单、采购退货和采购入库的金额权限控制尚未开发，本轮不作为通过项。
- OA 接口尚未取得对方正式说明并完成联调，本轮只核对审批表单和现有字段，不测试真实 OA 流程。
- 真实 OSS 配置尚未提供，本轮不测试真实附件上传、预览、下载和删除。
- 华数之家售后同步、个人历史推荐和库存历史摆放查询已明确暂缓，本轮不进行测试。
