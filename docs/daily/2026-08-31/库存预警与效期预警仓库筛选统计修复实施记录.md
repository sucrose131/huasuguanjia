# 库存预警与效期预警页仓库筛选统计修复实施记录

> 日期：2026-08-31
> 分支：`fix/0831-display-adjustments-and-warehouse-stats`
> 类型：影响用户操作的界面缺陷修复（业务人员报障，范围已确认）
> 当前状态：代码完成，前后端类型检查、单元测试与浏览器验证通过（待提交）

## 一、需求描述

与库存盘点页修复口径一致：停用仓库（`status=1` 之外）的预警数据不应计入库存预警、效期预警页面的「全部」及各仓库统计；同时保证「全部」= 各仓库 Tab 之和，且不随选中仓库变化。

## 二、问题现状（修复前）

- 库存预警：`quantityAlerts` 未限制仓库状态，含停用仓库（仓库 15「华溯全链路原料仓」）的 2 条预警 → 全部 868，可见 Tab 之和 866；
- 效期预警：`expiryAlerts` 未选组织时不限制仓库状态，唯一 1 条预警恰在停用仓库 15 上 → 全部 1，可见 Tab 之和 0；
- 两个页面「全部」绑定当前筛选 `total`（点击仓库后变化），`warehouseCounts` 也随已选仓库过滤（点击后其它 Tab 归零）。

## 三、修改内容

| 文件 | 位置 | 修改 |
| --- | --- | --- |
| `apps/api/src/inventory/inventory.service.ts` | `quantityAlerts()` | 先取当前组织范围启用仓库；查询限定 `warehouse_id in 启用仓库`；`warehouseCounts` 按组织级（状态筛选后、未按仓库过滤）统计，warehouseId 在内存中过滤列表，保证统计稳定 |
| `apps/api/src/inventory/inventory.service.ts` | `expiryAlerts()` | 同样仅统计启用仓库；`warehouseCounts` 组织级稳定统计，warehouseId 在内存中过滤 |
| `apps/web/src/utils/warehouse-counts.ts` | 新增 | `sumWarehouseCounts(counts)`：「全部」= 各仓库统计之和 |
| `apps/web/src/utils/warehouse-counts.spec.ts` | 新增 | 4 项单元测试 |
| `apps/web/src/views/business/InventoryCheckPage.vue` | query-tools | 改用共享 `sumWarehouseCounts`（原内联函数移除） |
| `apps/web/src/views/business/InventoryQuantityAlertPage.vue` | query-tools | 「全部」改为 `sumWarehouseCounts(warehouseCounts)`，传入 `warehouse-counts` |
| `apps/web/src/views/business/InventoryExpiryAlertPage.vue` | query-tools | 同上 |

## 四、影响范围

- 库存预警、效期预警、库存盘点三个页面统一口径：「全部」= 各仓库 Tab 之和 = 当前筛选下列表条数，不随选中仓库变化；
- 停用仓库的预警/盘点数据不再出现在三个页面（列表与统计均排除）；
- 其余页面（库存查询等）不受影响；接口新增行为向后兼容。

## 五、验证结果

- Web TypeScript 类型检查：通过；Web 单元测试：18 个文件 63 项全部通过（新增 4 项）；
- API 核对：
  - 库存预警全量：`total = 866`，`warehouseCounts` 之和 866（停用仓库 15 的 2 条已排除）；
