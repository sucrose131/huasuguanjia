# 采购与报表优化手工测试用例

日期：2026-09-07。范围：待采购订单编辑、删除后重新生成、金额权限及报表中心；另附计划内既有采购功能的回归检查。

本文件为待执行用例，不代表全部已经测试通过。只在测试环境操作，使用测试单据，不操作正式采购、付款或真实OA审批。

## 一、测试前准备

- 准备五类账号，菜单操作权限和组织范围尽量一致，区别仅为金额权限：A无金额权限；B仅查看·自己；C可编辑·自己；D仅查看·权限内全部；E可编辑·权限内全部。
- “自己”指当前账号经办的单据，不是同部门其他人经办的单据。测试时准备本人及他人的单据。
- 准备：已审批通过且含三个不同商品的普通人工采购申请、申请生成的待采购订单、直接创建的待采购订单、采购中订单、已有付款/入库记录的订单。
- 准备同一组织下两个与商品分类匹配的仓库，以及其他组织或类型不匹配的仓库；没有第二个匹配仓库时，仓库切换用例记为待测。
- 报表日期选择覆盖测试单据的时间，必须有数据再检查金额，不能把空表当作金额权限测试通过。每条用例执行后记录通过、不通过或阻塞；不通过时附账号、单号及截图。

## 二、今天修改的采购功能

除金额权限专门用例外，使用E账号；每次修改后均保存，再点击“查看”核对实际保存结果。

|编号|功能与操作|应出现的结果|
|---|---|---|
|P01|进入采购管理→采购订单，找到采购申请生成的待采购订单，点击“编辑”|打开原采购订单弹框，可以修改采购执行信息，不再因订单来自申请而整体禁止编辑|
|P02|在上述弹框检查来源申请、成本承担组织、商品、SKU、申请数量|这些原审批信息只读；不能替换商品、删除原申请商品行或添加未经申请的商品|
|P03|修改供应商，点击保存，再查看订单|显示新供应商，来源申请和商品不变，状态仍为待采购|
|P04|展开目标仓库，选择同一组织下另一个匹配仓库，保存再查看|只能选择本组织且匹配商品分类的具体仓库；新仓库正确保存，不能选其他组织或类型不匹配的仓库|
|P05|修改接收部门，再选择收货人，保存再查看|收货人按新的组织/部门关系选择；不保留失效人员，新部门和收货人正确保存|
|P06|修改到货方式、计划到货日期、运输方式、物流单号、结算方式、计划付款日期、明细备注和订单备注，保存再查看|各项正确回显；保存不自动开始采购、不自动付款或入库|
|P07|找申请数量为10的明细，把实际采购数量改为12，保存；再查看订单及原采购申请|订单申请数量仍为10、采购数量为12；原申请数量不变|
|P08|把采购数量填写为0、负数或小数，尝试保存|控件阻止输入或保存时提示错误，不保存非法数量|
|P09|把采购数量设为12、该行采购总金额设为120元，保存再查看|采购单价为10元，明细与订单金额正确回显|
|P10|清空必填供应商、仓库或收货人后尝试保存；再把数量或必填金额设为非法值尝试保存|提示对应校验错误；原订单不被部分修改，不产生新订单|
|P11|修改收货人、数量及备注后，点击“取消”或关闭弹框，再查看订单|仍为修改前的数据，未保存的内容不生效|
|P12|进入直接创建、未开始采购且无下游记录的订单，点击编辑；增删商品、改数量及采购执行信息后保存|合法修改成功，状态仍为待采购；区别于申请生成订单，直接订单允许有金额编辑权限者调整商品明细|
|P13|在普通申请生成的待采购订单点击“更多→删除”，先取消，再重新删除并确认|取消时订单仍存在；确认后订单从正常列表消失，原采购申请仍保留已通过状态|
|P14|删除后返回原采购申请，点击“整单生成”，填写供应商、采购数量和金额并保存；点击“关联订单”|被释放的明细可以重新生成；生成新订单并正确关联原申请，不恢复旧订单号|
|P15|用三个商品的申请“选品生成”：先用商品1、2生成订单甲，再用商品3生成订单乙；删除甲，回原申请再次“选品生成”|只能重新选择商品1、2；商品3仍归订单乙，乙的商品、数量及状态不受影响|
|P16|所有明细已生成有效订单时，再点击整单生成或选品生成并尝试提交|不能重复生成已被有效订单占用的明细，不产生重复订单|
|P17|删除订单后，使用有生成采购订单权限且有对应组织范围的采购账号进入“工作台→待办事项”|原采购申请重新出现待生成采购订单的待办；点击可进入对应申请；旧订单待办不再要求继续处理|
|P18|在有效待采购订单点击“开始采购”并确认，再查看列表及更多菜单|状态变为采购中；不能再编辑、删除；按业务状态显示付款、生成入库等后续入口|
|P19|先打开某待采购订单编辑框，再在另一个浏览器标签页开始该订单采购；回旧编辑框保存修改|保存被拒绝并提示状态已变化，不能覆盖已开始采购的订单|
|P20|找到已有付款或入库记录的订单，尝试编辑或删除|无可用入口，或操作时明确拦截；付款、入库及订单原数据保持不变|
|P21|编辑保存后点击该订单“更多→操作记录”|能看到此次编辑的操作人、操作时间和编辑说明，且对应正确订单|

## 三、采购金额权限检查

|编号|功能与操作|应出现的结果|
|---|---|---|
|M01|A账号进入有编辑操作权的待采购订单，修改收货人、到货方式、采购数量及备注后保存|金额显示¥ ****，不能输入金额；非金额修改可保存|
|M02|由D或E账号重新查看M01修改的订单，与修改前对比采购总金额|采购总金额未被掩码、空值或0覆盖；如数量变化，按既有规则反算单价|
|M03|B账号分别查看自己及他人经办的采购订单，再打开自己的待采购订单编辑|自己的金额可见、他人的金额掩码；自己的金额也不能编辑，允许的非金额字段可改|
|M04|C账号分别编辑自己和他人经办的待采购订单|自己的金额可编辑；他人的金额不能查看或编辑，不能因有编辑能力而越过“自己”范围|
|M05|D、E账号分别查看组织授权范围内的他人订单并打开编辑|D能看金额但不能改金额；E可以按订单状态修改金额；均不能越过组织数据权限|

## 四、报表中心逐张检查

### 执行方法

下面21张报表逐张执行，不能只抽查一张：

1. 分别登录A、B、C、D、E账号，点击“报表中心→对应报表”。
2. 选择覆盖测试数据的日期，检查列表、金额合计和非金额信息。
3. 点击“导出”，打开下载的文件，核对金额和非金额列。

**有金额的报表：**A、B、C的所有金额及合计均为¥ ****，包括本人单据；导出也不得包含实际金额。D、E可见组织授权范围内的金额，导出与页面一致。金额数据缺失时不得伪装成0或显示不完整的合计。

**无金额的报表：**五类账号在相同菜单和组织权限下，资料、数量、状态正常显示，导出正常，不因金额权限不同而丢失非金额信息。

### 报表补充操作

|编号|功能与操作|应出现的结果|
|---|---|---|
|R22|B或C账号只筛选出本人经办单据，再查看及导出金额报表|即使全部记录都是本人经办，金额与合计仍全部掩码|
|R23|由管理员将测试账号金额范围从“全部”改为“自己”；测试账号刷新数据或重新登录，再查看原报表并导出|旧金额不再显示或导出，不残留上次“全部”权限的金额|
|R24|先使用E账号打开报表，退出后换A账号登录，再打开同一报表并导出|不得看到或导出上一账号的金额|
|R25|D或E查看含实际0元和含小数金额的测试报表|真实0元显示¥0.00，小数金额正常显示两位；不是把掩码或缺失金额显示成0|
|R26|选择没有数据的日期；再把开始日期设为晚于结束日期|无数据时显示空表提示，不报服务器错误；日期反向时有错误提示且不能正常导出|
|R27|C账号依次进入自己的采购订单、库存管理→库存查询、报表中心→库存汇总统计分析表|自己订单按原规则可看/改金额；库存查询按原规则可看金额；报表库存汇总的金额必须掩码，不能把报表限制错误扩散到普通业务页面|
|R28|用只授权组织甲的D或E账号，打开各业务报表并导出；与甲、乙组织测试单据对照|只出现授权范围内的数据；“金额范围全部”不能额外放行组织乙的数据|

## 五、当前计划中的既有功能回归（不是今天新增）

|编号|功能与操作|应出现的结果|
|---|---|---|
|G01|点击采购申请→新增，查看申请人，切换推送OA组织；再切换成本承担组织|申请人显示当前员工中文姓名；申请部门随OA身份带出；仓库、收货人受成本承担组织限制，不保留失效选项|
|G02|将普通人工采购申请保存草稿后编辑；在测试审批流程中提交，再由申请人在审批中撤回、重新编辑|草稿可按权限编辑；提交后锁定；允许撤回的审批中申请撤回成功后恢复草稿；不把已通过或生产自动生成申请当作普通审批中申请撤回|
|G03|对两张有待生成明细的已通过申请，分别点击整单生成和选品生成；填写与申请量不同的实际采购量|整单生成带入全部未生成明细；选品生成只带入选中明细；实际采购量可以不同，原申请量不变|
|G04|采购中订单点击更多→付款：分别测试未付款、部分已付款；再手动调低或超额填写本次付款金额|未付款默认当前应付额，部分付款默认剩余应付；不是0.01元；允许合法分期金额，拒绝0、负数和超出剩余应付|
|G05|在指定测试订单点击生成入库，核对商品、数量及收货信息；仅在允许过账的测试单上确认入库|生成入库信息与当前订单一致，剩余数量正确；确认入库后更新入库进度与对应仓库库存，不重复入库|

## 六、已知阻塞与本轮优先补测

- 当前本地历史采购订单存在重复商品/SKU，R04采购明细、R05采购统计、R21应付账款会加载失败。遇到该提示应记录“阻塞”，不能记为金额权限通过，也不要自行删除历史单据；待处理后重测。
- 优先补测：P04匹配仓库切换、P15部分选品删除隔离、P17待办恢复、P21编辑记录、M02原总金额保留，以及A/B/C账号真实报表金额与导出。删除日志因本次未确认可用界面入口，由开发配合核查，不要求测试人员操作数据库。
- 本轮不包含性能、压测或数据库操作，测试人员通过系统界面执行即可。
