# 库存预警 / 效期预警首屏渲染优化实施记录

> 日期：2026-09-07
> 分支：`feature/0907-inventory-quantity-alerts`
> 类型：影响用户操作的界面性能改造（业务已确认恢复分页）
> 当前状态：代码完成；API 类型检查（涉及文件）与前后端单元测试通过；真库只读核对通过；浏览器首屏实测待 UI 环境（见遗留）

## 一、需求描述

两个预警页（库存预警 / 效期预警）为全仓库业务页面中仅有的 `pagination:false` 大列表，共享引擎一次渲染全量行，数据到达后首屏可见约 5s；正式环境数据持续增长，故分页必须下放到 SQL。目标：首屏渲染 < 1s、翻页与仓库 Tab 切换 < 300ms、摘要与统计不随页码变化、金额权限口径不变。

## 二、修改内容

| 文件 | 位置 | 修改 |
| --- | --- | --- |
| `apps/api/src/inventory/inventory.service.ts` | `quantityAlerts()` | 改为 $queryRaw 真分页：页行 = inventory_total LEFT JOIN alert_qty（派生 warning/gap/purchase、状态/仓库过滤）+ LIMIT/OFFSET；统计 = 同条件 GROUP BY warehouse_id（不带仓库过滤）→ warehouseCounts；total/summary 取当前筛选范围（选中仓库取该组、未选则全部仓库求和），等价旧逐行口径；名称富化仅对当前页 |
| `apps/api/src/inventory/inventory.service.ts` | `expiryAlerts()` | 页行 = alert_period JOIN batch_total（确认库存批次>0）+ LIMIT/OFFSET；warehouseCounts/total 走 GROUP BY；`end_day` 经模型读取保持原 Date 语义，避免剩余天数时区漂移 |
| `apps/api/src/inventory/inventory.service.ts` | 新增私有 | `quantityAlertConditions / expiryAlertConditions / keywordIdConditions`（Prisma.sql 参数化条件片段） |
| `apps/api/src/inventory/inventory.service.spec.ts` | 新增 | 7 个用例：统计/摘要不随页码变化、仓库 Tab 口径（总计数 org 级稳定）、页行映射与无配置行回退、非法状态 400、效期聚合与字典/引用映射 |
| `apps/web/src/views/business/configs/inventory-quantity-alert.ts` | config | 删除 `pagination:false`（恢复分页器 20/50/100） |
| `apps/web/src/views/business/configs/inventory-expiry-alert.ts` | config | 同上 |
| `apps/web/src/views/business/business-document-config.ts` | 注释 | `pagination` 字段注释改为建议服务端分页 |
| `apps/web/src/components/business/OverflowTooltipCell.vue` | 组件 | el-tooltip 首次 hover 且确溢出时才创建（active），消除每行常驻 tooltip 实例；保留 fixed 列虚拟定位（不回退原生） |
| `apps/web/src/views/business/BusinessDocumentPage.vue` | 引擎 | tooltip 列去重 displayCell（单次调用，content 回落 innerText）；行操作权限过滤 `computed` 缓存（permittedActions）；重置按钮补 `query.page = 1` |
