# OA审批流程清单与现有字段说明

> 文档状态：现有字段清单 v0.2，可交 OA 接口开发人员做字段对照
>
> 编制日期：2026-08-09
>
> 核对依据：当前分支 `apps/api/prisma/schema.prisma` 及现有业务代码

## 1. 文档用途

本文只回答两个问题：

1. 华溯管家哪些业务表单需要 OA 审批；
2. 每张表单目前能够向 OA 提供哪些已经存在的数据库字段。

本文不替 OA 设计接口，不拟定请求头、签名、回调地址、幂等键、状态机或 OA 字段名称。OA 接口的正式请求格式由 OA 开发人员提供，双方对接时再把本文中的现有字段映射到 OA 已有接口。

清单中的字段均满足以下至少一项：

- 当前数据库表中已经存在；
- 通过现有外键能够查询到对应名称。

数据库没有、代码没有或业务尚未确认的字段不列为我方可提供字段。

## 3. 关联名称的现有数据来源

业务表中多数保存的是 ID。向 OA 展示中文名称时，可以通过以下现有表查询，不需要虚构新字段。

| 数据内容 | 关联表                     | 已有字段                                                                            |
| -------- | -------------------------- | ----------------------------------------------------------------------------------- |
| 组织     | `hspsi_basic_organization` | `org_id`、`org_no`、`name`、`short_name`、`outer_ref_id`                            |
| 部门     | `hspsi_basic_dept`         | `dept_id`、`dept_no`、`name`、`outer_ref_id`                                        |
| 仓库     | `hspsi_basic_warehouse`    | `warehouse_id`、`org_id`、`dept_id`、`name`、`warehouse_type`                       |
| 商品     | `hspsi_goods_info`         | `goods_id`、`query_code`、`goods_name`、`spec_models`、`unit_type`、`goods_catg_id` |
| SKU      | `hspsi_goods_info_sku`     | `sku_id`、`good_id`、`spec_models`、`unit_type`、`is_default`                       |
| 单位     | `hspsi_basic_unit`         | `id`、`name`                                                                        |
| 系统用户 | `hspsi_sys_user`           | `id`、`org_id`、`dept_id`、`username`、`nickname`、`phone`、`email`                 |
| 人员资料 | `hspsi_basic_staff`        | `id`、`name`、`staff_code`、`out_staff_id`、`outer_ref_id`                          |

说明：当前系统用户表与人员资料表之间是否存在可供 OA 使用的稳定一一映射，仍需对接时核实。本文不把 `out_staff_id` 或 `outer_ref_id` 直接认定为 OA 用户 ID。

1. OA 发起审批接口实际接收的字段名称、类型和必填规则；
2. OA 如何标识申请人、组织和部门；
3. OA 如何区分采购申请、采购退货、库存、生产和领用等审批模板；
4. OA 审批通过或拒绝后实际返回哪些字段；
5. 测试环境的接口地址、认证方式和测试账号。

取得 OA 接口说明后，只做两边字段对照：

```text
OA已有接口字段
↔
本文列出的华溯管家现有字段
```

在双方完成字段对照前，不在本文增加推测字段，也不据此修改数据库。
