# 十方清源用户同步

将十方清源**有更新**的用户主数据同步到本平台客户表，并在 `levels` JSON 中保存身份描述：会员等级、云库存代理等级。

对应接口文档：[user-api.md](./user-api.md)  
与订单侧客户对齐：[订单同步.md](./订单同步.md)（同一幂等键；**订单同步只补建缺失客户，不覆盖已有姓名与身份**）

> 状态：已按业务确认实施

---

## 1. 需求与边界

| 项 | 约定 |
| --- | --- |
| 同步定义 | 只把源侧 `updated_at` 落在水位之后的用户主数据 upsert 到 `hspsi_basic_customer` |
| 触发方式 | 由「系统管理 > 任务管理」中的 `shifang-qingyuan:users` 按 Cron 调度；本期**不提供**手动 HTTP 触发接口，可在任务管理页立即执行 |
| 落库目标 | `hspsi_basic_customer` |
| 幂等键 | `source_type = 数据源 id` + `related_customer_id = 十方 user.id` |
| 身份存储 | 单字段 `levels`（JSON），只存会员等级名称 + 云库存代理等级名称，**不存**等级 ID |
| 机构未映射 | **单条失败**：该用户记失败并跳过，其余用户继续写入 |
| 订单同步 | 已存在客户不覆盖姓名 / 手机 / 推荐人 / 状态 / `levels`；仅缺失时用收货人补建 |
| 暂缓 | 云库存金额/库存等数值；手动同步接口；按手机号合并；水位持久化表 |

列表每个用户元素已含 `user` / `user_level` / `cloud_stock_agent`，**不调用** `detail`。

---

## 2. 数据库变更

不新增表、字段或字典。沿用 `hspsi_basic_customer.levels`（json）。

---

## 3. `levels` JSON 结构

只存中文标签数组，去重，顺序固定。

```json
["经销商", "城市合伙人"]
```

写入规则：

| 顺序 | 条件 | 写入文案 |
| --- | --- | --- |
| 1 | `user.level_name` 或 `user_level.name` 非空 | 会员等级名称（含接口回退的「普通会员」） |
| 2 | `cloud_stock_agent.level_name` 非空且与上一项不同 | 云库存代理等级名称 |

两者都空时存 `[]`。

## 4. 字段映射

| 业务字段 | 十方 | 平台库 | 说明 |
| --- | --- | --- | --- |
| 客户名称 | `nickname` → `username` | `name` | 空则 `十方用户{id}` |
| 手机号 | `mobile` | `mobile` | |
| 生日 | `birthday` | `birthday` | 空/非法 → null |
| 所属组织 | `mall_id` | `org_id` | 经 `hspsi_sys_organization_mapping` |
| 来源 | — | `source_type` | 数据源 id |
| 关联外部用户 | `user.id` | `related_customer_id` | |
| 推荐人 | `parent_nickname` → `parent_username` / `parent_mobile` | `referrer_*` | |
| 状态 | `user.status` | `status` | 1→启用1；0→停用2 |
| 身份 | 见上 | `levels` | 仅描述，无 ID |
| 地址 / 性别 | — | `address` / `gender` | 新建 `''` / `0`；用户同步更新不改地址 |

不写：`cloud_stock_agent` 的 stock / total_price / frozen_price 等。

## 5. 同步流程

增量拉取：`POST /open-api/v1/user/list` 传 `start_time`（`Y-m-d H:i:s`），按源 `updated_at >= start_time` 过滤。**不传 `end_time`**（接口会把 `end_time` 补成当天 `23:59:59`，会截断当天后续更新）。

水位（进程内内存，不新建表）：

| 场景 | `start_time` |
| --- | --- |
| 首轮基线 / 进程重启内存水位丢失 / 入参强制全量 | 不传，分页拉全部 |
| 之后每轮（上一轮全部成功） | 上一轮开始时间减去重叠窗口（默认 5 分钟） |
| 上一轮有失败 | 不前进水位；下一轮仍按上一成功轮（或全量）重试 |
| 补拉/重试 | `syncUsers({ startTime })` 可覆盖 |

不按 `max(related_customer_id)` 前进：那只能拉到新用户，拉不到等级/直推人等主数据更新。

```
1. 校验数据源 id 可落入 source_type
2. 确定本轮 start_time（见上表）
3. 循环 POST /open-api/v1/user/list：page 递增，limit 固定；按页即时处理
4. 页内并发写入：按 source_type + related_customer_id 查找后创建或更新；机构问题单条失败
5. 本轮全部成功后前进内存水位；有失败则不前进，下一轮按原水位重试
6. 输出统计：fetched / created / updated / failed / startTime
```

无分布式锁；进程内 `running` 防重入，上一轮未结束则跳过本轮。

触发方式由「系统管理 > 任务管理」调度 `ShifangQingyuanUserSyncService.syncUsers()`，开关和 Cron 存在 `hspsi_sys_scheduled_task`。

分页配置：

| 项 | 本期 | 说明 |
| --- | --- | --- |
| 分页 | 代码常量 | `limit=100`（接口上限）；**不走环境变量** |
| 调度 | 数据库配置 | 开关、Cron 由任务管理表维护；分页仍为代码常量 |

实现位置：

- `apps/api/src/integrations/shifang-qingyuan/sync/user-sync.service.ts`
- `apps/api/src/integrations/shifang-qingyuan/sync/build-customer-levels.ts`

认证沿用现有 `x-mall-sign` + `Host`。
