# 十方清源订单同步

将十方清源已支付订单同步到本平台销售履约体系：销售订单、客户、收款/退款、出库扣库、售后退货入库、售后事件。

对应接口文档：[order-api.md](./order-api.md)  
商品映射依赖：[商品同步.md](./商品同步.md)

---

## 1. 同步范围与前提

| 项 | 约定 |
| --- | --- |
| 入库门槛 | 仅同步 **已支付**（`pay_status=1`）且非待付款（`order_status≠0`）的订单 |
| 金额单位 | **元**（订单/明细/售后与商品接口一致，直接落 Decimal，不做 ÷100） |
| 归属机构 | 订单 `mall_id` → `hspsi_sys_organization_mapping` → 平台 `org_id` |
| 仓库 | `SHIFANG_QINGYUAN_GOODS_CATEGORY_ID` 分类的 `warehouse_type` + 平台 `org_id` → 启用仓 |
| 外部发货 | 自动生成出库单并**确认过账扣库存**；`order_type=1` 云库存纯入库**不写出库** |
| 售后退货成功 | 自动生成退货入库单并**确认过账加库存**；`order_type=1` **不回库** |
| 仅退款不退货 | `refund.type=1`：只写退款记账 + 售后事件，**不回库** |
| 幂等维度 | `source_id + source_order_type + source_order_id` |

`source_order_type`：由拉取接口族决定，本期常量 `SALE_ORDER`。

### 1.1 机构映射（硬性）

```
order.mall_id
  → hspsi_sys_organization_mapping(
       source_id = hspsi_sys_data_source.id（code=shifang_qingyuan）,
       source_object_id = String(mall_id)
     )
  → org_id
```

- `organization_mapping.source_id` **必须等于** 十方清源数据源 `id`，不得写 0 或其他数据源
- 按实际商城 `mall_id` 手工配置映射行；不设死常量外部机构 ID

### 1.2 列表即全量（不再逐单拉详情）

| 接口 | 路径 | 用途 |
| --- | --- | --- |
| 订单列表 | `POST /open-api/v1/order/list` | 批量 / 增量 / 按 `order_no` 单笔；**每条已含全量嵌套** |
| 订单详情 | `POST /open-api/v1/order/detail` | 联调备用；**同步主流程不调用** |

自 2026-08-12 起，list 每条与 detail 结构一致（`order` / `details` / `refunds` / `express` / `actions` / `behavior_logs` / `extra` / `invoice`，另可含 `user`）。同步直接以 list 元素为快照 apply，避免 N+1 详情请求。

### 1.3 状态变更与原始快照

与华溯之家相同原则：

- 映射表一行对应一笔外部订单（始终同一 `so_id`）
- 头表三维状态只向前；副作用按条件幂等补齐
- `last_payload` 存最近成功快照；失败写 `last_error_payload`
- **仅售后**写入 `hspsi_sale_order_service`；支付建单、发货出库不写售后记录
- 历史已写入的下单/发货 service 行本次不同步删除

售后事件幂等键：`SFQY-EVT-{sourceId}-{orderType}-{orderId}-AS-{refundId}-{phase}`

## 4. 客户同步

与用户主数据同步共用幂等键，详见 [用户同步.md](./用户同步.md)。

- `source_type` = 数据源 id
- `related_customer_id` = 十方 `user_id`
- **已存在**：只更新 `address`（收货拼接）和审计时间，**不覆盖**姓名 / 手机 / 推荐人 / 状态 / `levels`（身份由用户同步写入）
- **不存在**：用 `receiver_name` / 订单 `mobile` / 地址补建，`levels=[]`，`status=1`；后续用户同步补齐身份
- 销售单头收货快照：`customer_name/mobile/address` 仍写**本单收货信息**，不受客户主数据保护影响

## 5. 销售订单

### 5.1 头表

| 平台字段 | 取值 |
| --- | --- |
| `org_id` | `mall_id` → organization_mapping |
| `warehouse_id` | 分类 warehouse_type + org |
| `so_type` | `order_type=1` 云库存纯入库为 **4 无需出库**；否则按明细商品类型：全实体1 / 全虚拟2 / 混合3 |
| `so_source` | data_source.id |
| `so_source_id` | sale_order_source_mapping.id |
| `customer_*` | 上节 |
| `order_date` | `created_at` 时间戳 |
| `so_qty` | 明细数量合计 |
| `so_amount` | `original_goods_price`（无则 `goods_price`） |
| `fact_amount` | `pay_money` |
| `priceoff_amount` | max(so_amount - fact_amount, 0) |
| `shipper` | `express[].express_no` 拼接 |
| `delivery_date` | 发货态时取 `consign_time` 或 express.created_at |
| `approve_status` | 1 |
| `remark` | 订单 `remark`（用户备注） |
| `business_source_*` | **不同步** |

### 5.2 状态映射

| 十方 `order_status` | 平台 order | delivery | service | 说明 |
| --- | --- | --- | --- | --- |
| 1 待发货 / 6 待自提 | 1 | 1 | 3 | 已支付待履约 |
| 2 已发货 / 3 已收货 / 7 自提成功 | 1 | 3 | 3 | 已发货 |
| 4 已完成 | 2 | 3 | 3 | 结束 |
| `order_type=1` 纯入库 | 按上表 | **强制 1 待发货** | 按上表 | 云库存增加，无实体发货 |
| 维权中（`is_feedback=1` 或存在处理中 refund） | 1 | 保持 | 1 | 售后中 |
| 维权完成且有成功退款 | 2 或 3 | 保持 | 2 | 视是否整单关闭 |
| -4 已关闭（曾支付） | 3 | 保持 | 2 | 关闭 |

不建单：`pay_status≠1` 或 `order_status=0`。

发货触发：`order_status∈{2,3,4,7}` **或** `express[]` 非空 **或** `shipping_status=1`。  
例外：快照 `order_type=1`（向云库存纯入库、无实体发货）**不触发出库**，头表 `delivery_status` 保持待发货。销售订单记为 `so_type=4`（无需出库）后，销售订单页不出现「直接出库」，`POST /sales/outputs` 也会拒绝创建出库单。

### 5.3 明细

- 保留下单 SKU：`goods_id` / `goods_attr_id` → mapping（**不区分 source_type**）
- `source_sku_id` = `String(goods_attr_id)`；缺少 `goods_attr_id` 则整单失败
- `sale_qty` = `num`；单价优先行 `price`，金额用 `goods_price`（无则 单价×数量）
- 无映射：整单失败

## 6. 支付 / 退款

| 场景 | so_pay_type | 金额 | request_key |
| --- | --- | --- | --- |
| 建单已支付 | 1 | `pay_money` | `SFQY-PAY-...` |
| 售后成功退款 | 2 | `reality_refund_price` 优先，否则 `refund_price` | `SFQY-REFUND-...-{refundId}` |

支付方式：`payment_type` → 平台 `pay_mode`（见常量 `SHIFANG_QINGYUAN_PAY_MODE_MAP`；未知回退 2）。

**业务日期取第三方时间；平台 `updated_at` 取写入/同步时刻**：

| 单据 | 业务日期 | `created_at`（列表「操作时间」） | `updated_at` |
| --- | --- | --- | --- |
| 收款 | `pay_date` ← `order.pay_time` → `order.created_at` | 同业务日期 | 同步写入时刻 |
| 退款 | `pay_date` ← `refund.refund_at` → `updated_at` → `created_at` | 同业务日期 | 同步写入时刻 |

## 7. 外部发货 → 出库

`order_type`（与 `order` 同级，v8）：

| 值 | 含义 | 平台出库 |
| --- | --- | --- |
| 0 | 无云库存数据 | 按发货条件出库 |
| 1 | 向云库存纯入库 | **不出库、不扣仓库库存**；销售单 `so_type=4` 无需出库 |
| 2 | 从云库存出库 | 按发货条件出库 |
| 3 | 从系统仓库出库 | 按发货条件出库 |
| 4 | 混合出库 | 按发货条件出库 |

1. 出库明细：按订单行查 `conversion_rule`（启用，`rule_type∈{1替换,2拆解}`）；有则 `qty * quantity_ratio`，无则原下单 SKU
2. 生成 output 并自动确认；外部库存过账（允许负库存、不校验商品 org、不判断商品/规格启用状态）
3. 物流单号写入销售单头 `shipper`
4. 幂等：有 express 取首条 id，否则 `ALL`
5. 历史已误写出库的 `order_type=1` 单据本次不删除；新同步不再新增

`order_type=1` 的退货退款：只写退款记账和售后事件，**不生成退货入库**（仓库从未出库）。

## 8. 售后

来源：list 快照中的 `refunds[]`。

| `type` | 资金 | 库存 |
| --- | --- | --- |
| 1 仅退款 | 成功则退款 payment | 不回库 |
| 2 退货退款 | 成功则退款 | 按 refund.num + 关联明细商品回库 |
| 3 换货 | 仅事件 | 本期不改库存 |

成功判定（实现约定，若 constants 实拉后不一致则改常量）：

- **成功**：`is_refund=1`，或 `refund_status` ∈ 完结集合（默认含文档常见完结值，见代码常量）
- **处理中**：未成功且未拒绝，或订单 `is_feedback=1`
- **拒绝/取消**：`refund_status` ∈ 拒绝/取消集合

售后记录（`hspsi_sale_order_service`）：

| 字段 | 取值 |
| --- | --- |
| `goods_id` / `sku_id` | `refund.order_detail_id` → 订单明细 → 平台 mapping；解析失败写 0 |
| `event_date` / `created_at` | 成功优先 `refund_at`，否则 `updated_at` / `created_at`（第三方时间） |
| `updated_at` | 同步写入时刻 |
| `event_content` | reason / remark / refuse_remark |

退货入库明细：关联 `order_detail_id` 对应行的平台 mapping + `refund.num`；无法解析则只记账。

## 9. 同步主流程

```
1. 分页 list（start_time 默认映射表最大 source_updated_at，空页退出）
2. 每单以 list 元素为快照 applyOrder（含 refunds/express，不再调 detail）：
   ensureDataSource → resolveOrg(mall_id) → resolveWarehouse
   → ensureCustomer → resolveOrderLines
   → upsert mapping(RETRY) → upsert SO
   → ensurePayment
   → ensureShipments → ensureAfterSales
   → mapping SUCCESS + last_payload
```

触发方式：由「系统管理 > 任务管理」调度 `shifang-qingyuan:orders`；本期**不提供 HTTP 接口**，可在任务管理页立即执行。

- 批量：`ShifangQingyuanOrderSyncService.syncOrders(userId, options?)`
- 单笔：`ShifangQingyuanOrderSyncService.syncOrderByNo(orderNo, userId)`
- 实现：`apps/api/src/integrations/shifang-qingyuan/sync/order-sync.service.ts`
- 进程内防重入：上一轮未结束则拒绝
- HTTP 手动同步路由（对齐华溯）**暂缓**，需要时再挂 `ShifangQingyuanController`

- `refund_status` 全量表以 constants 实拉为准，代码常量可随环境调整
- 换货出入库本期不做

- 发票 / behavior_logs / actions 不落业务表（可进 last_payload）
- HTTP 手动同步接口暂未提供
