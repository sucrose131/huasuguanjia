## 二、业务目标

用户在华溯管家中先保存业务草稿并上传附件。提交 OA 审批时，系统自动完成：

```text
读取单据附件元数据
→ 从华溯 OSS 下载业务原件到 API 临时目录
→ 调用薪福通 OA 文件上传接口
→ 取得 OA fileId、objectKey
→ 组装图片/附件控件 formData
→ 发起 OA 审批
→ 清除 API 临时目录中的下载文件
```

## 三、“本地文件清除”的口径

本方案区分两类文件：

| 文件                           | 是否清除 | 原因                                             |
| ------------------------------ | -------- | ------------------------------------------------ |
| API 服务器临时目录中的下载副本 | 是       | 仅用于转传 OA，成功或失败后均不保留              |
| 华溯 OSS 中的业务原件          | 否       | 属于进销存业务档案，页面预览、下载和审计仍需使用 |
| OA 上传成功后的 OA 文件        | 否       | 由 OA 审批单使用和管理                           |

不得在 OA 上传成功后删除华溯 OSS 原件。若“清除本地文件”实际是指删除 OSS 原件，需要重新进行业务确认和档案保留评估。

### 3.1 手写签名存储口径

- 新产生的手写签名由 API 将画布 PNG 直接上传华溯 OSS；
- 数据库不再把新签名 Base64 写入 `signature_content`；
- 签名作为业务附件写入现有 `attachments` JSON，并标记 `category=signature`；
- `signature_attachment` 保存对应附件 ID，用于判断签名是否存在；
- OA 提交时签名附件与其他图片一起进入 `FinImageUpload`“图片”控件；
- 历史 `signature_content` Base64 暂时只读兼容，批量迁移 OSS 需在备份和回查方案确认后单独执行。

## 四、现有能力

### 4.1 华溯 OSS

- 业务附件已经保存在华溯 OSS；
- 业务主表 `attachments` JSON 保存本地 `objectKey`、文件名、MIME、大小、上传人和上传时间；
- 单文件默认不超过 20 MB，单张单据默认最多 10 个附件；
- OSS 原件目录格式为 `documents/{documentType}/{documentId}/{attachmentId}.{ext}`。

### 4.2 薪福通 OA

现有 `XinfutongOaApprovalService.uploadFile()` 已封装：

```text
POST /xft-oa/openapi/xft-oa/file/upload
Content-Type: multipart/form-data
```

传入文件名和 `Buffer`，成功后取得：

```json
{
  "fileId": "OA文件ID",
  "objectKey": "OA对象Key",
  "fileName": "原文件名",
  "fileSize": 1024,
  "fileType": "PDF",
  "fileUrl": "临时下载地址"
}
```

发起流程时文件控件只传：

```json
[
  {
    "id": "OA文件ID",
    "objectKey": "OA对象Key",
    "name": "原文件名"
  }
]
```

不传 `fileToken`，也不把 OA 的七天临时 `fileUrl` 保存为业务附件地址。

## 五、详细处理流程

### 5.1 提交前检查

1. 业务主单必须已经保存，附件不得依赖未保存的临时业务数据；
2. 仅允许草稿或 OA 推送失败状态重新提交；
3. 校验附件数量、文件名、扩展名、MIME 和大小；
4. OA 限制文件名不超过 100 字符、单文件不超过 20 MB；
5. OA 不支持的文件格式必须在提交前明确提示，不能静默忽略；
6. 无附件时不调用 OA 文件上传接口，文件控件不传或传空数组。

### 5.2 临时目录

每次 OA 提交创建独立随机临时目录，例如：

```text
{系统临时目录}/hspsi-oa-upload-{随机ID}/
```

要求：

- 使用系统安全临时目录和随机名称，禁止使用用户提交路径；
- 临时文件名使用附件 UUID，原文件名只用于 OA 上传显示；
- 下载完成后再次核对实际大小；
- 不允许通过 `../`、绝对路径或符号链接逃逸临时目录；
- 每个附件在 `finally` 中删除；整个流程结束后删除随机临时目录；
- 服务异常退出遗留的目录由定时清理任务按创建时间清理。

### 5.3 下载和 OA 上传

每个附件按顺序处理：

1. 使用业务附件中的本地 OSS `objectKey` 下载到本次随机临时目录；
2. 校验实际文件存在、大小与附件元数据一致；
3. 读取为 `Buffer`；
4. 调用 `uploadFile(credential, { fileName, fileBuffer, mimeType })`；
5. 校验 OA 响应同时存在 `fileId` 和 `objectKey`；
6. 根据 MIME/扩展名分组；
7. 释放 `Buffer` 引用并删除临时文件。

分组规则：

| 文件类型                                         | OA控件                 |
| ------------------------------------------------ | ---------------------- |
| JPG、JPEG、PNG、GIF、BMP、WEBP                   | `FinImageUpload`“图片” |
| PDF、DOC、DOCX、XLS、XLSX、PPT、PPTX、TXT、ZIP等 | `FinUpload`“附件”      |

如果某张 OA 表单只有 `FinUpload`，图片也统一进入附件控件；如果只有 `FinImageUpload`，非图片文件应阻止提交并提示 OA 表单缺少附件控件。

### 5.4 领用申请 formData

上传成功后，在现有领用申请 `formData` 中增加：

```json
{
  "jie0xqxvlelg": [
    {
      "id": "OA图片fileId",
      "objectKey": "OA图片objectKey",
      "name": "现场图片.jpg"
    }
  ],
  "9d9x9fg3tmg4": [
    {
      "id": "OA附件fileId",
      "objectKey": "OA附件objectKey",
      "name": "领用依据.pdf"
    }
  ]

```

全部附件上传成功后才允许调用 OA 流程发起接口。

## 六、失败与重试

| 场景                            | 处理方式                                                 |
| ------------------------------- | -------------------------------------------------------- |
| OSS 下载失败                    | 停止发起 OA，实例标记 `PUSH_FAILED`，保留业务原件        |
| 文件校验失败                    | 停止提交并返回具体文件名和原因                           |
| 单个 OA 文件上传失败            | 停止流程发起，清除本地临时文件，保留 OSS 原件            |
| 部分文件已上传 OA，后续文件失败 | 不发起审批；记录成功和失败明细，重试时尽量复用已上传结果 |
| 文件全部上传成功但流程发起失败  | 标记 `PUSH_FAILED`；重试前先进行 OA 流程对账             |
| 清理临时文件失败                | 不改变 OA 业务结果，记录错误并交由定时任务再次清理       |

OA 现有文档没有提供文件删除接口。部分上传成功但最终未发起流程时，可能在 OA 形成孤立文件，因此必须记录 OA 上传结果并在重试时复用，减少重复上传。

## 七、OA 文件映射缓存

为保证失败重试不重复上传，建议在业务附件 JSON 的每个附件对象中增加可选的 OA 上传缓存，不新增业务表字段：

```json
{
  "id": "本地附件UUID",
  "objectKey": "documents/requisition_application/1900850004/xxx.pdf",
  "fileName": "领用依据.pdf",
  "contentType": "application/pdf",
  "size": 102400,
  "oaUploads": [
    {
      "accountSetId": "1",
      "fileId": "OA文件ID",
      "objectKey": "OA对象Key",
      "uploadedAt": "2026-08-11T08:00:00.000Z",
      "size": 102400
    }
  ]
}
```

复用条件必须同时满足：本地附件 ID、文件大小、账套 ID 均一致。若附件被删除或替换，不得复用旧 OA 文件映射。

该 JSON 结构变化需要业务负责人确认后实施；如不接受修改业务附件 JSON，则需要新增专用映射表，必须另行履行数据库变更确认。

## 八、事务和状态

1. OSS 下载、OA 文件上传和 OA 流程发起均为外部网络操作，不放入长数据库事务；
2. 创建/更新 OA 审批实例和最终状态时使用短事务及行锁；
3. OA 流程发起成功后保存返回的 `busKey`、`procInstId` 和状态；
4. 任一步失败，本地业务单据继续保留，OA 实例标记 `PUSH_FAILED`；
5. 已存在 `RUNNING/BACKTOSTART/PASSED` 流程时禁止再次上传附件和重复发起；
6. 回调处理与附件上传相互独立，仍按现有幂等状态机处理。

## 九、安全与审计

- OSS AccessKey 只通过环境变量提供，不写入代码、数据库业务字段或日志；
- 日志不得输出预签名 URL、AccessKey Secret 或完整文件内容；
- 记录业务类型、业务 ID、本地附件 ID、文件名、大小、OA fileId、结果和错误摘要；
- 下载、上传和清理临时文件均使用明确的单文件路径；
- 不根据 OA 上传成功结果删除华溯 OSS 业务原件；
- 正式环境使用最小权限 RAM 用户并定期轮换密钥。
