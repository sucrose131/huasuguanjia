# 华溯之家订单同步

将华溯之家已支付订单同步到本平台销售履约体系：销售订单、客户、收款/退款、出库扣库、售后退货入库、售后事件。

对应接口文档：[订单列表.md](./订单列表.md)、[订单详情.md](./订单详情.md)、[会议门票订单列表.md](./会议门票订单列表.md)、[分期订单列表.md](./分期订单列表.md)  
商品映射依赖：[商品同步.md](./商品同步.md)  
请求签名规则：[请求规则.md](./请求规则.md)

## 1. 同步范围与前提


| 项      | 约定                                                                         |
| ------ | -------------------------------------------------------------------------- |
| 入库门槛   | 仅同步**已支付及以后**的订单；待付款 / 支付中不建销售单                                            |
| 金额单位   | 元（`total_amount` / `actual_amount` / `after_sales_amount` 直接落 decimal）     |
| 归属机构   | 华溯 `service_org_id` → `hspsi_sys_organization_mapping` → 平台 `org_id`       |
| 仓库     | 华溯同步商品统一分类的 `warehouse_type` + 平台 `org_id` → 该机构下对应类型仓库                    |
| 外部发货   | 自动生成出库单并**确认过账扣库存**                                                        |
| 售后退货成功 | 自动生成退货入库单并**确认过账加库存**                                                      |
| 仅退款不退货 | `after_sales_type=1`：只写退款记账 + 售后事件，**不回库**                                 |
| 幂等维度   | `source_id + source_order_type + source_order_id`（同平台不同请求接口类型下，外部 id 可能重复） |


`source_order_type`：**由「订单业务类型对应的拉取接口族」决定**（不同业务订单接口对应不同常量），不是华溯订单体里的字段，也与列表/详情无关。  
当前接口族常量：`SALE_ORDER`（普通销售订单）、`CONFERENCE_TICKET`（会议门票订单）、`INSTALLMENT`（分期订单）。

普通订单若存在且非空 `order_installment_no`，视为分期完款转入，**整单跳过**（接口可能尚未返回该字段，必须先判断字段是否存在）。

### 1.1 列表与详情


| 接口     | 路径                                           | 用途                  |
| ------ | -------------------------------------------- | ------------------- |
| 订单列表   | `POST /hspsi/order/list`                     | 批量发现 / 增量同步入口       |
| 订单详情   | `POST /hspsi/order/info`，body=`{ order_sn }` | 单笔补拉：失败重试、按订单编号强制刷新 |
| 会议门票列表 | `POST /hspsi/order-conference/list`          | 门票增量同步入口；本期无详情接口    |
| 分期订单列表 | `POST /hspsi/order-installment/list`         | 分期增量同步入口；本期无详情接口    |


普通销售订单列表与详情进入**同一套** `applyOrder(snapshot)`。会议门票走独立 `applyConferenceOrder`，不与普通单混用水位。详情与列表字段大体一致，需兼容差异：

- 详情 `address` 文档为 `string[] | null`；列表多为省市区对象 → 统一格式化为字符串
- 详情 `total_amount` 可能为 string；列表为 number → 统一 `Number(...)`
- 明细 `product_type`：`1=套餐`，`2=单品`（优先于 `package_id` 判断）

```
- **能做**：同一订单多次同步时更新当前态，并按「本次相对上次多出来的节点」补作业与事件
- **不能做**：从接口还原「从未被同步观察到的中间状态」完整流水（接口本身只给当前快照）
```

## 1.2 同一订单状态变更如何记录

映射表一行对应一笔外部订单（始终同一个 `so_id`）。每次拿到更新后的快照时：

1. 比较映射表 `source_status` / `source_updated_at` 与本次快照
2. 更新销售单头三维状态（只向前）
3. 对**尚未执行**的副作用按条件补齐：收款 → 出库 → 退款/回库
4. **仅售后**写入 `hspsi_sale_order_service`（幂等）。支付建单、发货出库、期次支付/发放、门票核销**不**写入售后记录

售后事件幂等键：

`HH-EVT-{sourceId}-{orderType}-{orderId}-AS-{PROCESSING|DONE|CANCEL-*}`

| 同步观察到的路径           | 平台记录                                                        |
| ------------------ | ----------------------------------------------------------- |
| 先同步到 3，再 4，再 7，再 8 | 头表跟到 8；收款/出库/退款在对应节点生成；无售后则 `hspsi_sale_order_service` 不写 |
| 漏跑中间态，一次直接看到 8     | 头表到 8；出库/退款若条件已满足仍会**按终态补齐**（不依赖售后事件） |
| 售后处理中 / 完结 / 取消    | service 写 `AS-*`（类型 4 退货 / 5 换货），商品规格取该单下单行 |


结论：**业务履约（钱货）按终态补齐；售后记录只反映售后，不反映下单/发货流水。**  
历史已写入的下单/发货 service 行本次不同步删除。若必须完整状态流水，需华溯提供状态变更日志接口，或本地提高同步频率降低漏态概率。

### 1.3 是否保存原始数据（建议：要存）

**建议保存。** 尤其后续还有分期单、门票单等「多状态/多阶段」模型时，原始快照是低成本扩展点。


| 方案                | 做法                                                       | 适用                  |
| ----------------- | -------------------------------------------------------- | ------------------- |
| A. 映射表存最近快照（本期采用） | `last_payload`（JSON/mediumtext）+ 可选 `last_error_payload` | 排障、按新规则重放、字段演进      |
| B. 同步快照日志表（推荐二期）  | 每次 `source_updated_at` 变化追加一行报文                          | 多状态对账、审计、漏态分析       |
| C. 不存原始数据         | 只落业务字段                                                   | 不推荐：后期改映射/补字段只能再调华溯 |


本期最小集（A）：

- 每次成功 `applyOrder` 后覆盖写入 `last_payload` = 本次完整订单 JSON
- 失败时写入 `last_error_payload`（或 `remark` 截断原因 + payload）
- **不**把原始 JSON 拆进销售单头的大量扩展列

多订单类型与「多个状态」的处理原则：

1. **平台销售单头仍只用现有三维状态**（`order_status` / `delivery_status` / `service_status`），不按外部多状态改表结构。
2. **外部特有状态**（分期还款态、门票核销态等）留在 `last_payload`，并由各 `source_order_type` 的适配器映射到平台三维状态；`sale_order_service` **只写售后**。
3. 售后事件键按售后阶段/明细带维度，例如：
  - 普通单：`AS-PROCESSING` / `AS-DONE` / `AS-CANCEL-*`
  - 门票单：`AS-PROCESSING`（退款申请）/ `AS-DONE`（已退款）
  - 分期单：`AFTERSALE-{id}`；`status=5` 且无 aftersale 明细时补 `AS-DONE`
4. `source_status` 字段：本期存主状态 `order_status`；多状态类型可改存「摘要状态」或并行增加 `source_status_ext`（JSON），以 payload 为准。

## 4. 客户同步



### 匹配规则（已确认）

使用 `source_type` **+** `related_customer_id` 判断是否已存在：

- `source_type` = 华溯数据源 `hspsi_sys_data_source.id`
- `related_customer_id` = 华溯 `user_id`（本对接约定：外部用户主键落此字段）

**不存在则创建，存在则全量更新**（姓名、手机、性别、生日、地址、推荐人、状态、备注、`levels` 身份等均可覆盖）。

> 说明：此处复用 `related_customer_id` 承载外部用户 ID，仅在 `source_type` 指向外部数据源时生效；手工客户勿写入外部 id，避免冲突。



### 创建/更新字段


| 平台客户字段                              | 来源                                               |
| ----------------------------------- | ------------------------------------------------ |
| `org_id`                            | 订单归属机构（由 `service_org_id` 映射）                    |
| `name`                              | `user.nickname`，空则 `consignee`，再空则 `华溯用户{id}`    |
| `mobile`                            | `user.mobile`，空则订单 `mobile`                      |
| `gender`                            | `user.gender`                                    |
| `birthday`                          | `user.birth`（空则 null）                            |
| `address`                           | 订单地址拼接：省+市+区+详细地址                                |
| `referrer_name` / `referrer_mobile` | 订单 `referrer.nickname` / `referrer.mobile`       |
| `source_type`                       | 数据源 id（仅创建时写入）                                   |
| `related_customer_id`               | 华溯 `user_id`（仅创建时写入）                             |
| `status`                            | `user.status`：0→停用(2)，其它→启用(1)                   |
| `remark`                            | `user.remark`                                    |
| `levels`                            | 由订单 `user` 身份字段构建的中文标签数组（与用户同步同规则）；报文无身份时可为 `[]` |


`levels` 构建与用户同步共用：`buildCustomerLevels`（见 [用户同步.md](./用户同步.md)）。

收货信息以**订单快照**写入销售单头 `customer_name/mobile/address`（可与客户主数据不同）。

### 5.3 明细 `hspsi_sale_order_detail`

- **保留下单 SKU**（用户购买的商品/套餐），不在订单行直接拆转换；**规格转换只发生在出库**（第 7 节）。
- 映射后写入平台 `goods_id` + `sku_id`（来自 `hspsi_goods_source_mapping`）：
  - `product_type=1` 套餐：`source_type=COMBO`，`source_goods_id=package_id`，`source_sku_id=0` → 套餐商品及其唯一/默认规格
  - `product_type=2` 单品：`source_type=STANDARD`，`source_goods_id=product_id`，`source_sku_id=sku_id` → 下单规格（华溯 `sku_id` 对应平台 SKU，`spec_models` 为规格文案）
- 明细表本身**不存**规格文案快照，只存 ID；详情接口按 `sku_id` 联查 `hspsi_goods_info_sku.spec_models` 展示
- `sale_qty` = `quantity`
- `sale_price` / `sale_amount` / `fact_sale_amount`：以行 `price` 与数量计算；头尾差落在头 `priceoff_amount`
- 无商品映射：整单失败挂起（`sync_status=3`），不写半截业务单
- **出库**不落购买行，见第 7 节 `package_items`

| 场景     | `so_pay_type` | 金额                                      | `request_key`   |
| ------ | ------------- | --------------------------------------- | --------------- |

| 华溯 `payment_method` | 平台 `pay_mode`                    |
| ------------------- | -------------------------------- |
| 1 微信                | 3                                |
| 2 支付宝               | 4                                |

## 7. 外部发货 → 出库扣库

触发：华溯 `shipments[]` 非空，或状态进入已发货（4/10/5 等）且尚未生成对应出库。

流程：

1. **出库明细优先按** `items[].package_items` **展开真实发货单品**（套餐/单品行均有）：
  - 平台 SKU：`package_items.product_id` → `STANDARD` 映射后取**默认规格**（`is_default=1`）
  - 数量：`(number + gift_number) * items.quantity`
2. 某行无 `package_items` 时：回退该行的 `conversion_rule`；再无则按下单 SKU 原样出库
3. 生成 `hspsi_sale_order_output` + `_detail`（`go_where=1`）并**自动确认过账扣库存**
4. 物流单号写入销售单头 `shipper`（多单号拼接；**出库表不存物流**）
5. 幂等：整单一次出库（`shipments.items` 为空时无法按包裹拆数量）



### 外部同步专用过账（与平台出库不同）

- 实现：`HuasuHomeExternalInventoryPostingService`（**不**走平台 `InventoryPostingService`）
- 出库明细统一空 `batch_no`，不按 FIFO 占批
- **允许负库存**：无 `inventory_total` / `batch_total` 明细时先建账再扣减
- 商品/SKU 只校验存在且未删除，**不判断**启用状态，**不要求** `goods.org_id === 订单机构`；仓库仍用订单机构销售仓
- 若商品分类有 `warehouse_type`，仍须与目标仓库类型一致

平台其它销售出库仍校验库存不足即失败，互不影响。

### 批次策略（外部同步）

- 统一空批号出库；库存不足不挂起，直接扣成负数。



## 8. 售后



### 8.1 事件 → `hspsi_sale_order_service`

**只写售后。** 支付建单、发货出库落到收款单 / 出库单，不写入本表。


| 事件        | `event_type`                      | `event_status` | 商品/规格   |
| --------- | --------------------------------- | -------------- | ------- |
| 售后处理中     | 4 退货 / 5 换货（按 `after_sales_type`） | 1 进行中          | 见下      |
| 售后成功完结    | 同上                                | 2 已完成          | 见下      |
| 售后拒绝/用户取消 | 同上                                | 3 已取消          | 见下      |


售后事件 `goods_id` / `sku_id` 必须取**该销售订单明细行**（与页面手工登记同一约束）：

1. `after_sales.rights_deducted_records[].product_id` 能匹配到下单行时，用该行平台商品/规格
2. 否则取 `items[].after_sales_amount > 0` 的下单行
3. 再否则取第一行

主表只有一组商品/规格：多商品售后只落一条主记录。套餐订单的权益扣减单品若不是下单行本身，回退到套餐下单行，不写订单明细之外的 SKU。历史 `goods_id=0` 的**售后**事件（`event_type` 4/5）在下次同步时补写，不新建。历史下单/发货 service 行（类型 2/3）不补写、不删除。

`event_content`：按事件取源端备注类文本，有则写、无则空；不拼状态/类型/金额等字段。


| 事件                           | `event_content` 来源 |
| ---------------------------- | ------------------ |
| 售后处理中 / 售后成功完结               | 华溯订单 `remark`      |
| 售后拒绝 / 用户取消                  | 华溯 `cancel_reason` |


`next_document_*`：关联生成的出库/退货/退款单号（若有）。

### 8.2 售后成功后的库存与资金


| `after_sales_type` | 资金                              | 库存                                     |
| ------------------ | ------------------------------- | -------------------------------------- |
| 1 仅退款              | 写退款 payment                     | **不回库**（即使有 `rights_deducted_records`） |
| 2 退货退款             | 写退款 payment                     | 按权益扣减生成 exit，自动确认入库                    |
| 3 换货               | 本期先记 service 事件；换货出入库待华溯明细齐全后再做 | —                                      |
| 4 异常售后             | 有退款金额则记账；曾发货则按权益扣减回库            | 见左                                     |


退货入库（`type=2` / 异常售后且曾发货）：

- 明细来源：`after_sales.rights_deducted_records[]`（**不再**按出库明细整单回退）
- 商品：`product_id` → `STANDARD` 映射 → **默认规格**（`is_default=1`，与出库 `package_items` 一致）
- 数量：`gift_number + buy_number`；同 `product_id`（同平台 SKU）**合并为一条明细**
- **不校验** ≤ 已出库可退量；按权益扣减数直接入库（可与出库不一致）
- `rights_deducted_records` 为空 / 缺失 / 有效数量均为 0：跳过回库，**只记账**（退款 payment + 售后事件）
- 若有已确认出库单则写入 `source_output_id`，否则为 0；**不因缺少出库单而失败**
- 自动确认入库加库存

## 10. 同步主流程



### 10.1 批量（列表）

```
1. POST /hspsi/order/list { page, page_size, updated_at }
2. updated_at 不传时：若该类型存在失败映射，取其中最小 source_updated_at（避免失败单被后续成功单越过）；否则取最大 source_updated_at；仍无则 1970-01-01 00:00:00。失败时映射也会写入 source_updated_at。
3. page 从 1 递增；同一轮保持相同 updated_at；按页即时 applyOrder
4. 以返回 total 判断是否还有下一页（page * page_size < total）；本页为空则结束，避免 total 偏大死循环
5. page_size 默认 200，最大 1000（不走环境变量）
```



### 10.2 单笔（详情）

```
1. POST /hspsi/order/info { order_sn }
2. 调用同一 applyOrder(snapshot)
```

用途：失败重试、指定订单刷新。平台接口：`POST /integrations/huasu-home/sync/orders/:orderSn`

### 10.3 `applyOrder(snapshot)`（核心，幂等）

```
1. 读映射；若存在且 source_updated_at 未变化且 sync_status=成功 → 可跳过
2. 若订单对象存在且非空 `order_installment_no` → 跳过（分期完款转入，履约走 INSTALLMENT）
3. 确保 data_source；解析 org / warehouse
4. 客户：source_type + related_customer_id 匹配或创建
5. 明细商品映射校验（失败则 mapping.sync_status=失败，不写半截单）
6. upsert 销售订单头行（已存在则更新状态/金额等，不改 so_no）
7. 收款 payment：无则创建（request_key 幂等）
8. 不写 STATUS / 下单 / 发货售后记录
9. 若已达发货态且缺出库：创建出库并自动确认扣库
10. 若存在售后：写 AS-* 事件（含商品规格）；售后成功时：
   - type=1：仅退款 payment（幂等），不回库
   - type=2 等需回库：按 rights_deducted_records 生成 exit（空则跳过回库）+ 退款
11. 更新映射 source_status / source_updated_at / sync_status / last_sync_at / last_payload（失败则写 last_error_payload）
```

触发建议：

- 批量：`POST /integrations/huasu-home/sync/orders`（body 可选 `updated_at`、`page_size`）
- 单笔：`POST /integrations/huasu-home/sync/orders/:orderSn`（华溯订单编号）
- 会议门票批量：`POST /integrations/huasu-home/sync/conference-orders`（body 可选 `updated_at`、`page_size`；无单笔详情）
- 分期订单批量：`POST /integrations/huasu-home/sync/installment-orders`（body 可选 `updated_at`、`page_size`；无单笔详情）
- 权限：登录 + `sales`
- 幂等：映射表唯一键 + 各作业 request_key / 事件键
- 防重入：普通订单、门票、分期同步各自进程内互斥
- 实现：`apps/api/src/integrations/huasu-home/sync/order-sync.service.ts`、`conference-order-sync.service.ts`、`installment-order-sync.service.ts`

## 15. 会议门票订单

接口：[会议门票订单列表.md](./会议门票订单列表.md)  
`source_order_type=CONFERENCE_TICKET`。增量水位按该类型单独计算：有失败映射时取最早失败 `source_updated_at`，否则取最大成功水位；不与 `SALE_ORDER` 混用。本期只有列表，无详情/单笔刷新。

### 15.1 业务口径

门票只有两段履约：**购买**、**核销发货**。退款只能发生在未核销，且**不退货、不回库**。


| 外部条件                                               | 平台动作                                 |
| -------------------------------------------------- | ------------------------------------ |
| `order_status` 1 待付款 / 2 已取消 / 9 支付中               | 不建单                                  |
| `order_status` 3 已付款 / 4 退款申请 / 5 已退款              | 建/更新销售单 + 收款                         |
| `verify_status=1` **且** `rights_granted=1`，且未退款    | 生成出库并自动过账扣库                          |
| `order_status=4` 退款申请                              | 头表售后中；只记事件，不退款记账                     |
| `order_status=5` 或 `refund.refund_status=2`，且本地未出库 | 写退款 payment；**永不**生成退货入库；即使报文已核销也不出库 |
| 本地已出库后再出现退款                                        | 整单挂起失败，不冲已出库库存                       |


归属机构：`user.organization_id` → `hspsi_sys_organization_mapping`。无 `service_org_id`。  
销售单无收货地址：`customer_address` 留空，**不使用**会议地址。推荐人字段留空。

门票 `order_status` 与普通销售单枚举不同，不可复用普通单状态码。


| 华溯门票状态 | 附加条件          | 平台 `order_status` | `delivery_status` | `service_status` |
| ------ | ------------- | ----------------- | ----------------- | ---------------- |
| 3 已付款  | 未达出库条件        | 1 正常              | 1 待发货             | 3 无              |
| 3 已付款  | 已核销且已发放、未退款   | 1 正常              | 3 已发货             | 3 无              |
| 4 退款申请 | 保持未发货         | 1 正常              | 保持                | 1 售后中            |
| 5 已退款  | 未出库（含首次同步已核销） | 3 关闭              | 1 待发货             | 2 售后结束           |


跳过无变更时除 `source_updated_at` / `order_status` 外，还比对上次 payload 的 `verify_status`、`rights_granted`。

### 15.2 字段映射差异


| 业务项  | 门票来源                                            | 落库                                                             |
| ---- | ----------------------------------------------- | -------------------------------------------------------------- |
| 销售明细 | `product_package_id`                            | `COMBO` 映射；`sale_qty=quantity`；价取 `price`                      |
| 出库明细 | 订单级 `package_items[]`                           | `(number+gift_number)*quantity`；`product_id` → STANDARD 默认规格   |
| 收款   | `actual_amount` / `pay_time` / `payment_method` | `HH-PAY-{sourceId}-CONFERENCE_TICKET-{orderId}`                |
| 出库   | 核销且发放后整单一次                                      | `HH-SHIP-{sourceId}-CONFERENCE_TICKET-{orderId}`               |
| 退款   | `refund.refund_amount`（空则 `actual_amount`）      | `HH-REFUND-...-{refund.id}`                                    |
| 事件   | 仅退款申请 / 已退款                                      | `AS-PROCESSING` / `AS-DONE`；商品/规格取门票套餐下单行；核销发货只写出库单 |


实现：`apps/api/src/integrations/huasu-home/sync/conference-order-sync.service.ts`  
触发：`POST /integrations/huasu-home/sync/conference-orders`

## 16. 分期订单

接口：[分期订单列表.md](./分期订单列表.md)  
`source_order_type=INSTALLMENT`。增量水位按该类型单独计算：有失败映射时取最早失败 `source_updated_at`，否则取最大成功水位；不与 `SALE_ORDER` / `CONFERENCE_TICKET` 混用。本期只有列表，无详情/单笔刷新。

**一张销售单会存在多笔分期期次**：一笔华溯分期订单（`no`=`OI…`）对应一张平台销售单；后续期次支付只追加收款和出库，不新建 `so_no`。

完款后华溯会转成普通订单并可能返回 `order_installment_no`。普通订单同步若检测到该字段存在且有值则整单跳过，履约仍以分期接口为准。

### 16.1 业务口径


| 外部条件                    | 平台动作                                     |
| ----------------------- | ---------------------------------------- |
| `status` 1 待审核 / 2 审核驳回 | 不建单                                      |
| `status` 3 进行中，且至少一期已支付 | 建/更新销售单；每期一笔收款；有 `rights_issue` 则按该期单品出库 |
| `status` 4 已完成          | 销售单结束；补齐已支付期次收款与出库                       |
| `status` 5 已售后          | 头表售后结束；已出库则按 `aftersale` 回库，从未出库则只记事件    |
| `status` 6 已转正常订单       | 仍走分期履约；对应普通订单靠 `order_installment_no` 跳过 |


归属机构：`organization_id`，缺则 `user.organization_id`。  
销售单无收货地址：`customer_address` 留空。推荐人留空。无 `payment_method` 时收款 `pay_mode=7` 线下。

分期 `status` 与普通销售单枚举不同，不可复用。`status=6` **不是**普通单的「已退款」。


| 华溯 status | 附加条件    | 平台 `order_status` | `delivery_status` | `service_status` |
| --------- | ------- | ----------------- | ----------------- | ---------------- |
| 3 进行中     | 尚无期次出库  | 1 正常              | 1 待发货             | 3 无              |
| 3 进行中     | 已有期次出库  | 1 正常              | 3 已发货             | 3 无              |
| 4 已完成     | 补齐出库后   | 2 结束              | 3 已发货             | 3 无              |
| 5 已售后     | 保持已有发货态 | 2 结束              | 保持                | 2 售后结束           |
| 6 已转正常订单  | 补齐出库后   | 2 结束              | 3 已发货             | 3 无              |


已支付期次：`paid_amount>0`，或（`amount>0` 且 `unpaid_amount` **显式为 0**；字段缺失不视为已付）。出库数量取 `rights_issue.number`（不含 `gift_number`）。头表 `so_amount=package_amount`（缺则 `amount`），`fact_amount=amount`，`priceoff_amount=max(package_amount-amount,0)`（未付金额 `unpaid_amount` / 已付 `paid_amount` 不是优惠，已付记收款）。首期出库后 `delivery_status` 只向前。

### 16.2 售后

列表字段 `aftersale` 对应华溯表 `hszj_order_installment_aftersale`，可能为 `null`、单条或数组。无退款金额、无售后类型。


| 字段           | 平台动作                                         |
| ------------ | -------------------------------------------- |
| `product_id` | STANDARD 映射后取默认规格回库                          |
| `number`     | 回库数量                                         |
| `remark`     | 退货原因 / 事件内容                                  |
| `id`         | 幂等键 `HH-EXIT-...-INSTALLMENT-{orderId}-{id}` |


软删（`deleted_at` 有值）的记录跳过。表无金额字段，**不写退款 payment**。`status=5` 且 `aftersale` 为空时更新头表售后态，并补一条 `AS-DONE`；有 aftersale 明细则只写 `AFTERSALE-{id}`，不重复。没有已确认出库时**不回库、不加库存**，只记售后事件。期次支付/权益发放不写售后记录。

### 16.3 字段映射差异


| 业务项  | 分期来源                                   | 落库                                                                                                                                 |
| ---- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 订单金额 | `package_amount`                       | `so_amount`；缺则回退 `amount`                                                                                                          |
| 实际金额 | `amount`                               | `fact_amount`（不是 `paid_amount`）                                                                                                    |
| 优惠金额 | `package_amount - amount`              | `priceoff_amount`，未付金额不记优惠                                                                                                        |
| 销售明细 | `products[]`                           | `product_id` → STANDARD 默认规格；`sale_qty=number`                                                                                     |
| 收款   | 每期 `paid_amount` / `offline_paid_time` | `HH-PAY-{sourceId}-INSTALLMENT-{orderId}-{period.no}`                                                                              |
| 出库   | 每期 `rights_issue`                      | `HH-SHIP-{sourceId}-INSTALLMENT-{period.no}`；数量=`number`                                                                           |
| 售后退货 | `aftersale.product_id` + `number`      | `HH-EXIT-{sourceId}-INSTALLMENT-{orderId}-{aftersale.id}`                                                                          |
