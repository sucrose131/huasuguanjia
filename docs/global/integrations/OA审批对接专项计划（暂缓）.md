# OA审批对接专项计划（暂缓）

> 状态：暂缓，不进入当前开发范围
>
> 编制日期：2026-08-04
>
> 恢复条件：OA接口、流程模板、人员映射和回调协议确认后单独批准实施
>
> 口径更新：2026-08-05 确认保留现有“审批通过后直接操作库存”的行为；详细实施以《统一审批与 OA 双模式改造计划》为准

## 1. 暂缓说明

当前阶段不实施 OA 审批对接，所有既有业务单据继续使用系统当前审批逻辑。

本期不修改：

- 现有审批页面；
- 现有审批接口；
- 现有审批字段；
- 现有审批状态；
- 审批通过、拒绝后的业务流转；
- 现有审批权限。

当前库存及业务规则改造不得依赖 OA 系统才能上线。

新增通用入库和通用出库按已确认规则无需审批，不属于未来 OA 审批范围，除非后续业务口径再次调整。

## 2. 后续目标模式

未来需要审批的单据在本系统提交后，自动向 OA 发起审批；本系统不再承担审批人同意、拒绝操作，只接收 OA 审批结果。

```text
本系统创建单据
→ 提交审批申请
→ 推送OA
→ OA审批中
→ OA回调审批结果
→ 本系统更新审批状态
```

OA 审批和内部审批只是两种审批结果来源，不改变现有审批通过后的业务效果。当前审批通过会直接操作库存的单据，在 OA 通过后继续由统一结果处理器直接完成库存过账；当前审批通过只生成下游草稿的单据，仍按现有方式生成下游草稿。

OA 回调接口只负责可靠记录结果，库存和下游业务由可重试、幂等的结果任务执行，不在回调请求事务中执行耗时库存操作。

示例：

```text
提交库存调拨
→ OA审批通过
→ 统一结果处理器完成调出仓扣减和调入仓增加
→ 调拨完成
```

## 3. 后续状态模型

未来 OA 对接需要区分：

1. OA 审批状态；
2. 本系统业务办理状态；
3. 库存过账状态。

建议状态：

```text
OA审批状态：未提交 / 推送中 / 审批中 / 已通过 / 已拒绝 / 推送失败
业务办理状态：草稿 / 待办理 / 办理中 / 已完成 / 已作废
库存过账状态：未过账 / 部分过账 / 已过账 / 已冲销
```

不同业务是否允许部分过账，需要后续逐项确认。

## 4. OA审批发起

后续需要保存：

- 本系统单据类型；
- 本系统单据ID和业务单号；
- OA流程类型；
- OA流程实例ID；
- OA申请单号；
- 推送状态；
- 推送次数；
- 首次和最后推送时间；
- 请求幂等键；
- 推送失败原因；
- 请求和响应必要摘要。

推送失败需要支持安全重试，同一次业务提交不得生成多个有效 OA 流程。

## 5. OA审批回调

回调需要具备：

- 调用方认证或请求签名；
- 时间戳校验；
- 重放攻击防护；
- OA流程实例ID唯一匹配；
- 幂等处理；
- 审批状态顺序校验；
- 重复回调不重复推进业务；
- 旧流程回调不能覆盖新流程结果；
- 原始回调或必要摘要留档；
- 明确的成功和失败响应。

OA回调拒绝后：

- 单据不得进入后续办理；
- 不得库存过账；
- 记录拒绝状态和审批意见；
- 创建人可按业务规则修改后重新提交或作废；
- 重新提交需创建新的 OA 流程实例或遵循 OA 接口约定。

## 6. 人员匹配和待办

系统用户需要关联稳定的 OA 人员标识，建议使用 OA 用户ID或工号，不通过姓名直接匹配。

审批通过后仍需人工办理的业务，根据单据中的经办人、接收人或责任人字段确定后续办理人。审批通过后按现有规则直接过账的库存业务不新增人工办理环节。

无法匹配人员时：

- 不得自动分配给错误用户；
- 单据进入责任人匹配异常状态；
- 记录异常原因；
- 由有权限的管理员处理。

## 7. 后续迁移原则

OA对接上线时，需要逐类迁移现有审批单据，不建议一次性关闭全部内部审批。

建议顺序：

1. 建立通用 OA 流程实例、推送记录和回调日志；
2. 完成签名、幂等、重试和人员映射；
3. 选择一个低风险业务试点；
4. 验证审批通过、拒绝、重复回调和人员异常；
5. 按业务模块逐步迁移；
6. 每个业务完成回归后再关闭对应内部审批入口；
7. 保留可回退到原审批模式的发布方案。

## 8. 恢复开发前待确认事项

1. OA系统产品和接口版本；
2. OA流程模板及各业务对应的流程类型；
3. 发起审批接口协议；
4. 审批结果回调协议；
5. 请求和回调签名方式；
6. OA流程实例唯一标识；
7. OA用户与本系统用户映射字段；
8. 各业务单据后续责任人字段；
9. 审批意见、审批人和审批过程是否需要完整同步；
10. 推送失败重试次数和人工补偿方式；
11. OA不可用时是否允许降级；
12. 旧审批中单据在切换期间如何处理；
13. 是否需要同步附件；
14. 测试环境和生产环境的 OA 地址及凭证管理方式。

## 9. 后续验收方向

- 同一业务提交只生成一个有效 OA 流程；
- 推送失败能够安全重试；
- 重复回调不会重复推进业务或库存过账；
- OA拒绝后不能继续办理；
- OA通过后正确匹配经办人或接收人；
- 人员无法匹配时进入可追踪的异常状态；
- 旧回调不能覆盖新流程结果；
- OA审批状态、业务状态和库存过账状态相互独立；
- 每个已迁移业务都可以按发布方案安全回退。
