# 当前需求前端界面设计方案

> 状态：设计已确认并完成首轮实现；浏览器界面验收通过
>
> 编制日期：2026-08-09
>
> 样式依据：`docs/global/standards/Element Plus Table表格样式归档.md`
>
> 对应需求：需求一“商品全局主档及组织可见范围”、需求十二“采购业务快捷创建正式商品”

## 1. 设计边界

本方案只设计当前两个必须继续开发的功能：

1. 根据当前登录账号所属组织的启用仓库类型，展示可用商品分类、商品和 SKU；
2. 在采购申请、采购订单、采购入库中的可编辑商品明细中，提供搜索无结果后的快捷新增正式商品能力。

本方案已用于本轮正式实现。后端权限、直接入库事务保存和采购页面交互均已落地；后续调整仍须遵守本文和项目级开发规则。

数据库继续使用现有表和字段，不新增表、字段或数据字典。基础单位来自 `hspsi_basic_unit`。

## 2. Element Plus Table 样式选型

所有表格改造只从《Element Plus Table表格样式归档》中选择。

| 页面/区域 | 采用的归档样式 | 选择原因 |
| --- | --- | --- |
| 商品资料主列表 | 2斑马纹、5溢出提示、7固定列、9流体高度、16自定义列模板、23自定义索引、24固定布局 | 商品字段多、需要稳定列宽和长文本提示，左侧序号/ID及右侧操作保持固定 |
| 商品分类主列表 | 5溢出提示、7固定列、16自定义列模板、19树形数据、23自定义索引、24固定布局 | 保留现有分类层级，明确仓库类型和状态 |
| 采购业务主列表 | 2斑马纹、5溢出提示、7固定列、9流体高度、16状态模板、23自定义索引、24固定布局 | 延续现有采购列表，不改变用户主列表操作习惯 |
| 采购申请/订单/入库明细 | 3带边框、5溢出提示、7固定操作列、16自定义列模板、21表尾合计、24固定布局 | 明细字段多，快捷新增状态需要在单元格中清晰展示 |

统一规则：

- 主列表使用 `stripe`；
- 单据明细使用 `border`；
- 数据多时使用 `max-height`，不使用写死页面高度；
- 序号和 ID 固定在左侧，操作列固定在右侧；
- 商品、分类、备注等长文本使用 `show-overflow-tooltip`；
- 状态使用 `el-tag`，数量和金额右对齐；
- 不在日常业务列表使用合并单元格。

## 3. 功能一：组织仓库类型决定商品可见范围

### 3.1 商品资料页面

现有页面：`apps/web/src/views/GoodsPage.vue`

实现裁剪说明：根据“现有界面能兼容新需求时不改页面”的后续确认，本轮保留现有商品资料布局、查询区和表格，不新增数据范围提示条或重复的仓库类型列。页面继续调用 `/goods` 和 `/goods/categories`，数据范围由后端统一收口，因此无需为了过滤逻辑重做已经可用的界面。以下提示条和列调整保留为后续增强建议，不属于本轮完成条件。

#### 页面顶部改造

在统计条和查询栏之间增加“当前数据范围”提示条：

```text
当前组织：华溯生物
可用仓库类型：试剂仓、耗材仓、成品仓
商品范围由当前组织的启用仓库类型自动确定
```

普通组织账号只展示自己的范围；具有跨组织权限的账号显示当前查看组织和“切换组织”入口。没有跨组织权限时不显示组织选择器。

#### 查询区改造

- 保留关键词、分类、供应方式、商品形态和状态；
- “商品分类”选项只加载当前组织可见分类；
- 不额外增加“所属组织”筛选，因为商品仍然是全局主档；
- 可增加只读的“适用仓库类型”提示，不允许用户在商品页直接改变组织范围。

#### 表格改造

列顺序：

```text
序号 → ID → 速查码 → 商品名称 → 分类 → 适用仓库类型
→ 基础单位 → 品牌 → 规格型号 → 供应方式 → 商品形态
→ 参考成本 → 销售价 → SKU数 → 状态 → 操作人 → 操作时间 → 操作
```

新增展示列“适用仓库类型”，该值来自商品分类的 `warehouse_type`，不是商品表新增字段。

表格采用：

- `stripe`；
- `max-height`；
- `table-layout="fixed"`；
- 商品名称、分类使用 `show-overflow-tooltip`；
- 序号、ID固定左侧，操作固定右侧；
- 分页序号使用归档第23种自定义索引，翻页后序号连续。

#### 空状态

当前组织没有启用仓库时：

```text
当前组织尚未配置启用仓库
配置仓库及仓库类型后，系统会自动展示对应分类和商品
```

当前组织有仓库但没有匹配分类时：

```text
当前仓库类型下暂无可用商品分类
请先维护对应仓库类型的商品分类
```

空状态不能显示“新增商品”作为唯一建议，因为没有可用分类时即使新增商品也无法完成分类选择。

### 3.2 商品分类页面

现有页面：`apps/web/src/views/CategoriesPage.vue`

实现裁剪说明：现有树形表格可以直接兼容后端返回的组织范围分类，本轮不改动其结构和样式。数据范围提示条属于后续可选增强，不影响当前权限逻辑。

#### 页面顶部改造

增加与商品资料相同的“当前数据范围”提示条，显示：

- 当前组织；
- 当前组织拥有的启用仓库类型；
- 当前展示分类数量。

#### 树形表格改造

继续使用归档第19种“树形数据”方案，不改成普通平铺表格。

列顺序保持：

```text
展开列 → 序号 → ID → 分类名称 → 仓库类型
→ 关联属性 → 属性数 → 商品数 → 子分类数 → 排序 → 状态 → 操作时间 → 操作
```

数据范围变化：

- 普通组织账号只显示其启用仓库类型对应的分类；
- 父分类为了维持树形路径可以作为结构节点返回，但必须明确其自身是否可用于建档；
- 分类名称和关联属性使用溢出提示；
- 仓库类型和状态继续使用自定义列模板。

#### 新增分类窗口

保持现有字段：分类名称、上级分类、仓库类型、状态、关联属性、排序和备注。

本设计建议普通组织账号新增分类时，仓库类型下拉只显示当前组织拥有的启用仓库类型，避免保存后分类立即从自己的可见范围消失。是否允许分类管理员创建当前组织没有的仓库类型，需要业务确认。

### 3.3 采购及其他业务商品选择

前端选择商品时不再先加载全系统商品再自行过滤，而是向后端请求当前用户有权访问的商品范围。

界面表现：

- 选择组织后刷新仓库、分类和商品选项；
- 选择仓库后只显示该仓库类型对应分类下的商品；
- 切换组织或仓库后，如果已选商品不再适用，清空该商品并提示原因；
- 无匹配商品时进入需求十二的“搜索无结果—快捷新增”流程。

## 4. 功能十二：采购业务快捷创建正式商品

### 4.1 适用页面

统一应用到：

- 采购申请新增/编辑；
- 无来源申请的采购订单新增/编辑；
- 直接采购入库新增；
- 采购入库中允许新增明细的业务场景。

由采购订单自动带出的普通入库明细保持来源商品只读，不允许通过入库环节把来源订单商品替换成另一商品。如确需新增订单外商品，应走直接入库或另行调整采购订单。

### 4.2 采购明细表格

现有页面：`apps/web/src/views/PurchasePage.vue`

采用归档第3、5、7、16、21、24种组合：

- 明细使用 `border`；
- 商品名称、SKU规格使用自定义列模板；
- 长商品名称使用溢出提示；
- 操作列固定右侧；
- 订单金额继续使用表尾合计；
- 表格保持固定列宽，防止快捷状态撑宽页面。

建议列顺序：

```text
商品编码 → 商品名称 → 分类 → SKU/规格 → 单位
→ 数量/入库数量 → 单价/批号/库位等当前业务字段 → 操作
```

### 4.3 商品搜索交互

当前“补充商品”按钮不再常驻显示，改成搜索无结果时出现明确引导。

#### 搜索有结果

```text
商品名称 [搜索框：医用手套]
          医用手套（耗材分类 / 件）
          医用检查手套（耗材分类 / 盒）
```

用户直接选择现有商品，不出现新增按钮。

#### 搜索无结果

```text
未找到“无菌采样管”
[＋ 新增“无菌采样管”]
```

点击后打开快捷新增窗口，商品名称自动带入“无菌采样管”。不使用 `allow-create` 直接把自由文本当成正式商品。

“搜索无结果”只代表当前组织候选范围内没有结果，不代表全局主档不存在。点击新增后必须先调用全局名称检查：

- 全局不存在：打开三字段快捷新增窗口；
- 全局存在且当前组织可用：关闭新增流程并自动选择已有商品；
- 全局存在但当前组织缺少对应仓库类型：不打开新增窗口，提示已有商品分类、要求的仓库类型以及配置仓库/联系管理员的处理方式；
- 全局商品或分类已停用/删除：禁止重复新增，提示联系商品管理员处理原档案。

快捷窗口内允许用户修改商品名称，因此点击“暂存到单据行”时必须再次执行全局名称检查，不能只检查一次搜索词。

### 4.4 快捷新增窗口

当前窗口包含速查码、SKU规格、换算系数、成本和销售价等字段，需简化为三个必填字段：

```text
新增商品

商品名称  [无菌采样管                 ]
商品分类  [请选择现有叶级分类          ▼]
基础单位  [请选择基础单位              ▼]

提示：确认后仅暂存在当前单据中，保存或提交整张单据成功后才会创建正式商品和默认SKU。

[取消]                         [暂存到单据]
```

字段规则：

- 商品名称：自动带入搜索词，允许修改；
- 商品分类：可搜索下拉，只显示当前组织仓库类型允许的启用叶级分类；
- 基础单位：可搜索下拉，读取现有基础单位资料；
- 三项全部必填；
- 系统自动生成“默认规格”SKU，`pcs_qty=1`、`is_default=1`；
- 供应方式、商品形态、价格等使用已确认的系统默认值，不在快捷窗口增加操作负担。

### 4.5 暂存后的明细行

使用归档第16种“自定义列模板”显示临时状态：

```text
商品名称：无菌采样管  [待创建]
分类：实验耗材
SKU/规格：默认规格   [系统生成]
单位：支
```

状态标签建议：

- “待创建”使用 warning 类型浅色标签；
- “系统生成”使用 info 类型浅色标签；
- 不显示虚假的数据库 ID；
- 商品编码在正式保存前显示“保存后生成”或“—”。

用户重新选择已有商品时，清除当前行的临时商品和临时 SKU。

### 4.6 保存、提交和关闭

- 点击快捷新增窗口“暂存到单据”：只改变当前页面内存，不调用独立商品创建接口；
- 点击整个采购表单右上角关闭、取消或离开页面：临时商品丢弃；
- 采购表单校验失败：临时商品仍留在当前页面供用户修正，但数据库无新增记录；
- 主表单请求失败：商品、SKU和单据全部不生效；
- 主表单成功保存后：商品、默认 SKU和采购单据在同一事务中创建。

在不新增临时字段的前提下，“保存草稿”也是一次正式业务单据持久化，因此保存草稿成功时必须创建正式商品和 SKU；仅关闭或取消表单时不创建。若要求保存草稿时仍不创建商品，则现有采购明细没有字段存放临时商品内容，需要另行改变数据库方案。

### 4.7 重复和不匹配状态

#### 商品名称重复

```text
商品“无菌采样管”已经存在
[返回选择已有商品]
```

不自动替换用户输入，不重复创建。

#### 分类与仓库类型不匹配

在分类下拉阶段即隐藏不适用分类；后端最终校验失败时提示：

```text
所选商品分类要求“耗材仓”，当前组织所选仓库为“试剂仓”，请重新选择分类或仓库。
```

#### 当前组织没有适用仓库

禁用“暂存到单据”，提示先维护组织仓库，不允许创建一个当前业务无法入库的商品草稿。

## 5. 前端字段—API—数据库映射

| 页面字段/状态 | API字段 | 数据来源/存储表 | 数据库字段 | 写入时机 |
| --- | --- | --- | --- | --- |
| 当前用户组织 | 登录上下文 | `hspsi_sys_user` | `org_id` | 登录时读取 |
| 可用仓库类型 | API计算结果 | `hspsi_basic_warehouse` | `org_id`,`warehouse_type`,`status`,`deleted_at` | 不写入 |
| 商品分类 | `categoryId` | `hspsi_goods_info_category` | `goods_catg_id`,`warehouse_type` | 主表单成功保存商品时 |
| 商品名称 | `goodsName` | `hspsi_goods_info` | `goods_name` | 主表单成功保存时 |
| 基础单位 | `unitType` | `hspsi_basic_unit` / `hspsi_goods_info` | `id` / `unit_type` | 主表单成功保存时 |
| 临时商品状态 | `newGoods` | 页面临时对象 | 无数据库字段 | 不单独写入 |
| 全局名称检查 | `name` / `exists`,`usable`,`reason` | `hspsi_goods_info`、`hspsi_goods_info_category`、`hspsi_basic_warehouse` | `goods_name`,`status`,`deleted_at`,`warehouse_type`,`org_id` | 只读，不写入 |
| 默认SKU规格 | 后端自动生成 | `hspsi_goods_info_sku` | `spec_models` | 主表单成功保存时 |
| 默认SKU标志 | 后端自动生成 | `hspsi_goods_info_sku` | `is_default` | 主表单成功保存时 |
| SKU换算数量 | 后端自动生成 | `hspsi_goods_info_sku` | `pcs_qty` | 主表单成功保存时 |
| 采购申请商品/SKU | `goodsId`,`skuId` | `hspsi_purchase_approve_detail` | `goods_id`,`sku_id` | 同一事务 |
| 采购订单商品/SKU | `goodsId`,`skuId` | `hspsi_purchase_order_detail` | `goods_id`,`sku_id` | 同一事务 |
| 采购入库商品/SKU | `goodsId`,`skuId` | `hspsi_purchase_order_input_detail` | `goods_id`,`sku_id` | 同一事务 |

## 7. 本轮已采用的业务确认

1. 超级管理员是否默认查看全部组织商品，还是必须先选择查看组织；
2. 普通组织账号新增分类时，仓库类型下拉是否只显示本组织已有的启用仓库类型；
3. 保存采购申请草稿成功时，是否按本方案同时创建正式商品和默认 SKU；
4. 采购订单来源入库是否保持商品只读，只在直接入库开放快捷新增；
5. 快捷新增商品的供应方式、商品形态是否沿用当前系统默认值，不在三字段窗口展示。

本轮采用结论：超级管理员查看全部；普通账号按自身组织范围；保存采购申请草稿时创建正式商品和默认 SKU；订单来源入库保持只读；快捷窗口不展示供应方式、商品形态和价格字段。

## 8. 实现与验收结果

- `PurchasePage.vue` 已将常驻“补充商品”改为搜索无结果后的“新增‘名称’”；
- 快捷商品窗口已缩减为名称、叶级分类、基础单位三个必填字段；
- 采购申请、无来源采购订单和直接采购入库复用同一页面暂存结构；
- 暂存行显示“待创建”，默认 SKU 固定为“默认规格”；
- 浏览器已验证直接入库入口、无结果引导和三字段弹窗；
- 浏览器已验证不在首批候选中的全局已有商品不会重复进入新增窗口，而是自动选择原商品；
- 全局不存在的唯一测试名称才会进入三字段窗口；
- 取消快捷窗口及父单据后，以唯一测试名称查询商品资料，结果为空；
- 订单来源采购入库仍使用原有只读明细组件，未破坏既有界面。
