# 定时任务定义与调度管理实施方案

> 状态：代码完成待验收
>
> 编制日期：2026-08-14
>
> 入口：系统管理 > 任务管理（`/system/tasks`）

## 1. 需求与边界

系统管理员在后台维护可调度的同步任务：新增、删除、修改名称、开关和 Linux Cron 执行时间。开启后由 API 进程按 `Asia/Shanghai` 时区自动执行。保存 Cron 后无需重启 API，调度器每分钟从数据库读取最新表达式。

**允许**：新增、删除、改名称、改 Cron、启用/停用、备注、立即执行一次。

**新增规则**：

- 任务类型来自代码处理器注册表，页面下拉选择，不能手填任意编码。
- 未删除记录中同一 `task_code` 只能有一条。
- 删除为软删除；删除后可按同一类型再新增。

**拦截**：未注册类型、编辑时改 `task_code`、非法 5 段 Cron、并行重入。

**暂缓**：OSS 清理、任务参数入库、多 API 实例分布式锁、十方清源手工 HTTP 同步接口。

## 3. 数据库

表 `hspsi_sys_scheduled_task`。`task_code` 在未删除记录中业务唯一，库表使用普通索引以便软删除后可再新增同一类型。不新增字典。

字段映射见下表。`nextRunAt` 为计算字段，不落库。

| 页面字段 | 业务含义 | API 字段 | 表.字段 | 必填/默认 | 写入时机 |
| --- | --- | --- | --- | --- | --- |
| 任务名称 | 显示名 | `taskName` | `task_name` | 必填 | 新增/编辑保存 |
| 任务类型 | 已实现处理器 | `taskCode` | `task_code` | 新增必选，编辑只读 | 仅新增写入 |
| Cron | Linux 五段表达式 | `cronExpr` | `cron_expr` | 必填，默认 `0 1 * * *` | 新增/编辑保存 |
| 启用 | 是否调度 | `status` | `status` | 默认 0 | 开关/保存 |
| 备注 | 说明 | `remark` | `remark` | 可空 | 新增/编辑保存 |
| 下次执行 | 计算字段 | `nextRunAt` | 不写库 | — | 列表/预览 |
| 最近执行 | 调度回写 | `lastRunAt` | `last_run_at` | — | 任务开始 |
| 最近结果 | 列表脱敏 | `lastStatus` / `lastMessage` | `last_status` / `last_message` | — | 任务结束 |
| 执行记录 | 每次触发一行；失败存原始错误 | `id` / `startedAt` / `status` / `message` | `hspsi_sys_scheduled_task_run` | — | 开始插入，结束更新 |
| ID | 主键 | `id` 字符串 | `id` | — | — |

`status`：0 停用 / 1 启用。`last_status` / 执行记录 `status`：1 成功 / 0 失败 / 2 跳过 / 3 运行中。任务列表 `last_message` 脱敏；执行历史 `message` 失败时写原始错误（截断 500）。

迁移：`database/migrations/20260814_scheduled_task.sql`、`database/migrations/20260814_scheduled_task_run.sql`、`database/migrations/20260818_shifang_qingyuan_scheduled_tasks.sql`。目标库以 `apps/api/.env` 的 `DATABASE_URL` 为准，库名 `hspsi-dev`。

## 4. 界面

系统管理下「任务管理」页。列表展示名称、类型、Cron、启用状态、下次执行、最近执行、最近结果。可打开「执行记录」查看历史。编辑弹窗可改 Cron（带下次执行预览和示例），类型创建后只读。行内开关控制启用。立即执行不改变已保存的 Cron，并返回执行记录编号。

## 5. API

权限：列表 `system:view` 或 `system:4:view`；新增 `system:create`；改配置/立即执行 `system:update`；删除 `system:delete`。系统级配置，不按登录组织过滤。

- `GET /system/scheduled-task-types`
- `GET /system/scheduled-task-cron-preview?cronExpr=`
- `GET /system/scheduled-tasks`
- `POST /system/scheduled-tasks`
- `PUT /system/scheduled-tasks/:id`
- `DELETE /system/scheduled-tasks/:id`
- `POST /system/scheduled-tasks/:id/run`（立即启动，返回 `runId`，不阻塞等待同步结束）
- `GET /system/scheduled-tasks/:id/runs`（最近 50 条执行历史）
- `GET /system/scheduled-tasks/:id/runs/:runId`

调度器每约 10 秒检查当前分钟，读取 `status=1` 且未删除的任务，命中 Cron 则投入进程内单通道队列串行执行（避免与网站共用连接池时并行打满）。同一 `task_code` 进程内互斥。单次执行超过 30 分钟记为超时并释放队列；失败后自动重试 3 次（1/5/15 分钟），重试等待不占用队列。`nextRunAt` / `lastRunAt` 按 `Asia/Shanghai` 墙钟返回。扫描失败不跳过当前分钟。定时触发的操作人 ID 为 `0`。按单 API 进程设计。

## 6. 验收标准

- Cron 解析单测通过。
- 停用不跑、启用到点跑、重入跳过。
- 新增未注册类型或重复类型被拒绝。
- 删除后不再调度，且可按同一类型再新增。
- 修改 Cron 后无需重启 API，列表下次执行时间更新；非法 Cron 不写库。
