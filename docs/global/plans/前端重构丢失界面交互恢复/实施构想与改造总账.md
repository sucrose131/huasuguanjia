# 前端重构丢失界面交互恢复：实施构想与改造总账

> 一级需求：恢复前端重构过程中丢失的页面布局、按钮、弹框及操作交互
> 产品基准分支：`fix/0818-dashboard-org-scope`
> 实施架构基准：`dev`
> 建立日期：2026-08-26
> 当前阶段：原 P0 已验收；P1 已批量实施；P0-R01 和 P2 代码已一次性完成并通过自动化，待业务审核；本地 MySQL 3306 未启动，字典与历史订单回算待执行

## 1. 已确认实施原则

1. 旧分支决定界面布局、字段顺序、组件类型、按钮文案、按钮位置、显示条件、弹框、提示语和操作路径。
2. `dev` 决定目录结构、组件拆分、配置组织、代码规范和格式，不恢复旧版巨型页面。
3. 不重新设计旧版已经存在的界面或交互，不用新编组件替代旧版已有组件。
4. 本轮只恢复前端丢失或弱化的界面入口和交互，不擅自新增数据库表、字段、字典或改变后端业务语义。
5. 默认按编号实施；业务负责人明确要求批量交付时，同一优先级可合并实施和记录，整体完成后进入“待业务审核”，审核通过后统一核销。

## 2. 状态和核销规则

- `待开发`：尚未修改代码。
- `开发中`：当前唯一正在处理的交付项。
- `待业务审核`：代码、对表和自动化检查已完成，等待业务负责人审核。
- `已验收`：业务负责人明确确认通过；从活动队列核销，但保留记录和链接。
- `部分完成/阻塞`：未满足完成定义，必须写明剩余工作和阻塞证据。

每项开始时更新本总账状态；每项结束时必须：

1. 在当日 `docs/daily/YYYY-MM-DD/前端重构丢失界面交互恢复/` 新增独立实施记录；
2. 在本总账填写实际修改、验证结果、记录链接和 Git 提交号；
3. 将状态改为“待业务审核”，不得直接标记“已验收”；
4. 业务负责人通过后，标记“已验收”并开始下一项。

## 4. 单项实施记录强制模板

每个编号的实施记录必须包含：

1. 编号、日期、分支、实施前后提交号和当前状态；
2. 旧分支产品基准：原页面、原组件、原按钮、原显示条件和原操作路径；
3. 改造前缺失证据：当前入口、弹框、字段或交互缺在哪里；
4. 本次范围与明确不改范围；
5. 界面、字段、API、数据库映射，明确是否只恢复现有字段和接口；
6. 实际修改文件及每个文件的职责；
7. 新旧组件、按钮、弹框和状态条件逐项对表；
8. 类型检查、自动化测试、静态检查及必要业务验证结果；
9. 遗留问题、风险和未验证内容；
10. 业务负责人审核结论、审核日期及 Git 提交号。

## 5. 完成定义

单项只有满足以下条件才能提交业务审核：

- 旧版对应界面、字段、组件、按钮和交互已经逐项核对；
- 当前 `dev` 拆分架构未被回退；
- 没有夹带其他清单项或无关重构；
- 必要类型检查和自动化验证通过；
- 已生成当日独立实施记录并回写本总账；
- 对未完成或无法验证的内容明确标记，不能写成已完成。
