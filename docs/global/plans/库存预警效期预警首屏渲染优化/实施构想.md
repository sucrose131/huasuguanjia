# 库存预警 / 效期预警页首屏渲染优化——实施构想

> 状态：有效方案（2026-09-07）
> 分支：feature/0907-inventory-quantity-alerts

## 一、需求与边界

- 用户：拥有库存模块权限、进入「库存预警 / 效期预警」页面的人员；
- 现状问题：后端返回不慢，但页面从数据到达列表可见约 5s。根因是两个预警页是全仓库业务页面里仅有的 `pagination:false` 大列表，共享引擎一次渲染全量行（本地 866 行 → 当前环境 1642 行，正式环境持续增长）；
- 范围：
  - 库存预警、效期预警两个接口恢复**服务端 SQL 真分页**（LIMIT/OFFSET + GROUP BY 统计），不再把全量匹配行搬进 Node 切片；
  - 两个页面 config 恢复默认分页 UI（20/50/100，默认 20）；
  - 共享引擎渲染瘦身：溢出 Tooltip 惰性化、单元格 displayCell 去重、行操作权限过滤缓存、重置按钮回第 1 页；
- 明确不做：方案 B（el-table-v2 虚拟滚动）、方案 D（列表请求缓存）、StatusTag 字典轻量化（字典已有模块级缓存，非瓶颈）、`.env` 数据库指向纠正（另行确认）。

## 二、界面与交互设计（业务已确认）

- 两个页面列表底部出现与库存查询一致的分页器（20/50/100），仓库 Tab、组织/状态/关键字筛选、摘要卡、操作列保持不变；
- 「全部」Tab 与各仓库 Tab 统计口径不变：全部 = 各仓库之和 = 当前筛选下列表条数；摘要随当前筛选（含选中仓库）口径展示，均不随页码变化；
- 列表顺序：库存预警由“无定义顺序”变为按（仓库、商品、SKU）确定性升序，翻页稳定。

## 三、字段—API—数据库映射

无新增表、字段、字典，无数据库结构变更。

| 页面/逻辑 | API 参数 | 表 | 字段 | 说明 |
| --- | --- | --- | --- | --- |
| 分页（两页） | `page` / `pageSize` | — | — | 沿用引擎既有参数；`pageSize` 钳制 1..100 |
| 返回 | `items / total / page / pageSize / warehouseCounts / summary` | — | — | `total`=筛选范围条数（非当前页条数）；`summary` 兼容既有键 `itemCount/totalAmount/warningCount` |
| 库存预警行 | `warning/safeQty/gapQty/purchaseQty` | hspsi_inventory_total s LEFT JOIN hspsi_inventory_alert_qty c ON (w,g,s) | `safe_qty/purchase_qty/inventory_qty` | SQL 派生：`warning = fact < COALESCE(safe,0)`，`gap = GREATEST(0, safe-fact)`，`purchase = COALESCE(c.purchase_qty, gap)`，与旧 JS 口径逐项等价 |
| 效期预警行 | `expiryStatus/remainingDays/alertDays` | hspsi_inventory_alert_period p JOIN hspsi_inventory_batch_total b ON (g,s,w,batch) | `end_day/alter_day/alter_type/inventory_qty/inventory_amount` | 剩余天数/效期状态沿用旧计算，`end_day` 走模型读取保证 Date 语义无时区漂移 |
| 金额 | `inventoryAmount/alertValue/summary.totalAmount` | — | `inventory_amount` | 字段名不变，全局金额拦截器按字段名脱敏行为不变 |

## 四、API 契约

- `GET /inventory/quantity-alerts`：新增支持 `page/pageSize`；`status` 参数合法值 `''|'0'|'1'`，非法抛 400「库存状态参数无效」；`warehouseId`/`orgId`/`keyword` 语义不变；
- `GET /inventory/expiry-alerts`：新增支持 `page/pageSize`；其余参数语义不变；
- 兼容性：返回新增 `page/pageSize` 字段，`items/total/warehouseCounts/summary` 结构与旧响应一致；种子脚本（已按 `{page,pageSize}` 调用）与前端引擎均兼容；
- 每个请求执行 2 条 SQL：页行查询（派生 + 过滤 + LIMIT/OFFSET）、统计查询（GROUP BY warehouse_id，不带仓库过滤 → warehouseCounts 稳定），选中仓库时 total/summary 取该仓库统计组（行按仓库互斥，等价旧逐行口径）。

## 六、验证与验收标准

1. 任一筛选下摘要、`total`、`warehouseCounts` 等于改动前全量口径且不随页码变化（含超页）；「全部」= 各仓库之和；
2. 页间切片连续、无重复（真库 1642 行逐页遍历校验通过）；
3. 金额权限口径不变；停用仓库不计入；非法状态 400；
4. 前端首屏渲染目标 < 1s、翻页/Tab < 300ms（浏览器实测项，见实施记录遗留）；
5. api/web typecheck 通过（api 侧存在与本次无关的既有 integrations spec 类型错误，见实施记录）、vitest 全绿。

## 七、遗留与风险

- `apps/api/.env` 指向 `host.docker.internal:13306/hspsi-prod`（含 hspsi-test 注释），与 AGENTS.md「本地仅连 127.0.0.1:3306/hspsi-dev」不一致——按业务侧指示本轮不改，验证均在当前 hspsi-prod 只读进行，纠正另行处理；
- 引擎改动面向 100+ 配置共享页面，需抽样回归（库存查询、库存盘点、采购订单、领用出库）。
