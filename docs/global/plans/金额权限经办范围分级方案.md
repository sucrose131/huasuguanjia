# 金额权限经办范围分级方案

> 状态：已实现（库存查询金额可见范围于 2026-09-07 完成合并回归修复），实施见 `docs/daily/2026-09-03/金额权限经办范围分级实施记录.md`、`docs/daily/2026-09-04/库存查询金额权限范围收口实施记录.md`、`docs/daily/2026-09-07/库存查询金额权限合并回归修复实施记录.md`
> 确认日期：2026-09-03
> 适用系统：华溯管家进销存
> 权限边界：仅扩展本地金额白名单的数据范围维度，不改 OA 接口、同步、审批、消息或回调

## 1. 需求与边界

现有金额白名单只有「无权限 / 仅查看 / 可编辑」三档能力，且"仅查看/可编辑"一律作用于数据范围内的所有单据。本次调整在能力之上新增一个正交维度「金额数据范围」，让可视与可修改都再分两档：

| 数据范围 | 含义 |
| --- | --- |
| 仅自己经办 | 只能看见（或修改）自己经办单据的金额信息 |
| 权限内全部 | 可以看见（或修改）权限内所有单据的金额信息 |

已确认口径（业务负责人，2026-09-03）：

- 「自己经办」= 单据 `created_by === 当前用户`。
- 「可编辑」同样分「自己 / 全部」两档。
- 存量白名单用户默认「自己经办」。
- 范围默认约束「单据」金额；商品档案成本价/售价等主数据仍由「查看能力」整体控制，不参与 own/all 分级。
- 库存查询为敏感库存货值入口：单位成本、库存金额及金额合计仅 `view·all`、`edit·all` 可见；`none`、`view·own`、`edit·own` 均脱敏。库存预警与效期预警暂维持原有主数据豁免口径。

固定边界：

- 金额范围是字段级授权，仍与既有组织/仓库数据权限取交集。「权限内全部」= 用户组织数据权限内的全部单据，不放大记录级数据范围。
- 编辑自动包含查看；「可编辑·自己」时查看范围同样收窄到「自己」。
- `admin` 与权限通配 `*` 不自动绕过金额白名单（沿用现状）。
- 白名单仍只绑定 `hspsi_sys_user.id`，不绑定 OA 人员、岗位、组织、部门。
- 用户停用或删除后，即使存在白名单记录也不生效（沿用现状）。

## 2. 现状核对

| 项 | 现状 |
| --- | --- |
| 白名单表 | `hspsi_sys_user_amount_access`：`user_id`（PK）、`can_view_amount`、`can_edit_amount`、`grant_reason`、审计字段；CHECK 约束 `edit⇒view` |
| 权限服务 | `amount-access.service.ts`：`forUser` / `assertCanEdit` / `saveForUser` / `maskFields`；`level ∈ {none, view, edit}` |
| 全局脱敏 | `amount-access.interceptor.ts`：无查看权时按 `GLOBAL_AMOUNT_FIELDS`（`amount-field-registry.ts`）对响应字段整体置空；`@RequireAmountEdit` 校验编辑能力 |
| 写入校验 | `purchase/sales/goods/inventory` 控制器通过 `@RequireAmountEdit` 或 `assertCanEdit` 拦截金额写入 |
| 前端状态 | `stores/auth.ts` 的 `amountAccess`（level/canViewAmount/canEditAmount），登录时读 `GET /auth/amount-access`；`moneyText` 依赖 localStorage 的 `hspsi_amount_access`（level），且 `null` 值已渲染为 `****` |
| 配置界面 | `SystemPage.vue` 用户列表「金额权限」列 + 独立弹框单选三档，写 `PUT /system/users/:id/amount-access` |

关键结论：现脱敏是"按字段名、不分单据归属"的全局置空。本次改造的核心是把"无查看权→全部置空"升级为"按记录归属、按档位"的脱敏。

## 3. 数据库变更

`hspsi_sys_user_amount_access` 新增一列：

```sql
ALTER TABLE `hspsi_sys_user_amount_access`
  ADD COLUMN `amount_scope` tinyint NOT NULL DEFAULT 1
    COMMENT '金额数据范围 1=仅自己经办 2=权限内全部',
  ADD CONSTRAINT `chk_user_amount_access_scope` CHECK (`amount_scope` IN (1, 2));
```

- `DEFAULT 1` 同时落地「存量默认自己经办」：`ADD COLUMN` 时存量行自动补 1，无需逐行 UPDATE。
- 不再新增表、不改字典、不改其他表字段。
- 迁移 SQL 落地文件（实施阶段创建）：`database/migrations/20260903_user_amount_access_scope.sql`。

## 4. 生效等级与判定规则

能力（`can_view_amount`/`can_edit_amount`）与范围（`amount_scope`）组合：

| 能力 level | 范围 scope | 查看金额范围 | 编辑金额范围 |
| --- | --- | --- | --- |
| none | — | 无 | 无 |
| view | own(1) | 自己经办单据 | 无 |
| view | all(2) | 权限内全部单据 | 无 |
| edit | own(1) | 自己经办单据 | 自己经办单据 |
| edit | all(2) | 权限内全部单据 | 权限内全部单据 |

范围与数据权限叠加后，最终可见 = 「金额范围」∩「组织/仓库数据范围」。

## 7. API 契约

### 7.1 `GET /auth/amount-access`

返回增加 `amountScope`：

```json
{
  "level": "none | view | edit",
  "canViewAmount": false,
  "canEditAmount": false,
  "amountScope": "own | all"
}
```

`canViewAmount`/`canEditAmount` 语义不变（仍是能力开关），`amountScope` 只参与"哪些记录"的判定。

### 7.2 `PUT /system/users/:id/amount-access`

请求增加 `amountScope`：

```json
{
  "level": "none | view | edit",
  "amountScope": "own | all",
  "grantReason": "业务负责人确认"
}
```

`level=none` 时删除白名单记录（`amountScope` 无意义、忽略）；`amountScope` 非法或缺失时返回 400。返回增加 `amountScope` 字段。

### 7.3 `GET /system/users`

用户列表返回增加 `amountScope`，供列表标签与弹框预填。

## 8. 脱敏与写校验设计（核心）

### 8.1 金额归属字段登记表

`amount-field-registry.ts` 新增「金额归属字段集合」`AMOUNT_OWNER_FIELDS`，登记标识记录创建人的字段名：

```ts
export const AMOUNT_OWNER_FIELDS: ReadonlySet<string> = new Set([
  'created_by', 'create_by', 'creator_id', 'creatorId', 'createdBy',
]);
```

「自己经办」判定：记录对象上存在以上任一字段且 `String(字段值) === String(当前用户ID)`（BigInt 经 API 序列化为字符串，比较统一转字符串）。

### 8.2 按记录脱敏 `maskAmountsByOwner`

在 `AmountAccessService` 新增方法，替代"全局置空"用于 `own` 档：

- 遍历响应树，携带"父级归属判定"向下递归：
  - 对象命中金额字段时，先看对象是否含归属字段：含 → 归属=当前用户则保留金额，否则置空；不含 → 继承父级判定。
  - 明细行通常不带归属字段，**继承父级判定**，避免"自己单据的明细金额被误脱敏"。
- 无归属字段的聚合结果（仪表盘合计等）默认置空（默认拒绝，无法证明属于当前用户）。
- `none` 档仍用现有 `maskFields` 全字段置空；`all` 档不解脱敏。

### 8.3 拦截器分档

`amount-access.interceptor.ts` 按 `access` 分派：

| 档位 | 行为 |
| --- | --- |
| none | `maskFields` 全字段置空（现状） |
| all | 放行（现状） |
| own | `maskAmountsByOwner` 按记录归属脱敏 |

`@RequireAmountEdit` 能力校验保持不变（先判有无编辑能力）。

### 8.4 写侧按记录断言

新增 `assertCanEditRecord(userId, ownerId)`：

- 无编辑能力 → 403（现状 `assertCanEdit` 语义）。
- 有编辑能力且 `amountScope === 'own'` 且 `ownerId !== userId` → 403 `当前账号只能编辑自己经办单据的金额`。

在 `purchase`/`sales`/`goods`/`inventory` 各金额写接口内，加载目标单据后调用该断言（owner 取单据 `created_by`），作为 `@RequireAmountEdit` 端点级校验之后的记录级兜底。前端隐藏不代替后端拦截。

### 8.5 前端配合

- `stores/auth.ts` 的 `AmountAccessState` 增加 `amountScope`，登录加载。
- `purchase-order.ts` 及各表单：own 用户对他人单据隐藏"编辑金额"入口（按 `row.created_by === user.id` 判断），避免"点了被 403"的无意义按钮。
- 金额显示：`moneyText` 已对 `null` 渲染 `****`，own 用户查看他人单据时后端返回 `null` 金额、前端自然显示 `****`；本轮统一各组件"能力级无权限→`****`"与"记录级脱敏→`null`→`****`"两路渲染，消除个别组件 `¥ ****` 的拼装瑕疵。

## 9. 边界与暂缓

- **商品主数据不参与 own/all**：`goods.costPrice/salePrice` 非"单据"、无经办归属，仍由 `canViewAmount` 整体控制；`view·own` 用户仍可看商品成本/售价，`none` 用户仍不可看。
- 导出与打印沿用页面同一金额口径（后端已脱敏，导出复用脱敏后数据）。
- 暂缓：无。按行隐藏"编辑金额"按钮作为本轮体验项一并完成，不留到二期。

## 10. 安全与风险控制

- 前端隐藏仅改善体验，后端拦截器脱敏 + `assertCanEditRecord` 是最终安全边界。
- 权限实时读取，不加长缓存；管理员改档后下一次敏感请求即生效。
- 归属比较统一 `String()` 化，规避 BigInt/Number 类型不一致导致的误判。
- 白名单管理与操作日志沿用现状（记录 old/new 的 level 与 scope）。
- OA 集成代码不引用金额权限服务，OA 同步表不保存金额范围。
