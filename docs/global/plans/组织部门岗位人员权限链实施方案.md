# 组织—部门—岗位—人员权限链实施方案

> 状态：全员基础账号、基础角色、多账套身份和授权组织已完成；岗位附加角色待业务配置
>
> 日期：2026-08-17
>
> 最终边界：OA 是人员身份源，进销存根据数据字典自动生成角色和授权组织；金额白名单始终由进销存手工审批维护

## 一、最终权限模型

账号的最终权限按以下顺序叠加：

`OA 员工有效 → 自动生成唯一登录账号和基础申请人角色 → 岗位字典叠加业务角色 → 授权组织中选择当前组织 → 独立金额白名单`

- OA 继续维护人员姓名、组织、部门、岗位、上级关系和启停状态。
- OA 同步自动创建/更新本地登录账号，并根据数据字典全量刷新本地角色和授权组织。
- 所有 OA 有效员工通过 `oa_default_staff_role` 自动获得基础申请人角色；未配置岗位映射时仍可提交采购申请和领用申请。
- “岗位→角色”只叠加采购、仓库、财务等额外业务角色，禁止通过岗位名称猜测权限。
- 同一自然人在多个 OA 账套中只使用一个手机号登录账号，并按单据所属账套选择正确的 OA 员工身份。
- OA 人员失效时停用本地账号，并清除 OA 生成的角色和组织授权。
- 同一会话每次只选中一个“当前组织”，业务查询和写入只能作用于当前组织。
- `admin` 等不关联 OA 人员的系统账号保留本地管理入口；普通 OA 人员的身份、角色和授权组织不能在用户管理中手工改写。
- `hspsi_sys_user_amount_access` 不属于 OA 同步事务，OA 同步不会授予、修改或撤销金额权限。

### 2.2 数据字典

| 字典类别编码                | `dict_name`                | `dict_value`                                     | 用途                                 |
| --------------------------- | -------------------------- | ------------------------------------------------ | ------------------------------------ |
| `oa_default_staff_role`     | 全员基础申请人             | `oa-staff-applicant`                             | 所有有效员工自动获得基础申请权限     |
| `oa_position_role_mapping`  | OA 岗位稳定 `outer_ref_id` | 本地 `hspsi_sys_role.code`                       | 一个岗位可叠加多个本地角色           |
| `oa_org_authorization_rule` | 规则显示名                 | `PRIMARY_ORG` / `SECONDARY_ORG` / `POSITION_ORG` | 控制 OA 哪些组织关系生成本地授权组织 |

当前安全初始值：

- 组织授权来源启用主组织、兼任组织、岗位所属组织。
- 全员基础申请人角色已配置采购申请、领用申请菜单。
- 岗位附加角色映射不预置任何数据；必须由业务负责人确认后配置。
- 旧 `role_scope_type` 字典已停用。

## 三、字段—API—数据库映射

| 页面/业务字段 | API 字段                      | 数据库来源                                                   | 写入时机                                       |
| ------------- | ----------------------------- | ------------------------------------------------------------ | ---------------------------------------------- |
| 主组织        | `orgId`                       | `hspsi_sys_user.org_id`                                      | OA 人员同步                                    |
| 主部门        | `deptId`                      | `hspsi_sys_user.dept_id`                                     | OA 人员同步                                    |
| 岗位          | `positionId/positionName`     | `hspsi_basic_staff.post_id` → `hspsi_basic_position`         | OA 同步                                        |
| OA 员工身份   | 按单据账套内部解析            | `hspsi_sys_user_oa_staff` → `hspsi_basic_staff`              | OA 同步；一个账号允许多个账套身份              |
| 本地角色      | `roleIds/roleNames`           | `hspsi_sys_user_role`                                        | 基础角色自动授予，岗位角色按字典叠加            |
| 授权组织      | `authorizedOrganizations[]`   | `hspsi_sys_user_authorized_org` → `hspsi_basic_organization` | OA 同步按 `oa_org_authorization_rule` 全量刷新 |
| 当前组织      | `currentOrgId/currentOrgName` | Redis `session:{sid}.currentOrgId`                           | 登录默认主组织，用户切换时更新                 |
| 金额查看/编辑 | `canViewAmount/canEditAmount` | `hspsi_sys_user_amount_access`                               | 本地管理员手工审批配置                         |

BigInt ID 通过 API 均按字符串传输。

## 四、API 与会话逻辑

| API                                  | 用途                                   | 后端约束                                               |
| ------------------------------------ | -------------------------------------- | ------------------------------------------------------ |
| `POST /api/auth/login`               | 登录并选中默认当前组织                 | 非管理员必须有启用角色和至少一个授权组织               |
| `GET /api/auth/session`              | 返回实时角色、菜单、授权组织和当前组织 | 不信任 JWT 中的历史权限快照                            |
| `POST /api/auth/switch-organization` | 切换当前组织                           | `orgId` 必须在用户当前授权组织列表中，成功后更新 Redis |
| OA 组织人员同步                      | 建号并刷新业务权限                     | 全员基础角色+岗位附加角色；聚合多账套授权，不访问金额白名单 |

后端 Prisma 统一拦截所有带 `org_id` 或 `organization_id` 的业务读写，非超级管理员只能访问 Redis 会话中的单一 `currentOrgId`。`org_id=0` 的集团共享商品保留可见。

## 五、页面规则

- 顶部导航增加“当前组织”选择器；仅展示 `authorizedOrganizations`，不能输入任意组织 ID。
- 只有一个授权组织时选择器禁用；切换成功后重载当前业务页面。
- 角色管理仅维护菜单和操作权限，不再出现“默认数据范围”。
- 用户管理列表展示授权组织；OA 同步账号不提供本地身份、角色和组织编辑入口。
- 金额权限仍通过用户行内“金额权限”独立操作，不随角色或 OA 岗位自动变化。
