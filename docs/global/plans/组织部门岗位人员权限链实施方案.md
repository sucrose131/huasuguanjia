# 组织—部门—岗位—人员权限链实施方案

> 状态：已实施并完成本地验收
> 日期：2026-08-17
> 边界：OA 维护身份资料，华溯管家维护本地角色、数据范围和金额白名单

## 一、最终权限关系

账号的最终权限按以下顺序叠加：

`OA账号可用 → 组织/部门/岗位/人员身份有效 → 本地角色菜单权限 → 角色数据范围 → 独立金额白名单`

- OA 同步组织、部门、岗位、人员及人员主组织关系；
- 本地系统用户通过 `staff_id` 显式关联一名 OA 人员；本地测试账号允许暂不关联；
- 关联 OA 人员后，所属组织和部门由人员主关系反算，前端不可改写；岗位必须启用且属于人员当前主组织或部门；
- OA 人员停用、删除、岗位缺失或主组织不完整时，关联的本地账号被停用；
- OA 同步不自动增加角色、菜单权限、指定组织范围或金额白名单；
- 金额白名单仍独立绑定本地用户，默认拒绝。

## 二、数据库映射

| 页面/权限含义 | API 字段 | 数据库表 | 字段 |
| --- | --- | --- | --- |

## 三、五类数据范围

| 值 | 规则 |
| ---: | --- |
| 1 | 全部启用组织 |
| 2 | 本组织及全部下级组织 |
| 3 | 本组织 |
| 4 | 本组织及手工指定组织 |
| 5 | 本组织内本人创建的业务单据；本组织基础资料仍可读取 |

后端在请求会话中实时读取账号、启用角色和组织范围，不再信任 JWT 中的历史权限快照。所有带 `org_id` 或 `organization_id` 的 Prisma 读写统一套用组织范围；跨组织详情、修改和删除均由后端拒绝。`org_id=0` 的全集团共享商品继续可见。

## 四、页面规则

用户管理增加：

- 关联 OA 人员；
- 所属岗位；
- 指定组织范围；
- 列表和详情中的人员、岗位来源展示。

同名人员下拉项使用“姓名 · 岗位 · 公司”区分。选中人员后自动带出并锁定公司、部门和岗位。未关联人员的本地测试账号仍按手工组织、部门和角色运行。

## 五、验收标准

- 组织、部门父子关系、人员主组织、岗位、角色和指定组织关系审计均为 0；
- 同组织列表和详情可访问；跨组织详情、修改、删除均失败；
- 组织切换不能看到未授权仓库；
- 集团共享商品不因组织隔离而消失；
- 关联人员时伪造组织、部门无效，后端以 OA 主关系为准；
- 关联 OA 人员不会自动获得金额权限；
- OA 人员停用后，本地账号无法继续登录。
