# 直接领用出库跨组织仓库改造计划

> 状态：已业务确认，实现完成
> 日期：2026-08-28
> 关联需求：领用管理（领用出库单「直接领用出库」）
> 关联文档：`docs/daily/2026-08-28/直接领用出库跨组织仓库改造实施记录.md`

## 1. 需求与边界

- **用户**：拥有多个授权组织（`authorizedOrganizations`）的账号，含超管。
- **入口**：领用出库单页面 → 「直接领用出库」新增弹框（`RequisitionOutputForm.vue` 的 `directOutput` 模式）。
- **目标**：仓库下拉展示当前账号**全部授权组织**下的领用类仓库；选仓库后**反推组织**，并据此筛部门、筛人员，替代原先“固定取登录人 OA 固定所属组织”的口径。
- **范围**：仅「直接领用出库」；领用申请单、领用出库（非直接）、领用退回单等其它入口**保持不变**。
- **拦截**：所选仓库组织不在授权范围 → 后端拒绝（禁止仅前端过滤）。
- **结果**：保存成功自动反向生成已通过的领用申请单并确认出库扣库存（既有 `saveDirectOutput` 逻辑不变）。

## 2. 交互设计（仅直接领用出库）

```text
选仓库(跨授权组织) → 反推组织(warehouse.org_id) → 按组织筛部门 → 按部门筛人员(手动选)
```

1. **仓库下拉**：授权组织范围内、`warehouse_type in [4..12, 14, 15, 16]`、启用仓库；选项显示「仓库名（组织名）」防重名。（14 固定资产库、15 低值易耗品库、16 仓储库于 2026-09-01 业务确认纳入领用范围。）
2. **选仓库后**：
   - `orgId` = 仓库 `org_id`；
   - 部门自动带出：仓库 `dept_id>0` 且该部门在该组织启用 → 直接选中；否则该组织只有一个启用部门 → 自动选中；否则留空手选；
   - 人员按部门筛（`org_type=2`），并保留组织直属人员（`org_type=1`）兜底，手动选择。
3. **部门切换**：重新按部门刷新人员（保留跨组织仓库列表，避免用户被困在当前组织）。
4. 未选仓库前，部门、接收人下拉禁用。

## 3. 字段—API—数据库映射

| 页面字段 | 业务含义 | 数据来源 | API | 数据库字段（写入） |
| --- | --- | --- | --- | --- |
| 仓库 warehouseId | 领用仓库 | 授权组织内领用类仓库 | `GET /requisitions/direct-output-options`（返回 raw.orgId/deptId） | `hspsi_draw_approve_output.warehouse_id` / `.warehouse_id`(申请) |
| 组织 orgId（隐藏） | 单据组织 | 由仓库反推 | — | `org_id`（出库/申请） |
| 领用部门 deptId | 领用部门 | 该组织启用部门 | `GET /requisitions/application-form-options?orgId=` | `dept_id`（出库/申请） |
| 领用接收人 receiverId | 领用人（手动选） | 该部门+组织直属人员 | `GET /requisitions/application-form-options?orgId=&deptId=` | `applicant_id`(申请) / `receiver_id`(出库) |

- 数据库：**无新增表、字段、索引或字典**。
- 接口：新增 `GET /requisitions/direct-output-options`；`application-form-options` 增加可选 `deptId` 参数。

## 4. API 与权限设计

- `GET /requisitions/direct-output-options`：按当前登录人 `orgId + authorizedOrganizations` 过滤组织，返回领用类启用仓库；非超管同时受 `PrismaService` 数据范围中间件二次强制。
- `application-form-options`：`deptId` 传入时人员 = 该部门成员（`org_type=2`）+ 组织直属（`org_type=1`）；不传维持原“组织直属 + 全部部门成员”口径。
- 保存校验：`saveDirectOutput` 新增后端组织授权校验（`assertAuthorizedOrganization`）——所选 `orgId` 必须 ∈ 当前账号授权组织范围（超管跳过）；原有 `validateApplicationReferences`（仓库属组织、部门属组织、接收人归属）保持不变。

## 5. 验收标准

1. 直接领用出库仓库下拉包含多个授权组织的仓库，且显示组织名。
2. 选带部门仓库（如 org 9 行政-办公耗材仓）→ 部门自动带出，人员按部门筛。
3. 选无部门仓库（如 org 2 华爱办公耗材库）→ 部门留空手选，人员随部门切换刷新。
4. 越权组织保存被后端拒绝。
5. 其余页面（领用申请单、非直接出库、退回单）行为不变。

## 6. 遗留与风险

- 仓库 `dept_id` 仅作“自动带出”提示；部门最终以组织部门表为准，`dept_id=0` 不阻塞流程。
- 直接领用出库仍要求部门必填（既有后端约束，本次不放开“组织级无部门领用”）。
