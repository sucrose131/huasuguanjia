## 1. 需求与边界

- 用户：领用申请单的创建人。
- 入口：领用管理 → 领用申请单列表。
- 要完成的事：对「申请中 / 审批中」的领用申请，增加与采购申请相同的 **终止** 和 **撤回**。
- 允许操作：创建人本人；单据 `status=1` 且 `approve_status=0`；终止与撤回同时显示。
- 必须拦截：非创建人；非审批中；OA 正在推送（`PENDING_PUSH`）；先出库后审批（列表 `reverseGenerated=true`，出库单 `generation_key` 以 `direct-requisition-output:` 开头）。
- 权限：新增操作权限授给全部启用且未删除的角色；没有领用申请页面权限仍进不了列表；按钮仍只对创建人显示。后端以登录用户 `created_by` 做最终校验。

保存、提交、关闭：本次不改新建/提交表单。失败时本地保持审批中（已推 OA 且远程撤销失败）。取消确认框不发请求。

本次范围：领用申请列表按钮、两个 API、OA 远程撤销、系统内待办关闭、OA 取消回调与采购对齐、审批中不可再编辑删除。

本次不包含：采购接口；给 reverseGenerated 做本系统终止/撤回（含终止后生成退回）；其它单据的终止/撤回。

## 2. 界面与交互

页面：现有领用申请单列表，不新增字段、不改列。

操作列在「查看 / 办理出库」之后、「通过 / 驳回」之前增加：

| 按钮 | 样式 | 确认标题 | 确认文案 |
| --- | --- | --- | --- |
| 撤回 | warning | 撤回审批 | 撤回后单据将回到草稿，可修改后重新提交，是否继续？ |
| 终止 | danger | 终止审批 | 终止后审批将结束，且不能再编辑提交，是否继续？ |

显示条件（前端与后端一致）：

- 当前登录人 = 行 `createdBy`
- `status === 1` 且 `approveStatus === 0`
- `reverseGenerated !== true`

配套收紧，避免审批中同时出现编辑/删除与撤回：

- 编辑、删除仅草稿：`status === 0` 且 `approveStatus === 0`，且限创建人。
- 通过、驳回、重新提交 OA 条件不变。
- reverseGenerated 仍只能走现有通过/驳回（含已通过后再否决并生成退回草稿）。

无权限、非创建人、非审批中：按钮不出现。接口被误调用时返回明确错误，不改单据。

| 页面操作 | 业务含义 | API | 权限 | 表 | 写入字段 | 字典 | 写入时机 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 终止 | 结束审批，不能再编辑提交 | `POST /requisitions/applications/:id/terminate` | `requisitions:applications:terminate` | `hspsi_draw_approve` | `approve_status=3`，`status` 保持 1，`approve_comment=创建人终止审批`，`approve_by`/`approve_date` | `requisition_approval_status` 的 `3`（已取消） | OA 撤销成功后或无需 OA 时 |

BigInt 主键 `draw_id` 经 API 以字符串传输。创建人取 `created_by`，不用 `applicant_id`。

## 4. API 与事务

路径：

- `POST /requisitions/applications/:id/terminate`
- `POST /requisitions/applications/:id/withdraw`

权限由请求最后一段推断，与采购 terminate/withdraw 相同，无需改推断规则。

事务与失败：

1. 行锁 `hspsi_draw_approve`。
2. 校验存在、创建人、审批中、非 reverseGenerated。
3. 若 OA `PENDING_PUSH`：拒绝，提示稍后重试。
4. 若借用且 OA 为 `RUNNING`/`BACKTOSTART`：先 `dealProcess(operateType=cancel)`。OA 失败则抛错，本地仍审批中。OA 已撤销视为成功。
5. 无实例、`PUSH_FAILED`、或直接领用（不推 OA）：只改本地。
6. 终止写 `approve_status=3`；撤回回草稿；关闭 `draw_approve` 待办；有 OA 实例则标 `CANCELED`。
7. 已终止再终止、已撤回再撤回：幂等成功。撤回时若回调已抢先写成 `3`，仍落成草稿。

OA 取消回调（相对现状的变更）：

- 现状：非 PASSED（含 CANCELED）写成 `approve_status=2` 且 `status=0`（等同驳回）。
- 目标：与采购一致。`CANCELED` → `approve_status=3` 且 `status` 保持 1；本地已是撤回草稿则跳过单据落账。
- reverseGenerated 的 CANCELED 仍生成领用退回草稿（物资已出，不能只改状态）。本系统列表不提供对该单的终止/撤回。

并发：以行锁为准。组织范围仍按登录身份，不信任前端组织 ID。

## 6. 验收标准

- 创建人在普通审批中单据上同时看到终止、撤回；他人看不到。
- reverseGenerated 行看不到终止、撤回；接口调用被拒绝。
- 终止后审批状态为已取消/已终止口径（`3`），不能再编辑提交。
- 撤回后为草稿，单号不变，可编辑再提交。
- 直接领用审批中：终止/撤回成功后，审批待办关闭。
- 借用且 OA 运行中：先撤 OA；OA 失败则页面报错，单据仍为审批中。
- `PENDING_PUSH` 提示稍后重试。
- 审批中不再出现编辑、删除；草稿创建人仍可编辑删除。
- 权限 SQL 在目标库执行后，有页面权限的创建人才能看到按钮。
- 单测覆盖上述拦截与回调；关键路径做浏览器点击验收。
