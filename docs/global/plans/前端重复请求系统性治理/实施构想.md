# 前端重复请求系统性治理实施构想

> 状态：已实施，待业务验收  
> 日期：2026-08-27

## 1. 需求与范围

- 用户：所有使用 Web 管理端的业务人员。
- 入口：采购、销售、库存、生产、领用、基础资料、系统管理、报表等列表页面。
- 目标：页面进入以及点击查看、编辑、配置、跨单据操作时，不再因共享页面调度产生重复接口请求。
- 保留规则：保存、提交、审批、撤销、删除等真实业务数据变更成功后，仍刷新当前列表。
- 本次不调整页面布局、表单字段、按钮权限、业务状态、API 契约、数据库表结构和数据字典。

## 2. 交互设计

| 操作 | 页面结果 | 列表刷新 |
| --- | --- | --- |
| 查看、编辑、配置 | 打开原有组件和弹框 | 不刷新 |
| 新增 | 打开原有组件和弹框 | 打开时不刷新；保存成功后刷新 |
| 跨单据跳转 | 进入目标页面并打开原有弹框 | 不刷新离开的页面 |
| 提交、审批、撤销、删除等 | 保留原确认框和成功提示 | 成功后刷新 |
| 自定义操作弹框 | 关闭不刷新；真正完成后刷新 | 按完成事件刷新 |

## 3. 字段、API 与数据库映射

本次没有新增或变更业务字段。已有页面字段、API 字段和数据库字段映射全部保持不变。

| 调整对象 | 数据来源 | 数据写入 | 变化 |
| --- | --- | --- | --- |
| 业务列表 | 原列表 GET API | 无 | 取消只读操作后的重复 GET |
| 单据详情 | 原详情 GET API | 无 | 同一次打开弹框只通过网络加载一次 |
| 组织/单位/仓库/供应商/字典 | 原 options/dictionaries GET API | 无 | 同用户、同参数复用请求结果；任意写请求后失效 |

数据库结论：不改表、不改字段、不改索引、不改字典。

## 4. 实施方案

1. 共享业务页面记录弹框打开和跨页导航交互；只有未发生界面跳转的业务动作才自动刷新列表。
2. 采购申请、采购订单由共享页面统一加载完整详情，表单不再二次请求。
3. 其他深链场景将已加载详情一次性交给表单消费，不建立通用业务详情缓存。
4. 组织、单位、仓库、供应商、人员和字典等只读参考数据按用户身份与查询参数缓存；任何 POST/PATCH/PUT/DELETE 前清空。
5. 保留 `router-view` 按完整路由重建页面，移除通用页面旧实例对路由参数的重复监听加载，确保只有一个加载生命周期。

## 5. 验收标准

- 查看、编辑、配置和跨页导航不触发原列表额外刷新。
- 采购申请、采购订单普通打开与深链打开的详情网络请求均为一次。
- 参考数据在同一用户、同一参数下不重复请求，写操作后能重新加载。
- 通用路由页面切换只加载目标页一次。
- 原有弹框、按钮、字段和保存后刷新行为保持不变。
- Web 类型检查、自动化测试和浏览器关键路径验收通过。
