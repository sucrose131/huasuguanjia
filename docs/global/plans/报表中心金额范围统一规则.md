# 报表中心金额范围统一规则

## 已确认需求与边界

报表中心只有「具备金额查看能力 + 权限内全部」才显示金额。「无权限」「仅查看·自己」「可编辑·自己」均不显示任何报表金额，即使记录由本人经办。金额范围缺失时默认拒绝。全部仍受既有组织数据范围限制，不代表跨越组织权限。

非金额列、筛选、菜单权限维持现状；不改变普通业务单据的自己经办规则，也不改变库存管理下库存查询的金额规则。界面、表格和导出按钮复用，不新建组件或重做页面。

## 字段及接口映射

|用途|已有字段/接口|处理|
|---|---|---|
|查看能力|hspsi_sys_user_amount_access.can_view_amount / can_edit_amount → canViewAmount|编辑能力按现有服务包含查看|
|范围|hspsi_sys_user_amount_access.amount_scope → amountScope|1=own，2=all；仅all放行报表金额|
|组织范围|现有登录身份与数据权限约束|沿用业务接口，不扩大|
|报表读取上下文|业务列表GET参数 amountContext=report|只读请求参数，不入库；后端根据真实白名单执行更严格脱敏|
|金额列|ReportPage中kind=money的列|单元格、合计、CSV统一校验；不可见用¥ ****而非0|

无新增数据库表、字段、索引或字典。报表当前由21个配置复用一个页面，使用原业务列表接口、前端聚合、CSV导出；无独立图表、钻取详情弹框或打印接口。浏览器打印使用当前已脱敏页面。

## 实施方案

1. 逐项清点21张报表及其数据源，区分10张金额报表与11张非金额报表。
2. 报表所有列表读取携带上下文；后端统一金额拦截器优先执行报表规则，覆盖本人单据和库存数据豁免。标记只能收紧，不能提权。去掉标记恢复的是原有单据接口的本人权限，并不取得他人金额；不得为了禁止报表显示而取消用户合法单据权限。
3. 抽取报表专属金额策略，复用现有页面。行金额、统计卡片、导出一致；空值和不完整聚合不兜成真实0。保留真实0和小数。
4. 覆盖五类权限以及缺失范围、空值、本人记录、合计、CSV、权限变化；验证普通单据和库存查询原规则不变。
5. 浏览器逐张打开报表并记录结果，接口读取核对；未实测场景明确标记，不以单元测试替代浏览器结论。

## 安全及交付限制

不修改授权数据来放宽权限；不修改数据库结构或字典；不提交或推送Git。真实环境权限变化后的数据重载须清理旧报表缓存，页面权限不足时必须立即掩码。
