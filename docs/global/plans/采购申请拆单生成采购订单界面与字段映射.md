# 采购申请拆单生成采购订单界面与字段映射

> 当前阶段：前后端业务逻辑已实现，待业务负责人最终验收。

## 1. 页面入口

采购申请审核通过后，在列表“更多”菜单展示：

- 整单生成
- 选品生成
- 关联订单
- 操作记录

界面遵循 `docs/global/standards/Element Plus Table表格样式归档.md`：列表使用斑马纹和固定操作列；生成明细使用带边框、多选、稳定 `row-key`、金额右对齐和固定表头。

## 4. 当前API

- `GET /api/purchase/applications`：返回申请列表及只读生成进度计数。
- `GET /api/purchase/applications/:id`：返回申请明细、有效订单映射和关联订单列表。
- `POST /api/purchase/applications/:id/generate-order`：按整单或选品方式生成一张采购订单。
- `GET /api/base-data/vendors/options`：供应商下拉。
- `GET /api/base-data/organizations/options`：组织名称。
- `GET /api/base-data/departments/options`：部门名称。
- `GET /api/base-data/warehouses/options`：仓库名称。
- `GET /api/base-data/units/options`：单位名称。
- `GET /api/dictionaries/purchase_order_status`：采购订单状态。
- `GET /api/goods/:id`：商品与SKU展示信息。

## 5. 生成接口契约与事务规则

请求字段：

- `generationMode`：`all`（全部待生成明细）或 `partial`（本次勾选明细）。
- `vendorId`：本张采购订单供应商ID，必填。
- `details[].applicationDetailId`：采购申请明细ID。
- `details[].totalAmount`：用户确认的该明细采购总金额，必须大于0且最多2位小数。

后端在同一事务中完成：

1. 锁定并确认采购申请已审核通过；
2. 校验组织、部门、仓库、供应商和明细归属；
3. 锁定申请明细并检查有效采购订单映射；
4. 以 `总金额 ÷ 申请数量` 四舍五入到2位计算采购单价；
5. 创建采购订单、采购订单明细和单据追溯关系；
6. 依靠 `source_application_detail_id` 唯一索引及事务校验阻止重复生成。

整单生成必须包含提交时全部尚未生成的明细；并发状态变化时返回冲突，要求刷新。采购订单删除成功时清空其明细来源映射，原申请明细恢复可生成；不满足现有删除条件的采购订单不能释放映射。采购申请审核通过只更新审批状态，不再自动生成零供应商、零金额采购订单。
