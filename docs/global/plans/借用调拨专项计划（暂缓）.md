# 借用调拨专项计划（暂缓）

> 状态：暂缓，不进入当前开发范围  
> 编制日期：2026-08-04  
> 恢复条件：业务规则确认并单独批准实施

## 1. 暂缓说明

当前阶段不新增借用调拨功能，不修改现有普通调拨的流转和库存权限。

现有普通调拨继续保持：A 仓调拨物资至 B 仓并确认入库后，B 仓获得完整处置权限，可以领用、销售、报损或再次调拨至 C 仓等其他仓库。

以下内容全部移出当前库存改造计划：

- 调拨类型中的“借用调拨”；
- 预计归还日期；
- 反向归还调拨单；
- 借用库存余额；
- 借用物资处置权限拦截；
- 借用逾期提醒和异常处置。

## 2. 预留业务定义

借用调拨表示物资只改变物理所在仓库，不授予借入仓库完整处置权限：

```text
A仓 --借出--> B仓
B仓 --归还--> A仓
```

借用物资进入 B 仓后：

- 只能归还至原调出 A 仓；
- 禁止调拨至 C 仓或其他第三方仓库；
- 禁止销售、领用、报废、报损和普通直接出库；
- 归还单必须关联原借用调拨单；
- 借用调拨必须填写预计归还日期。

调拨类型是单据级属性，整单明细采用同一类型，不支持按明细行混用普通调拨与借用调拨。

## 3. 后续建议数据模型

调拨单头预期增加：

```text
transfer_type           ordinary / borrow
expected_return_date    预计归还日期
source_transfer_id      归还单关联的原借用调拨单
```

借用调拨需要独立的借用余额或受限库存记录：

```text
原借用调拨单及明细
原调出仓库
当前借入仓库
商品、SKU、批次
借用数量
已归还数量
未归还数量
预计归还日期
借用状态
```

不能只在调拨单上增加类型字段。若 B 仓原有 100 件自由库存，并从 A 仓借入 20 件，则 B 仓物理库存为 120 件，但自由处置库存仍只有 100 件。销售、领用、报损和普通调拨都必须排除借用受限数量。

## 4. 后续流转设计

建议状态：

```text
草稿
待审批
待借出
借用中
部分归还
已归还
已逾期
已作废
```

归还单只能从原借用调拨单执行“生成归还单”：

- 调出仓库自动设为原借入 B 仓；
- 调入仓库自动设为原调出 A 仓；
- 自动关联原借用调拨单；
- 自动带出未归还商品、SKU、批次和数量；
- 仓库方向不可修改；
- 归还数量不得超过未归还数量。

## 5. 后续必须覆盖的拦截点

借用功能启用后，以下业务均需接入受限库存校验：

- 普通库存调拨；
- 销售出库；
- 领用出库；
- 报损、报亏及报废；
- 通用直接出库；
- 生产领料；
- 其他可能扣减借入仓库存的业务。

保存阶段进行基础校验，提交审批和最终确认过账阶段重新校验。确认阶段需通过数据库事务和库存行锁防止并发超额使用。

## 6. 恢复开发前待确认事项

1. 是否支持部分归还和多次归还；
2. 归还调拨单是否需要审批；
3. 预计归还日期到期后是仅标记逾期，还是发送提醒；
4. 借用期间发生损坏、丢失时采用什么异常处置流程；
5. 借用物资能否跨批次归还或使用替代品归还；
6. 借用关系按商品、SKU、批次还是单件资产追踪；
7. 借用固定资产是否必须一物一码；
8. 历史普通调拨是否需要迁移调拨类型，默认值是否统一为普通调拨。

## 7. 后续验收方向

- 借入数量不能被任何非归还业务消耗；
- 归还目标仓库只能是原调出仓库；
- 普通库存和借用库存即使商品、SKU、批次相同也能正确区分；
- 支持的归还方式不会超过未归还余额；
- 全部归还后借用关系正确闭环；
- 普通调拨逻辑不因借用功能启用而发生回归。
