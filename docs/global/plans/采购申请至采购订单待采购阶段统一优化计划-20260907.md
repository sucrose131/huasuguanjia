# 采购申请至采购订单待采购阶段统一优化计划

> 制定日期：2026-09-07  
> 适用范围：采购申请、采购订单生成、待采购订单编辑、删除后重新生成、采购付款及相关待办  
> 当前代码基线：`9b8a104`  
> 当前阶段：产品方案已确认，代码实施与自动化验证已完成，等待浏览器业务验收

## 一、计划目标

在不重做现有采购模块、不改变已经通过 OA 审批的采购需求事实、不新增第二套采购流程的前提下，统一明确采购申请到采购订单开始采购之前的产品规则。

本次优化的核心目标如下：

1. 采购申请准确记录申请身份、成本归属、目标仓库和收货责任；
2. 采购申请审批通过后，采购人员可以整单生成或选品生成采购订单；
3. 采购人员可以根据实际采购情况填写实际采购数量和采购金额；
4. 采购订单生成后、开始采购前，允许修改采购执行信息；
5. 已经经过审批的采购需求信息保持只读，不因采购订单编辑而被改变；
6. 待采购订单删除后，释放原采购申请明细，使其可以再次生成采购订单；
7. 点击“开始采购”后锁定订单，后续只能通过付款、入库、退货等正式业务操作继续处理；
8. 全过程继续叠加菜单操作权限、组织数据权限和金额白名单权限。

## 二、统一业务链路

```text
创建采购申请
→ 保存草稿
→ 提交 OA 审批
→ 审批中可撤回并恢复草稿
→ OA 审批通过
→ 整单生成 / 选品生成采购订单
→ 采购人员完善采购执行信息
→ 保存为待采购订单
→ 点击开始采购
→ 订单锁定
→ 付款 / 到货 / 入库 / 退货 / 退款
```

采购订单在“待采购”和“采购中”之间以“开始采购”作为正式业务边界：

```text
待采购：允许按规则修改、允许在满足条件时删除
开始采购：执行最终校验并生成正式待办
采购中及以后：禁止修改原订单，禁止删除原订单
```

## 三、采购申请需求

### 3.1 申请身份字段

| 字段         | 产品规则                                                                   |
| ------------ | -------------------------------------------------------------------------- |
| 申请人       | 自动显示当前登录账号对应的员工中文姓名，不显示“系统自动生成”或手机号       |
| 推送 OA 组织 | 从申请人在 OA 中的有效多组织身份中选择，决定本次审批由哪个 OA 组织身份发起 |
| 申请部门     | 随所选 OA 组织身份自动带出，表示申请人的 OA 部门，不允许手工随意选择       |

### 3.2 成本及收货字段

| 字段         | 产品规则                                                             |
| ------------ | -------------------------------------------------------------------- |
| 成本承担组织 | 从当前账号已授权的数据组织中选择，表示本次采购成本由哪个组织承担     |
| 目标仓库     | 只显示成本承担组织下已启用、未删除且与商品分类仓库类型匹配的具体仓库 |
| 收货人       | 只显示成本承担组织下具有有效 OA 员工关系和进销存账号的人员           |

字段之间的约束关系：

```text
当前账号 OA 身份 → 推送 OA 组织 → 申请部门

当前账号组织数据权限 → 成本承担组织 → 目标仓库
                                      → 收货人

商品分类 → 仓库类型 → 成本承担组织下的具体仓库
```

切换成本承担组织时，必须清空原目标仓库、原收货人以及不再适用的采购明细，再加载新组织下的候选数据。

### 3.3 商品选择规则

采购申请和采购订单创建阶段不按当前库存数量限制商品。

可选商品的判断关系为：

```text
成本承担组织已经建立某种类型的仓库
→ 仓库类型已经映射某个商品分类
→ 商品分类下的启用商品和 SKU 可以被选择
```

库存数量只在实际出库、占用或其他库存执行环节参与校验，不能错误用于限制采购申请或采购订单创建。

### 3.4 草稿、提交和撤回

- 新建采购申请可以保存为草稿；
- 草稿只能由申请人本人修改、提交或删除；
- 草稿中的 OA 组织、成本承担组织、仓库、收货人、原因和采购明细均可修改；
- 提交 OA 审批后，采购申请原单锁定；
- OA 审批中的人工采购申请可以由申请人撤回；
- 撤回成功后恢复为草稿，可以修改并重新提交；
- OA 已审批通过的申请不能按“审批中撤回”处理；
- 生产缺料自动生成的采购申请不得按普通人工申请方式撤回和编辑。

## 四、采购申请生成采购订单

### 4.1 生成方式

采购申请 OA 审批通过后，具有相应操作权限的采购人员可以选择：

1. **整单生成**：将该申请所有尚未生成的明细合并生成一张采购订单；
2. **选品生成**：勾选部分尚未生成的采购明细生成采购订单；
3. **关联订单**：查看当前采购申请已经生成的采购订单。

一张采购申请允许分多次、生成多张采购订单，但同一条申请明细不能同时存在于多张有效采购订单中。

### 4.2 申请数量与实际采购数量

采购申请数量和实际采购数量是两个不同的业务口径：

| 数量         | 含义                                                       | 是否允许采购人员修改 |
| ------------ | ---------------------------------------------------------- | -------------------: |
| 申请数量     | 申请人经过 OA 审批确认的原始需求数量                       |         否，只读保留 |
| 实际采购数量 | 采购人员根据包装、供应商起订量和实际采购情况确定的执行数量 |                   是 |

整单生成或选品生成时，采购人员可以填写本次实际采购数量。实际采购数量可以与申请数量不同，但必须为正整数。

### 4.3 金额规则

- 采购人员填写明细采购总金额；
- 系统按照“明细总金额 ÷ 实际采购数量”反算采购单价；
- 金额最多保留两位小数；
- 金额必须大于零；
- 是否能查看和修改金额，继续由现有金额白名单控制；
- 无金额查看权限时统一显示为 `¥****`，不能回退显示为 `¥0.00`；
- 无金额编辑权限时，不能通过前端、接口或修改请求绕过限制。

## 五、采购订单生成后、开始采购前的编辑规则

### 5.1 适用条件

以下条件必须同时满足：

- 采购订单状态为“待采购”；
- 尚未点击“开始采购”；
- 尚未产生付款、采购入库、采购退货等下游业务数据；
- 当前用户具有采购订单编辑操作权限；
- 当前用户的数据组织权限覆盖订单的成本承担组织。

该规则同时适用于：

1. 采购申请审批通过后生成的采购订单；
2. 人工创建并保存的直接采购订单。

### 5.2 可以修改的字段

| 字段           | 是否可修改 | 约束                                                 |
| -------------- | ---------: | ---------------------------------------------------- |
| 供应商         |         是 | 必须为有效、未删除的供应商                           |
| 目标仓库       |         是 | 只能选择成本承担组织下与原商品分类仓库类型相同的仓库 |
| 接收部门       |         是 | 只能选择成本承担组织下的有效部门                     |
| 收货人         |         是 | 根据接收部门或成本承担组织筛选有效员工               |
| 到货方式       |         是 | 支持整批或分批到货；采购申请生成订单时默认整批交货   |
| 计划到货日期   |         是 | 必须为有效日期                                       |
| 运输方式       |         是 | 按现有数据字典选择                                   |
| 物流单号       |         是 | 非必填                                               |
| 结算方式       |         是 | 按现有数据字典选择                                   |
| 计划付款日期   |         是 | 非必填                                               |
| 实际采购数量   |         是 | 必须为正整数，可与申请数量不同                       |
| 明细采购总金额 |     有条件 | 具有金额编辑白名单权限时可以修改                     |
| 明细备注       |         是 | 记录本行实际采购说明                                 |
| 订单备注       |         是 | 记录整单采购执行补充信息                             |
| 附件           |         是 | 待采购期间可以补充或删除                             |

### 5.3 不能修改的字段

| 字段            | 原因                         |
| --------------- | ---------------------------- |
| 采购订单号      | 系统唯一业务编号             |
| 来源采购申请    | 保证上下游单据追溯关系       |
| 采购申请人      | 已由来源申请确定             |
| 推送 OA 组织    | 属于已经完成的 OA 审批身份   |
| 申请部门        | 属于原申请身份               |
| 成本承担组织    | 已经经过 OA 审批确认         |
| 原申请商品      | 不允许采购人员改变审批范围   |
| SKU/规格        | 不允许替换为未经审批的物品   |
| 申请数量        | 保留为原始需求数量，只读展示 |
| 来源申请明细 ID | 保证申请明细与订单明细关联   |
| OA 审批结果     | 不能由采购订单编辑改变       |

如果原申请商品、SKU、成本承担组织或审批范围本身存在错误，应删除尚未开始采购的采购订单，释放原申请明细后按业务规则重新生成；不能直接篡改已经审批的采购事实。

## 六、采购订单页面交互计划

不新增采购订单页面，不重新设计整张页面，继续复用当前采购订单查看、新增和编辑弹框及已经拆分的采购组件。

### 6.1 列表操作

- 待采购订单显示“编辑”“开始采购”“删除”；
- 采购中及以后隐藏“编辑”和“删除”；
- 查看按钮始终按照权限展示；
- 付款、生成入库等按钮只在对应业务状态出现。

### 6.2 编辑弹框

- 复用现有采购订单弹框；
- 来源申请、申请商品、SKU、申请数量以只读方式显示；
- 采购执行字段恢复编辑能力；
- 明细中同时展示“申请数量”和“实际采购数量”；
- 金额列继续叠加金额白名单；
- 点击保存后，订单仍保持“待采购”，不触发采购执行；
- 保存草稿不生成付款记录，不提前生成正式收货待办。

## 七、开始采购规则

点击“开始采购”时，后端必须重新校验：

1. 订单仍处于待采购状态；
2. 供应商有效；
3. 订单至少存在一条明细；
4. 实际采购数量合法；
5. 明细采购金额完整；
6. 目标仓库属于成本承担组织；
7. 仓库类型与商品分类一致；
8. 接收部门与收货人关系有效；
9. 来源采购申请仍然存在且已经审批通过；
10. 当前订单没有被其他操作并发修改或删除。

校验通过后：

- 订单状态由“待采购”进入“采购中”；
- 锁定订单基本信息和采购明细；
- 创建或更新收货人的采购到货待办；
- 后续通过付款、到货、入库、退货和退款流程处理。

## 八、采购订单删除与重新生成

### 8.1 允许删除的条件

- 订单状态必须为“待采购”；
- 尚未产生付款记录；
- 尚未产生采购入库记录；
- 尚未产生采购退货、退款等下游记录；
- 非生产缺料自动生成且受生产计划约束的采购订单；
- 当前用户具有删除操作权限和对应组织数据权限。

前端隐藏按钮不能代替后端校验。即使直接调用接口，后端也必须拒绝删除已经开始采购的订单。

### 8.2 删除后的处理

删除采购申请生成的待采购订单后，系统必须在同一事务内完成：

1. 软删除采购订单；
2. 关闭或删除该采购订单自身的待办；
3. 释放订单明细与来源采购申请明细的占用关系；
4. 对应采购申请明细恢复为“未生成”；
5. 采购申请重新具备整单生成或选品生成能力；
6. 如果采购申请仍有待生成明细，重新恢复采购人员的“待生成采购订单”待办；
7. 保留可审计的删除操作记录；
8. 部分生成场景只释放被删除订单占用的明细，其他有效订单不受影响。

## 九、采购付款需求

- 采购付款从采购订单操作列的“付款”入口发起；
- 新增付款时不再默认 `0.01` 元；
- 未付款订单默认当前有效应付总额；
- 已部分付款订单默认当前剩余应付金额；
- 少数分期付款场景允许用户手动调低本次付款金额；
- 本次付款金额必须大于零且不得超过剩余应付；
- 草稿采购订单保存时不允许夹带付款数据；
- 订单尚未开始采购时不显示付款入口。

## 十、采购入库、退货和退款衔接

- 开始采购后，根据订单剩余可入库数量生成采购入库单；
- 支持整批到货和分批到货；
- 待入库单可以办理入库、撤销或在满足条件时删除；
- 确认入库后才执行库存增加；
- 已入库商品退货必须生成采购退货单并按审批规则处理；
- 退货生效后按照金额关系形成采购退款任务；
- 退款任务支持登记退款和关闭；
- 临时采购入库必须保存供应商，并保证反向生成的采购申请、采购订单和入库单供应商一致；
- 收货经办人和入库单创建人优先显示员工中文姓名，不回退显示手机号作为正常业务名称。

## 十一、权限叠加规则

采购订单能否查看、编辑和操作，由以下权限共同决定：

```text
菜单访问权限
→ 具体操作权限（查看 / 新增 / 编辑 / 删除 / 开始采购等）
→ 组织数据权限
→ 金额白名单权限
```

- 角色操作权限决定是否可以进入菜单和点击对应操作；
- 组织数据权限决定能够查看和操作哪些组织的采购数据；
- 金额白名单独立决定是否可以查看或修改金额；
- 没有金额编辑权限的采购人员仍可以修改非金额采购执行字段；
- 超级管理员的角色管理能力不能绕过金额白名单，也不能改变员工从 OA 同步的组织归属。
