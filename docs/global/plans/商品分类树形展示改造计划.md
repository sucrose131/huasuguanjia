# 商品分类树形展示改造计划

> 状态：已实施并完成验证
>
> 编制日期：2026-08-05
>
> 本期范围：调整分类列表接口为不分页返回，并实现前端 Element Plus 树形展示；不修改数据库结构和分类写入接口

## 1. 改造背景

当前商品分类数据通过 `parent_goods_catg_id` 保存父子关系，后端接口也返回 `parentId`、`parentName` 和 `childCount`，数据结构具备多级分类能力。

但当前前端商品分类页面使用普通分页表格，所有分类平铺展示，只通过“上级分类”和“子分类数”两列说明层级，没有形成可以展开、收起的嵌套分类树。

本期优先处理展示问题：后端分类列表接口取消分页、一次返回完整平铺分类数据，前端使用 Element Plus 树形表格实现嵌套分类管理。后端分类完整性、递归属性继承和专用树接口等问题记录在本计划中，但暂不实施。

## 2. 改造目标

1. 商品分类列表按真实父子关系树形展示；
2. 支持任意已有分类层级的展开和收起；
3. 保留现有查询、新增、查看、编辑、启停和删除操作；
4. 分类列表接口取消分页，但继续返回平铺分类数据；
5. 不修改现有分类表结构；
6. 不改变现有分类新增、编辑和删除接口；
7. 不影响商品只能选择叶级分类的现有规则；
8. 对历史孤儿节点和循环节点进行前端防护，避免页面崩溃；
9. 将后端分类治理问题单独列入暂缓范围。

## 3. 当前实现基线

### 3.1 数据结构

分类表使用邻接表结构：

```text
goods_catg_id          当前分类ID
parent_goods_catg_id   上级分类ID，0表示顶级分类
```

### 3.2 后端接口

当前分类列表接口：

```text
GET /goods/categories
```

取消分页后仍返回平铺数据，主要包含：

- `id`；
- `name`；
- `parentId`；
- `parentName`；
- `warehouseType`；
- `propertyIds` 和 `propertyNames`；
- `goodsCount`；
- `childCount`；
- `sort`；
- `status`。

分类列表接口不再接受 `page` 和 `pageSize` 作为有效分页条件，一次返回所有符合查询条件的分类。为兼容现有调用方，响应继续使用 `{ items, total, summary }` 包装结构，但不再返回 `page` 和 `pageSize`。

### 3.3 当前前端

当前页面：

```text
apps/web/src/views/CategoriesPage.vue
```

现状：

- 使用普通 `el-table`；
- 使用服务端分页，默认每页 20 条；
- 上级分类下拉选项只来自当前页数据；
- 查询结果也是平铺数据；
- 新增、编辑后重新加载当前页。

## 4. 本期实现方案

### 4.1 后端一次返回全部分类

分类列表服务取消分页处理：

1. 不再计算 `page` 和 `pageSize`；
2. Prisma 查询移除 `skip` 和 `take`；
3. 保留现有名称、上级分类、仓库类型和状态过滤条件；
4. 保持原有 `sort ASC、id DESC` 顺序；
5. `items` 返回全部符合条件的分类；
6. `total` 返回当前查询条件下的分类数量；
7. `summary` 继续返回全部、启用和停用分类统计；
8. 不再返回 `page` 和 `pageSize`。

前端分类管理页面和商品页面都只需请求一次分类接口。分类管理页面使用未分页的完整结果构建 `allCategories` 和分类树。

本期不新增后端树接口，后端仍返回平铺集合，由前端组装 `children`。

### 4.2 构建分类树

新增纯前端树构建方法：

```ts
type CategoryTreeNode = CategoryRow & {
  children: CategoryTreeNode[];
  hierarchyWarning?: string;
};
```

构建原则：

1. 先创建 `id → node` 映射；
2. `parentId = 0` 的分类作为根节点；
3. 存在有效父节点时加入父节点的 `children`；
4. 父节点不存在时按异常根节点展示；
5. 使用访问集合检测自引用和循环引用；
6. 循环节点不继续递归，避免浏览器栈溢出；
7. 同级节点沿用现有排序结果；
8. 不修改后端真实 `parentId`，前端异常处理只用于安全展示。

### 4.3 Element Plus 树形表格

使用：

```vue
<el-table
  :data="filteredCategoryTree"
  row-key="id"
  :tree-props="{ children: 'children' }"
  default-expand-all
>
```

要求：

- 必须设置稳定且唯一的 `row-key="id"`；
- 分类名称列作为树形缩进列；
- 保留上级分类、仓库类型、关联属性、商品数、子分类数、排序、状态、操作时间和操作列；
- 首期默认全部展开；
- 用户可以按节点展开或收起；
- 后续分类规模较大时再评估默认折叠和懒加载。

### 4.4 查询和过滤

分类管理页面首次加载完整分类数据后，本期查询在前端完成，不再请求过滤后的后端结果直接构树，避免服务端过滤移除必要祖先节点。后端保留过滤能力供其他调用方使用。

#### 分类名称

名称匹配时：

- 展示匹配节点；
- 保留匹配节点的全部祖先，保证树路径完整；
- 同时保留匹配节点的后代，便于查看其分类范围。

#### 上级分类

选择上级分类时：

- 展示所选分类的直接子分类及全部后代；
- 所选分类自身可以作为树根上下文展示；
- “全部上级分类”恢复完整树。

#### 仓库类型和状态

- 按节点自身仓库类型和状态匹配；
- 保留匹配节点的祖先路径；
- 是否保留匹配节点的全部后代与名称查询保持一致。

#### 组合条件

多个条件同时存在时先判断节点是否匹配全部条件，再补齐该节点的祖先和后代，不能分别过滤后直接拼接。

### 4.5 取消前后端分页

树形结构不适合按平铺数据分页，否则父节点和子节点可能被分到不同页。

本期调整为：

- 后端分类列表查询取消 `skip`、`take`、`page` 和 `pageSize`；
- 响应保留 `items`、`total` 和 `summary`，降低调用方改造量；
- 移除分类页面底部页码切换；
- 保留“共 N 条商品分类”；
- `N` 使用完整分类数量；
- 树形过滤后可以补充显示“当前匹配 N 条”；
- 商品页面移除无效的 `pageSize: 100` 分类请求参数。

### 4.6 上级分类下拉框

新增和编辑弹窗中的上级分类选项改用完整的 `allCategories`，解决当前只显示一页分类的问题。

本期至少保持：

- 不允许选择当前分类自身；
- 顶级分类选项继续使用 `0`；
- 选项显示分类名称；
- 可以根据树深度增加前导缩进，帮助识别层级。

“禁止选择当前分类的后代”属于后端完整性问题，本期记录但暂不作为最终业务保障。前端可以隐藏明显的后代选项，但不能替代后端校验。

### 4.7 新增、编辑和状态操作后的刷新

以下操作成功后重新加载全部分类并重建树：

- 新增分类；
- 编辑分类；
- 启用分类；
- 停用分类；
- 删除分类。

刷新后：

- 保留当前查询条件；
- 尽可能恢复原展开节点；
- 找不到原节点时安全忽略；
- 不保留已删除节点状态。

## 7. 暂缓问题清单

以下问题保留在后续分类治理计划中，本期不处理：

### 7.1 分类完整性

- 后端禁止分类把自己设为上级；
- 后端禁止把分类移动到自己的后代；
- 后端检测多节点循环引用；
- 数据库是否增加自关联外键；
- 孤儿分类和循环分类历史数据修复。

### 7.2 删除规则

- 删除分类前检查有效子分类；
- 明确有停用子分类时是否允许删除父分类；
- 明确父分类删除时是否允许子分类自动提升；
- 统一前端提示和后端实际校验。

### 7.3 分类属性继承

- 属性是否沿父分类逐级继承；
- 子分类是否允许覆盖父分类属性；
- 属性冲突处理；
- 商品保存时保存继承快照还是实时读取；
- 分类迁移后历史商品属性如何处理。

### 7.4 专用树接口和性能

- 后端提供一次性树形分类接口；
- 服务端递归查询或闭包表方案；
- 大规模分类的懒加载；
- 服务端树形搜索；
- 分类缓存和缓存失效；
- 分类数量超过合理规模时的懒加载或按节点加载方案。

## 8. 异常数据前端防护

虽然本期不治理数据库异常数据，页面仍必须安全处理：

| 异常            | 前端处理                                         |
| --------------- | ------------------------------------------------ |
| 父分类不存在    | 作为根节点展示并标记“上级分类不存在”             |
| `parentId = id` | 截断循环，作为异常根节点展示                     |
| 多节点循环      | 访问集合检测后截断，相关节点作为异常节点展示     |
| 重复分类ID      | 首条或最后一条按固定规则保留，同时记录控制台错误 |
| 空分类名称      | 使用“未命名分类 #ID”兜底展示                     |

异常防护只保证页面可用，不自动修改数据库数据。
