# 销售订单操作列交互优化实施构想

## 需求与边界

- 用户：销售订单列表使用人员。
- 页面：销售订单列表的固定操作列。
- 问题：同一行最多平铺五个操作按钮，超过通用操作列的可用宽度后被裁剪。
- 本次范围：调整按钮展示层级，保证所有操作可见、可点击。
- 本次不调整：按钮显示条件、权限、确认提示、接口及业务处理逻辑。

## 界面与交互

- 固定操作列继续复用 `BusinessDocumentPage` 和 `TableRowActions`。
- 平铺保留高频操作“查看”“直接出库”。
- “缺口分析、登记收款、登记退款、发起退货、登记售后、删除”进入“更多”菜单。
- “全链路追溯”继续由通用页面追加到“更多”菜单。
- 不增加操作列宽度，不允许按钮换行，不影响其他业务页面。

## 数据及接口映射

本次仅修改前端配置项 `RowAction.primary`，不新增页面字段，不调用新接口，不写数据库，不变更数据字典、权限或事务。

## 验收标准

- 销售订单任一业务状态下，操作列最多平铺“查看”“直接出库”和“更多”。
- 原有操作仍按权限和订单状态显示。
- 所有次要操作均可从“更多”菜单触发。
- Web 类型检查和配置回归测试通过。
