# 库存预警筛选与查看交互修复实施构想

## 一、业务范围

- 使用人：有库存查询权限的库存管理人员。
- 页面入口：库存管理 → 库存预警；同类查看交互覆盖效期预警。
- 本次目标：库存状态筛选真实生效、组织树可选择、组织与仓库页签联动、查看按钮打开既有库存流水弹框。
- 不在范围：不改变安全库存计算口径，不新增库存状态，不修改库存数据和组织权限规则。

## 二、界面与交互

1. 数量预警使用现有组织树选择器，并将原通用“业务状态”明确为“库存状态”。
2. 库存状态继续使用既有 `inventory_stock_health_status` 字典，支持库存正常和库存不足。
3. 选择组织后，清空原仓库选择并仅加载该组织的仓库页签；列表、摘要和页签数量使用同一筛选结果。
4. 点击“查看”打开项目现有 `InventoryLedgerDialog`，展示商品、仓库及库存流水；不新建弹框组件。

## 三、字段与接口映射

| 页面字段 | 业务含义 | API 字段 | 数据来源 | 写入 |
| --- | --- | --- | --- | --- |
| 组织 | 库存所属组织 | `orgId` | 组织基础资料 `/base-data/organizations/options` | 不写库 |
| 库存状态 | 计算后的库存健康状态 | `status` | `inventory_stock_health_status`；`0` 正常、`1` 不足 | 不写库 |
| 仓库页签 | 库存所在仓库 | `warehouseId` | `/inventory/warehouses/tabs?orgId=...` | 不写库 |
| 查看 | 查询指定商品、SKU、仓库的流水 | 既有库存流水查询参数 | 库存流水接口 | 不写库 |

数量预警接口为 `GET /inventory/quantity-alerts`。后端先按组织、仓库和关键字读取库存，再计算 `warning = factQty < safeQty`，最后按 `status` 过滤并据此返回 `items`、`total`、`warehouseCounts` 和 `summary`。

## 四、数据库与字典

- 数据库表结构：不变。
- 数据字典：不新增、不修改，复用 `inventory_stock_health_status`。
- 数据生命周期：本次全部为只读筛选与查看，不产生业务数据写入。

## 五、验收标准

- 选择库存不足后，列表仅包含库存不足记录，摘要和仓库数量同步变化。
- 状态值 `0` 能正确筛选库存正常，不因假值判断被忽略。
- 组织下拉能显示 `parentId=0` 的根组织及其子组织。
- 选择组织后仓库页签同步收敛，不保留其他组织的已选仓库。
- 数量预警和效期预警点击查看均打开既有库存流水弹框。
