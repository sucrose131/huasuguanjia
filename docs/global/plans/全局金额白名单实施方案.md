# 全局金额白名单实施方案

> 状态：已完成
> 确认日期：2026-08-15
> 适用系统：华溯管家进销存
> 权限边界：仅进销存本地金额查看与编辑权限，不改 OA 接口、同步、审批、消息或回调

## 1. 业务规则

系统在现有菜单、角色和组织权限之外，新增一套独立的人员金额白名单。

| 白名单状态 | 查看金额 | 录入/修改金额 |
| --- | --- | --- |
| 无权限 | 否，页面显示 `****` | 否，后端拒绝写入 |
| 仅查看 | 是 | 否，后端拒绝写入 |
| 可编辑 | 是 | 是 |

固定规则：

- 未配置白名单记录即无权限，采用默认拒绝。
- 可编辑自动包含可查看。
- `admin` 和现有权限中的 `*` 不自动绕过金额白名单。
- 白名单只绑定 `hspsi_sys_user.id`，不绑定 OA 人员、岗位、组织和部门。
- 用户停用或删除后，即使存在白名单记录也不生效。
- 白名单管理与金额查看、金额编辑相互独立。

## 2. 范围

### 2.1 第一阶段：基础能力

- 新增本地用户金额白名单表。
- 新增统一金额权限服务。
- 用户管理列表显示金额权限状态。
- 用户管理提供独立的金额权限弹框。
- 记录授权、变更和取消授权操作日志。

### 2.2 第二阶段：采购订单试点

- 采购订单列表、详情金额脱敏。
- 采购订单新增、编辑和采购申请生成订单的金额写入权限校验。
- 明细总价由可编辑用户输入，单价继续由后端按 `明细总价 ÷ 数量` 反算。
- 无查看权限时，前端显示 `****`，接口不返回真实金额。
- 仅查看人员不能通过直接调用 API 修改金额。

### 2.3 第三阶段：全局接入

- 已建立显式全局金额字段注册表，覆盖采购、库存、销售、生产、领用、商品、工作台和报表接口。
- 所有已登录业务接口的响应统一在后端执行金额脱敏；无查看权限时金额字段返回 `null`。
- 人工录入金额的业务接口通过 `@RequireAmountEdit()` 明确标记，并在后端实时校验白名单。
- 仓管数量、批次、出入库等操作不因内部携带金额字段而被误拦截；相关金额由服务端订单价、主数据成本或账面成本计算。
- 前端统一读取当前用户金额权限；金额文本显示 `****`，金额输入框按权限禁用。

## 3. 数据库设计

新增表：`hspsi_sys_user_amount_access`

| 字段 | 类型 | 含义 | 约束 |
| --- | --- | --- | --- |
| `user_id` | BIGINT UNSIGNED | 本地系统用户 ID | 主键，关联 `hspsi_sys_user.id` |
| `can_view_amount` | TINYINT | 是否查看金额 | 0/1，默认 0 |
| `can_edit_amount` | TINYINT | 是否编辑金额 | 0/1，默认 0；为 1 时查看必须为 1 |
| `grant_reason` | VARCHAR(255) | 授权或变更原因 | 必填 |
| `created_by` | BIGINT | 首次授权人 | 本地系统用户 ID |
| `updated_by` | BIGINT | 最后操作人 | 本地系统用户 ID |
| `created_at` | DATETIME | 首次授权时间 | 默认当前时间 |
| `updated_at` | DATETIME | 最后操作时间 | 自动更新 |

取消全部金额权限时删除该用户的白名单记录；历史通过 `hspsi_sys_oper_log` 保存。

不修改：

- `hspsi_basic_staff`
- `hspsi_basic_staff_organizations`
- `hspsi_basic_position`
- `hspsi_basic_position_belongs`
- OA 账套、表单、回调和字段映射表

## 4. 页面设计

### 4.1 用户管理列表

在现有用户表格中增加“金额权限”列：

- 无权限：灰色标签
- 仅查看：蓝色标签
- 可编辑：绿色标签

“更多”操作中增加“金额权限”。点击后打开独立弹框，不混入角色和组织配置。

### 4.2 金额权限弹框

| 页面字段 | 交互 |
| --- | --- |
| 用户姓名、登录账号、所属公司 | 只读 |
| 金额权限 | 单选：无权限、仅查看、可编辑 |
| 授权原因 | 必填，最长 255 字 |
| 保存 | 写入白名单并记录日志 |
| 取消 | 关闭弹框，不写数据库 |

界面沿用当前 `SystemPage.vue` 的 Element Plus 弹框、表格、标签和按钮风格；金额列右对齐、金额保留两位小数。

## 5. API 契约

### 5.1 白名单管理

`PUT /system/users/:id/amount-access`

请求：

```json
{
  "level": "none | view | edit",
  "grantReason": "业务负责人确认"
}
```

返回：

```json
{
  "id": "13",
  "amountAccess": "edit",
  "message": "金额权限已保存"
}
```

错误：用户不存在、授权原因为空、权限等级非法时返回 400/404。

`GET /auth/amount-access`

返回当前登录用户实时金额权限，不依赖 JWT 中的历史快照：

```json
{
  "level": "none | view | edit",
  "canViewAmount": false,
  "canEditAmount": false
}
```

### 5.2 采购订单接口

| API | 查看校验 | 编辑校验 |
| --- | --- | --- |
| `GET /purchase/orders` | 无查看权限时掩码 | 不适用 |
| `GET /purchase/orders/:id` | 无查看权限时掩码 | 不适用 |
| `POST /purchase/orders` | 不适用 | 必须可编辑 |
| `PATCH /purchase/orders/:id` | 不适用 | 必须可编辑 |
| `POST /purchase/applications/:id/generate-order` | 不适用 | 必须可编辑 |

无查看权限时：

- 金额字段返回 `null`，不得把真实金额传输到浏览器。
- 响应增加 `amountMasked: true`。
- 前端根据标记显示 `****`。

无编辑权限时，任何金额写接口返回：

```json
{
  "code": "FORBIDDEN",
  "message": "当前账号不在金额编辑白名单中"
}
```

### 5.3 全局接入规则

- `AmountAccessInterceptor` 仅处理已通过登录校验的本地业务请求。
- 响应脱敏使用 `GLOBAL_AMOUNT_FIELDS` 显式字段集合，不匹配分页 `total`、数量、状态和字典值。
- 商品主数据无编辑权限时仍可维护非金额字段，但成本、售价由后端保留原值；新建 SKU 默认金额为 0。
- 通用入库无编辑权限时忽略客户端成本，使用商品主数据成本。
- 库存盘点、报损、报盈使用服务端账面成本计算金额，不信任客户端单价和金额。
- 销售订单、折价销售、销售收退款、采购付款退款等人工金额入口必须具备可编辑权限。

## 6. 第一批字段映射

### 6.1 白名单字段

| 页面字段 | API 字段 | 数据库表 | 数据库字段 | 写入时机 |
| --- | --- | --- | --- | --- |
| 金额权限等级 | `level` | `hspsi_sys_user_amount_access` | `can_view_amount`, `can_edit_amount` | 管理员保存白名单 |
| 授权原因 | `grantReason` | `hspsi_sys_user_amount_access` | `grant_reason` | 管理员保存白名单 |
| 授权操作人 | 当前用户 ID | `hspsi_sys_user_amount_access` | `created_by`, `updated_by` | 管理员保存白名单 |

### 6.2 采购订单金额字段

| 页面字段 | API 字段 | 数据库表 | 数据库字段/计算口径 |
| --- | --- | --- | --- |
| 明细总价 | `details[].totalAmount` | `hspsi_purchase_order_detail` | `total_amout` |
| 反算单价 | `details[].unitPrice` | `hspsi_purchase_order_detail` | `unit_price = total_amout ÷ qty`，两位小数 |
| 订单总金额 | `totalAmount` | `hspsi_purchase_order` | `pay_amout`，并以明细总价合计校验 |
| 已付金额 | `paidAmount` | `hspsi_purchase_order`/付款表 | `pay_amount_done`/付款流水合计 |
| 应付、退款、净付、剩余 | `payableAmount` 等 | 多表计算 | `purchaseMoneyPosition` 计算结果 |

## 7. 安全与风险控制

- 不使用前端权限作为最终判断，所有金额写入必须由后端重新查询白名单。
- 不使用长期缓存，权限取消后下一次敏感请求立即生效。
- 无查看权限时同时掩码原始金额和单价、合计、成本、利润等派生金额。
- 导出和打印必须与页面使用相同的金额权限。
- 白名单管理操作写入操作日志；日志不得保存用户密码或其他密钥。
- OA 集成代码不得引用金额白名单服务，OA 同步表不得保存金额权限。

## 8. 验收矩阵

| 测试账号 | 预期结果 |
| --- | --- |
| 普通用户，无白名单 | 金额显示 `****`，API 无真实金额，写入返回 403 |
| 仅查看用户 | 显示真实金额，输入禁用，写入返回 403 |

| admin，无白名单 | 与普通用户相同，不自动绕过 |

验收同时覆盖列表、详情、直接 API、刷新后的即时失效以及 OA 同步回归。

## 9. 实施结果

- 数据库 Patch：`database/migrations/20260815_user_amount_access.sql`。
- 本地数据库：已应用到 `127.0.0.1:3306/hspsi-dev`，验收结束后白名单为 0 条，保持默认拒绝。
- 单元测试：金额服务及全局拦截器 8 项通过；相关业务模块定向回归共 108 项通过。
- API 验收：无权限、仅查看、可编辑三种状态均符合预期，测试后已撤销临时授权。
- 界面验收：用户管理、采购订单、商品资料、工作台、销售订单完成浏览器检查。
- 全局扫描：31 组业务列表接口及对应可用详情接口未发现未脱敏金额字段。
- OA 隔离：未修改 `apps/api/src/integrations` 下任何 OA 同步、审批、消息或回调实现。
