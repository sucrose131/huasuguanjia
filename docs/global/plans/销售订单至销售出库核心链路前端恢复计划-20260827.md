# 销售订单至销售出库核心链路前端恢复计划

日期：2026-08-27  
实施范围：仅前端逻辑、前端组件、前端测试与实施记录  
后端原则：以当前后端实现为唯一业务依据，不修改后端代码、数据库表结构或数据字典

## 一、任务目标

恢复并验证以下核心业务链路在前端的完整可操作性：

```text
销售订单
→ 成品库存判断
→ 缺口分析
→ 生产计划
→ BOM 原料库存判断
→ 生产缺料清单
→ 自动生成采购申请
→ 采购申请审核
→ 生成采购订单
→ 采购入库
→ 生产计划重校库存
→ 生产计划审批
→ 生成 BOM 出库单
→ 执行生产领料出库
→ 生产成品入库
→ 销售出库
```

完成标准不是“页面存在”或“接口存在”，而是用户能够从销售订单开始，按照后端既定状态和操作顺序完成整条链路，并且能够在前端看见每一步的结果、状态和上下游来源。

## 二、不可改变的边界

1. 不修改当前后端接口、服务逻辑、状态流转、库存过账和单据生成规则。
2. 不修改数据库表结构，不新增字段，不修改数据字典。
3. 前端必须适配后端现有请求字段、返回字段、状态值和错误信息。
4. 不在前端重新实现库存计算、缺口计算、BOM 计算或单据状态机；前端只负责展示、触发和刷新。
5. 不把代码重新写回通用大文件；页面配置、表单、弹框、专用组件和测试继续按当前目录规范拆分。
6. 如果测试发现后端结果与产品目标冲突，只形成“后端问题清单”，立即停止该冲突点的前端扩展，不直接修改后端。

## 三、现有后端能力基线

当前代码已经确认存在以下后端能力，后续前端只调用，不改造：

| 链路环节 | 现有后端能力 | 前端应调用或展示 |
| --- | --- | --- |
| 销售订单缺口分析 | `POST /sales/orders/:id/analyze` | 仅普通且已审批销售订单可执行；按未出库、未计划数量及成品库存计算缺口 |
| 自动生成生产计划 | 缺口分析服务内部生成 | 返回生成计划数量及计划结果，不允许前端自行创建替代数据 |
| BOM 原料校验 | 生产计划生成时由后端执行 | 有料进入待审批，无料生成缺料清单 |
| 自动生成采购申请 | 生产缺料服务内部生成 | 缺料清单与采购申请建立来源关系 |
| 采购入库回写缺料 | 采购入库确认逻辑内部执行 | 入库未补齐时保持缺料，全部补齐后允许重校库存 |
| 生产计划重校库存 | `POST /production/plans/:id/recheck` | 仅未审批、未执行、缺料已补齐的计划可执行 |
| 生成 BOM 出库 | 生产计划生成出库单接口 | 仅重校并审批通过、库存满足且未出库的计划可执行 |
| 执行生产领料出库 | 生产出库专用执行接口 | 按实际批次扣减原料库存 |
| 生产成品入库 | `POST /production/inputs` | 按生产计划和成品批次增加成品库存 |
| 销售出库 | 销售出库创建、确认接口 | 继承销售订单组织和仓库，确认后扣减成品库存 |

## 四、分阶段执行计划

### 阶段 0：建立前后端映射矩阵

工作内容：

1. 对每个后端接口记录请求字段、返回字段、状态前置条件和错误提示。
2. 对每个前端页面记录按钮、弹框、字段、路由入口、接口调用和操作后刷新行为。
3. 形成“已有后端能力—当前前端实现—缺失内容—拟修改文件”矩阵。
4. 对状态字段统一建立前端语义表，不自行改变后端数值。

交付证据：

- 完整映射矩阵；
- 前端缺失清单；
- 后端代码零修改的 Git 差异证明。

### 阶段 1：恢复销售订单至生产计划入口

工作内容：

1. 校验“缺口分析”按钮只在后端允许的销售订单状态显示。
2. 点击按钮调用现有缺口分析接口，禁止前端自行计算库存缺口。
3. 根据接口返回结果展示：生成生产计划数量、是否存在原料缺料、是否生成采购申请。
4. 操作完成后刷新销售订单列表及详情。
5. 提供进入关联生产计划、单据追溯的前端入口。
6. 成品库存充足时明确提示“无需生成生产计划”，不得重复生成。

验收场景：

- 成品库存充足：不生成计划，可继续销售出库；
- 成品库存不足：生成生产计划；
- 已存在有效生产计划：再次分析不重复生成；
- 未审批或折价销售订单：前端不展示或不可执行缺口分析。

### 阶段 2：恢复生产计划、缺料清单和采购申请联动展示

工作内容：

1. 生产计划列表和查看弹框准确展示销售订单来源、BOM、成品仓、原料仓、计划数量、库存校验状态、原料状态、审批状态和出库状态。
2. 原料不足时展示缺料状态及关联缺料清单入口。
3. 缺料清单展示需求数量、当前库存、缺口数量、建议采购数量和关联采购申请。
4. 提供缺料清单 → 采购申请、生产计划 → 销售订单的追溯入口。
5. 系统自动生成的缺料采购申请保持只读边界，不增加手工编辑入口。

验收场景：

- BOM 原料充足：计划不生成缺料清单；
- BOM 原料不足：生成缺料清单和采购申请；
- 多种原料不足：全部缺料明细可见，关联关系准确；
- 缺少启用 BOM：展示后端错误，不由前端绕过。

### 阶段 3：恢复缺料采购、入库及生产计划重校库存

工作内容：

1. 在采购申请页面准确标识“生产缺料自动生成”来源。
2. 保留现有 OA 审核结果或系统既定审核状态，不在前端伪造审批通过。
3. 审核通过后沿用现有采购申请生成采购订单功能。
4. 采购订单、采购入库单展示缺料来源和生产计划追溯关系。
5. 采购入库确认后刷新采购单据及生产计划状态。
6. 只有后端返回“缺料已全部补齐”状态时，生产计划显示“重校库存”。
7. 重校库存调用现有接口，并展示“仍缺料”或“已满足、进入待审批”的真实结果。

验收场景：

- 部分入库：不得显示可执行的重校库存；
- 全部入库：显示重校库存；
- 重校后仍不足：后端重新生成缺料及采购申请，前端刷新展示；
- 重校成功：生产计划回到后端规定的待审批状态。

### 阶段 4：恢复生产领料出库和成品入库

工作内容：

1. 生产计划只有在重校成功并完成既定审批后显示“生成 BOM 出库”。
2. 生成的 BOM 出库单准确继承生产计划、组织、原料仓、BOM 原料和计划出库数量。
3. “执行出库”使用现有批次选择弹框，并只展示所选组织、仓库中的正库存批次。
4. 执行后刷新生产计划出库状态和原料库存。
5. 生产成品入库只能选择后端允许入库、尚未完成交付的生产计划。
6. 成品入库继承计划成品、SKU、组织及成品仓，展示本次入库与累计入库数量。
7. 保存后刷新生产计划交付进度及成品库存。

验收场景：

- 未审批、仍缺料或已经出库的计划不能重复生成 BOM 出库；
- 原料批次库存不足时前端展示后端错误；
- 分批成品入库累计数量正确；
- 完成计划数量后不再允许超量入库。

### 阶段 5：恢复销售出库闭环

工作内容：

1. 销售订单可从行操作进入销售出库页面。
2. 销售出库继承订单组织、订单仓库、客户及未出库商品，不允许前端更换订单仓库。
3. 批次选项只来自当前组织、当前仓库的正库存。
4. 保存后形成出库草稿；确认后调用现有后端库存过账逻辑。
5. 操作后刷新销售订单发货进度、销售出库状态和库存数量。
6. 支持后端已有的部分出库和后续继续出库，不得超过订单剩余可出数量。

验收场景：

- 原库存充足订单直接出库；
- 生产完成入库后再销售出库；
- 部分出库后继续出库；
- 超订单数量、错仓库或库存不足均被拦截；
- 已完成出库不能重复出库。

### 阶段 6：建立前端自动化回归测试

必须补充三层测试：

1. 配置测试：验证按钮存在、显示条件、权限标识、接口地址和路由参数。
2. 组件测试：验证弹框字段映射、状态展示、上下游跳转、请求成功后的刷新及错误提示。
3. 端到端测试：在本地系统中按照真实用户操作完成整条业务链路。

端到端主场景：

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| E2E-01 | 成品库存充足 | 销售订单直接生成并确认销售出库，不产生生产计划 |
| E2E-02 | 成品不足、BOM 原料充足 | 生成生产计划，审批、领料、成品入库后完成销售出库 |
| E2E-03 | 成品不足、BOM 原料不足 | 完整经过缺料、采购申请、采购订单、采购入库、重校库存、生产和销售出库 |
| E2E-04 | 采购只部分入库 | 生产计划不能重校或不能进入可执行生产状态 |
| E2E-05 | 重复点击关键操作 | 不重复生成生产计划、采购申请或出入库单据 |
| E2E-06 | 错组织、错仓库、错批次 | 前端不展示无关选项，后端错误原样反馈 |

## 五、实施顺序与验收门槛

必须按以下顺序执行，前一阶段未通过不得跳到后一阶段：

```text
映射矩阵
→ 销售订单/缺口分析
→ 生产计划/缺料清单
→ 缺料采购/采购入库
→ 重校库存
→ BOM 出库/成品入库
→ 销售出库
→ 全链路回归
```

每一阶段完成的最低证据：

- 修改文件清单；
- 前端自动化测试通过；
- 实际页面操作证据；
- 接口请求与返回字段对应证据；
- 操作前后状态变化；
- Git 差异中无后端代码、数据库和字典改动。

## 六、暂停与报告条件

正常情况下按计划连续执行，不需要每完成一个按钮都等待人工审核。出现以下任一情况必须暂停并报告：

1. 产品要求与现有后端状态机直接冲突；
2. 现有后端没有前端完成该步骤所需的接口或返回字段；
3. 同一后端状态在不同接口中的含义不一致；
4. 必须修改数据库表结构或数据字典才能继续；
5. 测试发现库存重复过账、重复生成单据或来源关系错误；
6. 当前账号、角色或测试数据导致无法获得有效的页面验收证据。
