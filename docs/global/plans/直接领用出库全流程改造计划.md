# 直接领用出库全流程改造计划

> 状态：业务规则已确认，代码实现完成（待浏览器验收）
> 日期：2026-08-28
> 关联需求：领用管理（领用出库单「直接领用出库」）
> 关联文档：`docs/daily/2026-08-28/`（跨组织改造、明细表崩溃修复、全流程改造实施记录）

## 1. 业务规则（已确认）

直接领用出库 = 紧急场景先出库 + 同一事务反向生成领用申请单。

| 规则 | 说明 |
| --- | --- |
| 领用类型 | 表单可选：直接领用(1) / 借用(2) |
| 审批分流 | 直接领用 → 反向申请单「已通过」approve_status=1，不走OA；借用 → 「待审批」approve_status=0，走 OA 审核 |
| 是否可归还 | 跟随领用类型：借用=可归还(1)、直接领用=无需归还(0) |
| 领用人签字 | **必须签字才能保存出库**；签署人默认=领用接收人(receiverId)，不单独选签署人 |
| 签名附件 | 写入申请单 attachments(category=signature) + signature_attachment 字段 |
| 数量口径 | 申请数量(draw_qty) 与 出库数量(fact_draw_qty) 均编辑；出库数量 ≤ 申请数量；剩余可出 = min(申请数量 − 历史已出, 批次库存) |
| 布局 | 直接出库单不显示「领用申请号」字段（创建/查看一致）；备注/确认人/确认时间/附件与查看一致 |
| 出库时序 | 出库单保存即确认扣库存（先出库），即使 OA 后续驳回也通过「待确认退回单」追物资 |
| 跨组织 | 仓库下拉跨授权组织，选仓库反推组织、筛部门/人员（上轮已实现） |

## 2. 界面设计（直接领用出库创建弹框）

顶部字段（两列网格）：

1. 领用类型（下拉，必填，直接领用/借用）
2. 仓库（跨授权组织，必填）
3. 出库日期（必填）
4. 领用部门（选仓库后可用/自动带出）
5. 领用接收人（选仓库后按部门筛，手动选）
6. 领用人签字（SignaturePad，必签，签字人=接收人）
7. 备注

明细表列（与查看一致）：商品、商品编码、SKU/规格、单位、是否可归还、申请数量、历史已出、剩余可出、库存批次、出库数量、备注、删除。

- 申请数量：可编辑（直接出库专属 `drawQty`）。
- 历史已出：只读，直接出库恒 0。
- 剩余可出：只读联动显示 = min(申请数量, 所选批次库存)。
- 出库数量：可编辑，上限=剩余可出；未选批次时禁用。
- 是否可归还：只读标签，跟随领用类型。

## 4. API 与事务方案

### 4.1 `POST /requisitions/outputs`（`directOutput: true`）

```text
事务前：signatureContent 上传 OSS（同 saveApplication 的 uploadSignatureDataUrlForIntegration）
事务内：
  1. 幂等：按 generation_key 查已存在单据 → 命中直接返回
  2. 组织授权校验 assertAuthorizedOrganization
  3. 校验 drawType ∈ {1,2}；签字必填
  4. validateApplicationReferences（org/仓库/部门/接收人/领用类型归属）
  5. masterData.assertGoodsLines（商品与仓库兼容）
  6. 逐行校验：quantity ≤ drawQty；returnable 与 drawType 一致
  7. 生成申请单（draw_type、approve_status、签字四要素、draw_qty/fact_draw_qty 合计）
  8. 生成申请明细、出库单、出库明细（draw_qty / fact_draw_qty / is_returnable 分列）
  9. 库存过账扣减 + 出库单确认（comfirm_status=1）
 10. documentTrace.link（reverse_generated）
事务后：
 11. drawType=2（借用）→ oaApproval.submit(drawId, userId) 走 OA
```

### 4.2 问题 A：OA 通过不重复出库

`ensureAutomaticOutput` 增加：若该申请已存在 `generation_key` 以 `direct-requisition-output:` 开头的出库单，直接返回该单，不新建。

### 4.3 问题 B：OA 驳回自动生成待确认退回单

`handleOaCallback` 驳回分支增加：检测该申请存在直接出库单时，调用 `ensureRejectedDirectOutputReturn` 生成「待确认退回单」（幂等：已存在则复用）。

## 5. 验收标准

1. 直接领用(1)：保存后反向申请单「已通过」、不走 OA；明细无需归还；签字必填。
2. 借用(2)：保存后反向申请单「待审批」、提交 OA；明细可归还；签字必填。
3. 借用 OA 通过：不重复生成出库单；借用 OA 驳回：自动生成待确认退回单。
4. 申请数量/出库数量独立编辑；出库数量 ≤ 申请数量；剩余可出 = min(申请数量, 批次库存) 联动。
5. 直接出库单查看/编辑不显示「领用申请号」；备注/确认人/确认时间/附件与查看一致。
6. 越权组织保存被后端拒绝；签字缺失被拦截。

## 6. 风险与遗留

- 借用「先出库后审批」的固有风险：OA 审批期间库存已减，驳回依赖待确认退回单追回（业务已确认接受）。
- 签字上传 OSS 失败需回滚（事务外上传，失败不进入事务，同 saveApplication）。
