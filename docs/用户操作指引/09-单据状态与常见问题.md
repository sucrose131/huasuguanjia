# 单据状态与常见问题

不同业务单据的状态名称可能略有差异，但整体处理思路一致：先保存业务内容，再按单据类型完成提交、审批、确认或过账。

## 一、常见单据状态

| 状态           | 含义                                 | 常见可执行操作                 |
| -------------- | ------------------------------------ | ------------------------------ |
| 草稿           | 单据尚未正式进入后续流程             | 修改、删除、提交               |
| 待审批         | 单据已提交，等待有权限的人员处理     | 查看、审批、驳回               |
| 已通过         | 审批通过，但可能仍需收货、出库或确认 | 按业务继续办理                 |
| 已驳回         | 审批未通过                           | 查看原因、修改后重新提交       |
| 待确认         | 实际业务已录入，等待最终确认         | 核对并确认                     |
| 已确认／已过账 | 单据已产生正式业务或库存结果         | 查看，必要时走退货或冲销类流程 |
| 已完成         | 单据约定的全部步骤已结束             | 查看、报表查询                 |
| 已关闭／已终止 | 单据不再继续执行                     | 查看                           |

页面实际显示的状态和可用按钮，以当前单据类型、当前状态及账号权限为准。

## 二、保存、审批、确认和过账的区别

- 保存：记录当前填写内容。保存草稿通常不会改变库存。
- 提交：将草稿送入当前系统内的审批流程。
- 审批：有审批权限的人员决定通过或驳回。当前仍使用系统现有审批方式，暂未接入 OA 审批回调。
- 确认：确认实际收货、出库、领用、退货或生产结果。部分单据在确认时改变库存。
- 过账：将通用出入库等业务直接记入库存。通用出入库按当前约定不经过审批，操作前必须核对仓库、SKU、批次和数量。

不要把“已保存”理解为“已完成”。办理人应继续查看单据状态和待办信息，直到业务真正结束。

## 三、为什么看不到菜单或按钮？

常见原因如下：

1. 当前账号没有对应菜单权限。
2. 有页面权限，但没有新增、审批、确认或删除等操作权限。
3. 当前单据状态不允许执行该操作，例如已完成单据不能再次提交。
4. 当前用户不是该环节的经办人、接收人或审批人。
5. 功能开关已关闭，例如初期入库入口可能被管理员停用。
6. 相关功能尚未启用。当前“业务链路”按钮已隐藏。

先刷新页面确认状态；仍无法处理时，将账号、单据编号、页面名称和问题截图提供给系统管理员。

## 四、为什么选不到组织、仓库、商品或 SKU？

- 检查所属组织或业务类型是否已选择。
- 检查基础资料是否处于启用状态。
- 检查仓库、商品和 SKU 是否属于当前组织及当前业务范围。
- 检查商品是否已维护可用 SKU、基础单位和换算系数。
- 检查当前用户的数据范围是否覆盖该组织或仓库。

物资由操作者按实际情况选择商品或物品归类；固定资产目前只作为一种特殊库存物资管理，不包含完整固定资产管理流程。

## 五、数量为什么无法保存？

- 件数必须是大于 0 的整数，不支持小数件数。
- 所有 SKU 都应维护到基础单位的直接换算系数。
- 出库结果不得小于一个基础单位，也不能超过当前可用库存。
- `pieces` 表示基础单位数量，系统库存和成本按基础单位核算。
- 已发生业务的单位或换算关系不应随意修改，否则历史数据和当前库存可能失去一致性。

## 六、为什么提示库存不足？

库存校验通常不仅看商品总量，还会校验具体仓库、SKU、批次和可用数量。请检查：

1. 是否选择了正确的出库仓库。
2. 是否选择了正确的 SKU 和批次。
3. 其他待处理单据是否已占用或消耗库存。
4. 件数换算后的基础单位数量是否超过可用量。

不要通过修改基础资料换算系数来绕过库存不足，应先核对实物和库存流水，必要时按盘点或库存调整流程处理。

## 七、采购收货和退货常见问题

- 收货前确认采购单已进入允许收货的状态。
- 收货数量不能超过订单剩余未收数量。
- 按页面要求填写批次、仓库和实际到货数量。
- 实物采购退货会影响库存，退货前应确认退货数量仍在可退范围内。
- 付款、退货和退款属于不同业务动作，应分别办理并关注各自状态。

## 八、销售、领用和生产常见问题

- 销售出库前确认销售单已审批通过，且本次出库不超过剩余可出数量。订单类型为「无需出库」的不做出库。
- 销售退货应关联原销售业务，确认后再核对库存变化。
- 领用单按现有流程完成签字和审批，再由仓库办理出库；归还应关联原领用业务。
- 生产投入和产出应使用正确的计划、仓库、SKU 和数量，确认前先核对原料消耗与成品产出。

## 九、重复点击后如何处理？

提交、审批、确认、付款或过账时，如页面响应较慢，不要连续重复点击。先等待结果并刷新列表，按单据编号确认是否已成功。若出现两条相似记录，不要自行再次操作，及时联系管理员核对。

## 十、当前暂不包含的功能

以下内容已从当前改造范围中拆分，后续单独实施：

- 借用调拨及预计归还日期、原路归还限制。
- OA 审批消息推送和审批结果回调；目前继续使用系统现有审批。
- 单据附件上传与管理。
- 完整固定资产全生命周期管理。

普通调拨继续沿用现有规则：物资调入目标仓库后，由目标仓库按现有权限进行领用、销售、报损或再次调拨等处置。

## 十一、反馈问题时应提供什么？

为了便于快速定位，请尽量一次提供：

- 登录账号和所属组织。
- 页面名称及操作时间。
- 单据编号、商品、SKU、仓库和批次。
- 当前状态、期望结果和实际提示。
- 可复现的操作步骤及完整页面截图。

涉及库存或金额时，不要只提供截图中的合计数，还应提供相关单据编号，便于通过业务明细和流水核对。
