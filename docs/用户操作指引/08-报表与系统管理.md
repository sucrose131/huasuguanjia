# 报表与系统管理

本章面向需要查询经营数据、维护账号权限或调整系统参数的用户。若看不到某个菜单或按钮，通常表示当前账号没有对应权限，请联系系统管理员处理。

## 一、报表中心

### 1. 通用查询方法

1. 从左侧菜单进入「报表中心」，选择所需报表。
2. 选择统计开始日期和结束日期。
3. 根据页面提供的条件继续筛选组织、仓库、商品、供应商、客户或单据状态。
4. 查看汇总指标、趋势或明细记录。
5. 需要留档时点击「导出」。没有查询结果时，导出按钮可能不可用。

报表只展示系统接口返回的真实业务数据。若刚完成业务操作但报表尚未变化，可先点击页面右上角的「刷新数据」，然后重新查询。

### 2. 资料类报表

- 商品资料查询表：查看商品、SKU、规格、单位等资料。
- 供应商资料查询表：查看供应商基础资料。
- 客户资料查询表：查看客户基础资料。

### 3. 采购与应付报表

- 采购明细查询表：按采购单据查看商品、数量、金额和状态。
- 采购统计分析表：查看采购业务的汇总和趋势。
- 采购付款查询表：查询采购付款记录。
- 应付账款统计表：查看供应商应付账款汇总。

### 4. 库存报表

- 入库明细查询表、出库明细查询表：查询库存增减明细。
- 报损明细查询表、报溢明细查询表：查看报损、报溢记录。
- 库存汇总统计分析表：按商品、SKU、仓库等维度查看库存汇总。
- 盘点汇总统计分析表：查看盘点结果和差异。
- 分批入库查询表：按批次查看入库情况。

查看库存时应同时关注仓库、SKU、批次和基础单位数量；只比较商品名称可能会造成误判。

### 5. 生产、销售和领用报表

- 生产明细查询表、生产统计分析表：查看生产投入、产出及汇总数据。
- 销售明细查询表、销售统计分析表：查看销售单据明细和汇总。
- 折价处理明细表：查看折价销售处理记录。
- 领用明细查询表、领用统计分析表：查看物品领用及归还情况。

## 二、角色管理

角色用于一次性定义一组用户可以看到的数据、菜单和操作按钮。

### 新增角色

1. 进入「系统管理 > 角色管理」，点击「新增角色」。
2. 填写角色名称并选择启用状态。
3. 选择默认数据范围。
4. 勾选该角色可以进入的菜单。
5. 勾选新增、修改、删除、审批、确认等操作权限。
6. 保存角色。

至少应为角色分配一个菜单。菜单权限决定用户能进入哪些页面，操作权限决定用户进入页面后能执行哪些动作，两者需要配合配置。

修改角色会影响所有绑定该角色的用户。调整前应确认不会中断其他人员正在办理的业务。

## 三、用户管理

### 新增用户

1. 进入「系统管理 > 用户管理」，点击「新增用户」。
2. 填写登录账号、初始密码、姓名和联系电话。
3. 选择所属公司；根据实际情况选择部门。
4. 至少分配一个角色。
5. 设置账号状态并保存。

登录账号至少 3 个字符，初始密码至少 6 个字符。用户创建后登录账号不可直接修改，如账号录入错误，建议停用原账号并按管理制度创建新账号。

### 修改用户

- 修改姓名、联系方式、组织、部门、角色或状态后保存。
- 编辑用户时密码留空表示不修改密码。
- 停用账号后，该用户将不能继续正常使用系统；停用前应确认其待办单据已交接。

## 四、系统配置与菜单

当前「系统配置」页面主要用于维护系统菜单和权限项。可以查看或维护：

- 上级菜单和菜单名称；
- 菜单类型；
- 访问路径；
- 权限编码；
- 显示顺序和显示状态；
- 菜单图标。

新增菜单时选择正确的上级菜单和菜单类型，并按开发约定填写访问路径及权限编码。操作类型的权限项用于控制按钮权限，页面类型的菜单用于控制页面入口。

菜单和权限编码直接影响角色授权。修改、停用或删除前，应先检查现有角色是否正在使用该项；普通业务人员不应操作此页面。

初期入库属于可通过功能开关控制的业务能力。该开关关闭后，普通业务用户不应再通过初期入库入口录入期初库存；具体开关由系统维护人员按部署配置管理。

## 五、任务管理

「任务管理」用于控制华溯之家用户/商品/订单同步、十方清源用户/商品/订单同步和薪福通 OA 组织同步是否自动执行，以及何时执行。

1. 进入「系统管理 > 任务管理」。
2. 新增任务时从已实现的任务类型中选择，填写名称和 Linux Cron 执行时间（例如 `0 1 * * *` 表示每天 01:00）。同一类型未删除前只能有一条。
3. 使用行内开关启用或停用。停用后即使到点也不会自动执行。
4. 修改 Cron 后保存即可，不必重启系统；列表「下次执行」按北京时间显示（例如 `0 1 * * *` 为每天 01:00）。
5. 「立即执行」只跑一轮，不改变已保存的执行时间。若已有其他同步任务在跑，会排队等到当前任务结束后再执行，避免把网站拖慢。成功后会给出执行记录编号，可在「执行记录」中核对。
6. 「执行记录」查看最近 50 次结果（定时或手动、开始/结束时间、耗时）。失败原因写在执行记录中，便于排查；任务列表上的最近结果仍为脱敏摘要。
7. 失败后系统会自动再试 3 次（间隔约 1 分钟、5 分钟、15 分钟）。超过 30 分钟仍未结束会记为超时，并让出队列给其他任务。
8. 删除后不再自动调度，之后仍可按同一类型再新增。

同一时刻到点的多类同步会按队列逐个执行，不会并行抢数据库连接。

普通业务人员不应操作此页面。非法 Cron 不会被保存。

## 六、权限配置建议

- 业务经办人：只授予本人岗位需要的查询、新增和修改权限。
- 审批人员：额外授予对应业务的审批权限。
- 仓库人员：授予收货、入库、出库、盘点、调拨等实际库存操作权限。
- 财务人员：授予付款、退款、应付和相关报表权限。
- 系统管理员：负责角色、用户、配置和定时任务维护，不应代替业务人员办理日常单据。

涉及审批、库存过账、付款和退款的权限应谨慎分配，避免同一人员在没有业务需要时同时拥有申请、审批和最终确认权限。
